# Детали цели — переработка одного экрана

## Границы и источник

Экран: Управление → Альбом целей → детали цели (`#/goals/:id`).
Только `GoalDetailPage`, `GoalManagementPanel`, отдельные scoped styles и связанные проверки.
Оболочка получает scoped оформление только при открытых деталях цели. Другие страницы,
предметная модель и persistence не меняются.

Актуальный источник от 2026-09-09:
[выбранный графитовый вариант](../references/2026-09-08-goal-detail/selected-graphite-peach.png).
Пользователь вернулся к дымчатому стеклу, закатному фону и светящемуся персиковому CTA.
Этот выбор заменяет прежнее древесное направление и ограничение на декоративный фон.
Снимок «Сегодня» задаёт материал и атмосферу для текущих деталей цели, а не смену экрана.
Существующая фотография `public/planning-tomorrow-atmosphere.png` используется как фон;
это другой пейзаж, точное совпадение фотографии не заявляется. Реализация ещё не утверждена.

## Аудит до изменения

Назначение: понять смысл, состояние и продвижение цели, создать связанное решение.
Основной сценарий: открыть цель → создать решение → увидеть связь → продолжить работу.
Главное: название, прогресс, ближайшее продвижение, создание решения.
Поддерживающее: критерий достижения, мотивация, существующие связи.
Дополнительное: технические даты, все параметры, история, архивация и удаление.

Сильные стороны: реальные application-команды, возврат в альбом, подтверждение удаления,
отдельные loading/error/not-found, нативный progress, перенос длинных строк.

Проблемы: CTA ниже длинного описания и метаданных; опасные действия конкурируют с ним;
повторение параметров; отдельная рамка вокруг каждого абзаца; подписи 10–12px;
зелёный обозначает даже будущую цель; длинная мобильная страница с CTA далеко внизу.
Состояния: повторное открытие формы сохраняет уже отправленные поля; модальность без
управления фокусом. Ошибки должны оставаться вне закрытых раскрывающихся блоков.

Доказательства: [desktop до](../references/2026-09-08-goal-detail/before-desktop.png),
[mobile до](../references/2026-09-08-goal-detail/before-mobile.png).
Базовый `goals.unification.spec.ts`: 2/2 passed, isolated Playwright contexts.

## Контракт и внутренний план

Архетип: detail, смысловая колонка и колонка продвижения (примерно 3:2), max-width 72rem.
Визуальный центр: название цели, затем прогресс и ближайшее продвижение.
CTA: один «Создать решение», персиковая подсвеченная поверхность, тёмная контрастная надпись
как у выбранной светлой кнопки. Section accent: персиковый, зелёный только success,
красный для ошибок. Мотив: графит, дымчатое стекло и закатный пейзаж.
Локальные CSS tokens и `:has(.goal-detail-page)` ограничивают атмосферу текущим маршрутом.
Blur находится на декоративном псевдоэлементе: fixed-диалог сохраняет viewport-позиционирование.
При reduced-transparency стеклянная оболочка становится непрозрачной.

Порядок: возврат/редактирование/дополнительные действия → название → обложка (если есть)
и прогресс → блок продвижения и пояснения → раскрываемые сведения.
Уровень 1: цель, ближайший шаг, CTA. Уровень 2: критерии и связанные решения.
Уровень 3: метаданные и история. Пояснения объединяются общей поверхностью и разделителями;
повторная информация убирается из первого экрана. Опасные действия — раскрытие «Ещё».

Reuse: AppIcon, GoalProgress, GoalRouteAnchor, ProjectActivity, DecisionCreationDialog,
существующие controllers и application commands. Общие компоненты не редактируются.

Mobile: одна колонка, продвижение перед пояснениями, один экземпляр CTA в DOM,
контролы ≥44px, безопасный нижний отступ, без fixed CTA поверх навигации.
Диалог: начальный фокус, Tab trap, Escape до отправки, возврат фокуса; собственная прокрутка.

Состояния: loading/error/retry/not-found, no cover, missing optional values, empty relations,
long/many data, archived/achieved/paused, disabled/pending, mutation success/error.
Форма: focus/filled/validation/submitting/success/command failure.

План: структура → изолированные стили → исправления формы в GoalManagementPanel → targeted
тесты → фактические снимки 1600/1280/390/360 → полировка → verify и затронутый E2E.
Последнее пользовательское задание ограничивает E2E затронутыми сценариями.

## Результат

Структура реализована. Сохранены application-команды и правила доступности действий.
История и метаданные раскрываются по запросу; связанные решения остаются видимыми.
У формы исправлены повторное открытие с уже отправленными данными и управление фокусом.
Обработчик загрузки связей переводит исключения адаптера в асинхронный результат.

Проверки: 14/14 targeted unit; 6/6 новых E2E (desktop/mobile); после последней mobile CSS
правки повторно 2/2 reflow/lifecycle E2E. На 360×800 и 390×844 кнопка целиком выше нижней
навигации для проверенного обычного состояния без обложки. Очень длинный заголовок и
обложка требуют прокрутки; горизонтального overflow нет. Контролы ≥44px.
Сохранение/перезагрузка, пустые связи, validation error, focus/Tab/Escape, повторная форма,
редактирование, отмена архивации, pause/resume/complete, long text, cover и not-found проверены
в браузере. Технические loading/error/pending/delete покрыты существующими unit tests;
сбой реального хранилища и submitting при медленном диске в браузере не эмулировались.

Данные — изолированные фикстуры, созданные через реальные формы и application-команды.
Существующие пользовательские данные не изменялись. Общий `verify`: typecheck и lint PASS
(14 предупреждений вне этой правки), затем 8 failures в 7 файлах общего unit suite,
3276 tests passed. В том числе failure mapper прогулок и persistence; эти файлы не менялись
в рамках редизайна. Это ограничение общего gate, а не свидетельство готовности релиза.

Отдельная production build прошла (typecheck + Vite); предупреждение о крупных chunks сохранено.

Изменённые исходники: `src/presentation/goals/GoalDetailPage.tsx`,
`src/presentation/goals/GoalManagementPanel.tsx`, `src/presentation/styles/goal-detail.css`,
`src/presentation/goals/GoalDetailPage.test.ts`, `tests/e2e/goal-detail.redesign.spec.ts`.
Добавлены эта спецификация, `design-qa.md` и PNG-доказательства. Общие компоненты и токены не изменены.

Осталось пользовательское визуальное принятие. Другие экраны и переключатель тем не входят
в этот патч. Новая реализация не помечена APPROVED или LOCKED.
