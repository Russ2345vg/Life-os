# Исходный интерфейс выбора шага к цели

Дата: 01.10.2026. Активный worktree: `D:/LifeOS-App`.
Это baseline для [проекта обновления](../../features/2026-10-01-goal-guidance.md), а не утверждение нового макета.

## Как получены снимки

Локальный Vite на `http://127.0.0.1:4174/`, Chrome через Playwright, отдельный временный browser context.
Данные синтетические: одна главная цель текущей недели «Подготовить портфолио», явно выбранный
следующий шаг «Описать первый проект» без даты и отдельное главное действие на сегодня.
Личное хранилище пользователя не использовалось. Часовой пояс `Asia/Chita`, дата приложения 01.10.2026.

Все шесть сохранённых снимков просмотрены. На этих состояниях нет horizontal overflow,
console errors или page errors. Проверены видимые состояния, а не полный пользовательский сценарий.

| Шаг                                       | Маршрут                                  | Desktop                             | Mobile                            | Наблюдение                                                                                                                           |
| ----------------------------------------- | ---------------------------------------- | ----------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1. Открыть план дня                       | `#/v2/today`                             | [1440×900](baseline-today-1440.png) | [390×844](baseline-today-390.png) | Главное действие видно; выбранный шаг недельной цели не объяснён рядом с планом.                                                     |
| 2. Открыть фокус целей                    | `#/v2/goals/focus`                       | [1440×900](baseline-focus-1440.png) | [390×844](baseline-focus-390.png) | Главная цель и следующий шаг уже есть. В этом блоке доступны открытие и выполнение; назначения даты нет.                             |
| 3. Открыть обзор и раскрыть следующий шаг | `#/v2/goals?view=review&week=2026-09-28` | [1440 px](baseline-review-1440.png) | [390 px](baseline-review-390.png) | Уже доступны выбор действия, создание связанного и назначение даты. На mobile это расположено ниже итогов недели и результатов цели. |

На третьем шаге снята полная страница, поэтому закреплённая mobile-навигация видна на высоте
первого viewport внутри длинного изображения. Это не макет положения навигации при прокрутке.

Вывод из наблюдений: полезное обновление может сократить путь от «Сегодня» к существующему
шагу цели. Оно не должно повторять недельный обзор или объявлять его новой функцией.
Число действий и время обнаружения до изменения в этом проходе не измерялись.

## Компоненты и каскад

Изучены `PlannerToday`, `PlannerFocus`, `PlannerWeeklyReview`, `WeeklyGoalNextStep`,
`PlannerViewSwitcher`, `MonthlyDirectionFocusCard`, `PlannerSheet` и существующая форма действия.
Фактический порядок подключённых стилей сохранён в [baseline-metrics.json](baseline-metrics.json).
Релевантный порядок: global/tokens → planner-v2 → weekly-review → planner-library →
planner-views → planner-master → planner-premium; после premium подключаются отдельные стили
дневника, отмены даты и памяти.

Перед проектированием прочитаны все `LifeOS_DESIGN_RULES_v1.md` с поправкой на действующий
graphite/jade и приоритет текущего интерфейса из AGENTS.md. Историческое стеклянное направление
не использовалось как baseline.

## Границы проверки

Это экспертное исследование существующего интерфейса. Новый помощник ещё не реализован;
его keyboard/focus, ошибки, нагрузка, сохранение, 320 px и реальные пользовательские задания
проверяются на этапе реализации. Снимки не подтверждают полное соответствие WCAG.
