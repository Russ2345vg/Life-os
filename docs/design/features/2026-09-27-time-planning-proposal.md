# Планирование времени — предложение большого обновления

Статус: направление и макет календаря утверждены пользователем 28.09.2026 ответом «давай».
Календарь, оценки и доступное время реализованы. Отдельный макет таймера и отчёта
находится на визуальном согласовании; эти экраны ещё не внедрены.
Запрос: крупное обновление LifeOS с большим объёмом реализации. Предложенная
пользовательская цель — собирать выполнимый план дня и недели и сопоставлять его
с фактической работой. Контракт зафиксирован в
[спецификации](../../superpowers/specs/2026-09-28-time-planning-design.md).
Сохраняется требование пользователя не перегружать ежедневный интерфейс режимами.

## Выбор направления

1. **Планирование времени — рекомендуемый вариант.** Заполняет существующий пробел:
   текущий PlannerCalendar показывает даты, но у LifeAction нет текущего контракта
   начала и длительности планового блока. Даёт новый повседневный сценарий.
2. **Общий обзор жизни.** Объединяет существующие результаты целей, баланс и сон за
   длительные периоды. Меньше новых способов действий, больше работы с аналитикой.
3. **Дневник и знания.** Новая область с редактором и поиском. Потребует уточнить,
   какие записи пользователь хочет хранить и как связывать их с целями.

## Дизайн-контракт

FEATURE → новая функция календаря действий и новый сценарий исполнения
→ USER GOAL: понять, помещается ли план в день, затем выполнить его
→ EXISTING LOGIC: LifeAction, SetLifeActionPlan, PlannerCalendar, PlanningContext
→ PAGE/COMPONENT ARCHETYPE: рабочий календарь и контекстная колонка
→ SECTION COLOR: текущий jade, графит; золото только для приоритета
→ MAIN VISUAL CENTER: расписание выбранного дня / недели
→ COMPONENTS TO REUSE: оболочка PlannerWorkspace, переключатели, PlannerSheet,
кнопки, меню действия, поля дат/времени, общий поиск и voice input свободного текста
→ MOBILE BEHAVIOR: выбранный день, переключатель дат, список без времени ниже
→ APPROVED REFERENCE: YES для календаря; [макет](../references/2026-09-27-time-planning/preview.html)
→ TEST SCOPE: domain/application, IndexedDB, совместимость sync, scoped browser;
перед финальной поставкой полный E2E из-за общего persistence-контракта.

Атмосфера — действующая спокойная рабочая поверхность, без новой палитры или фона.
Состояния реализации: skeleton календаря; пустой день с одним действием; явная
ошибка загрузки и повтор; конфликт времени рядом с полями; подтверждение и отмена
после переноса; недоступное действие не допускает повторного сохранения.

## Предлагаемый объём одного обновления

1. **Модель времени.** Необязательная оценка длительности и временной блок у действия,
   существующая plannedDate остаётся единственным источником даты. Старые действия
   работают без заполнения новых полей. Пересечения проверяются атомарно.
2. **Календарь дня и недели.** Часовая сетка, создание блока из существующего действия,
   изменение начала/длительности, перенос между днями, отмена, управление без drag.
3. **Выполнимость плана.** Заданные пользователем доступные часы, свободные интервалы,
   длительность дел без фиксированного времени, явное обозначение неизвестных оценок.
   Предупреждение не переносит действия самостоятельно.
4. **Исполнение.** Начало, пауза, продолжение и окончание работы; восстановление после
   перезагрузки. Остановка времени не означает автоматическое завершение действия.
   Новая рабочая сессия не подключает прежний отключённый runtime сценариев.
5. **План и факт.** Затраты времени по действиям и целям, итог дня, обзор недели.
   Плановая оценка, фактическое время и завершение остаются различимыми фактами.
6. **Надёжность.** Версии, несколько вкладок, старые записи, повторяющиеся действия,
   архив/корзина, резервная копия и зашифрованная синхронизация новых полей; полный gate.

## Границы и источники

Domain владеет правилами блоков и сессий; Application командами и запросами;
Infrastructure реализует порты и атомарное хранение; App связывает сервисы;
Presentation рисует производные состояния. Новый календарь не ведёт отдельный
список копий действий. Точный контракт сессий и изменений схемы определяется
в письменной спецификации после выбора направления, до реализации.

Затрагиваются LifeAction, его record mapper, application-команды планирования,
PlannerCalendar/Today, composition, IndexedDB UoW и sync/snapshot-контракты.
Существующие таймеры прежних сценариев не являются готовой реализацией нового flow.

Первый макет показывает расписание и выбор времени на демонстрационных данных.
В нём нет рабочей синхронизации, drag, таймера и миграции. Он не обращается к
IndexedDB/localStorage и не изменяет реальные данные. Изменения живут только
в памяти страницы и исчезают после её перезагрузки.

Прямых внешних интеграций и AI-сервиса в базовом объёме нет. Работа локальная;
предыдущие изменения сохраняются, GitHub пользователь фиксирует отдельно.

## Критерии результата

- Можно выбрать день и назначить существующему действию время и длительность.
- Действие остаётся тем же объектом в календаре, Today, карточке цели и списке.
- Перенос не заменяет чужое главное дело и доступен для безопасной отмены.
- Два одновременных запроса не создают незаметного пересечения блоков.
- Пересечения из синхронизации или автоматического возвращения повторения сохраняются
  и явно показаны в календаре; они не перекрывают загрузку и не стирают прежнее окно.
- Дела без времени продолжают работать; неизвестная длительность не считается нулём.
- Сессия переживает перезагрузку, паузы не входят в фактическое время.
- Общие отчёты не смешивают оценку, фактическое время и факт завершения.
- Desktop/mobile доступны с клавиатуры; drag всегда имеет альтернативу.
- Старые записи и повторения сохраняются; новые поля проходят backup/restore/sync.
