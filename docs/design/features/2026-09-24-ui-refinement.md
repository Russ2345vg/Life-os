# Удобство и единообразие существующего интерфейса

Дата: 2026-09-24. Основание: аудит интерфейса и пользовательское «делай».

## Дизайн-контракт

- FEATURE: доработка существующих страниц и общих контролов; новые разделы не создаются.
- USER GOAL: видеть рабочие действия раньше настроек, читать мобильный экран без увеличения,
  предсказуемо перемещаться и закрывать формы.
- EXISTING LOGIC: существующие application-команды и запросы; локальное состояние формы и маршрута
  остаётся в Presentation. Хранение и правила планирования не меняются.
- PAGE/COMPONENT ARCHETYPE: «Сегодня» — центр управления, списки — рабочий экран,
  вечерняя подготовка — глубокий фокус; существующие PlannerSheet и формы.
- SECTION COLOR: общий тёплый акцент; зелёный — завершение; красный — ошибка/просрочка.
- ATMOSPHERE: текущая графитовая основа; декоративная смена фона не входит в этот этап.
- MAIN VISUAL CENTER: действия дня / список подготовки / содержимое каталога.
- COMPONENTS TO REUSE: PlannerScenariosPanel, PlannerOverdueActions, PlannerSheet, VoiceTextInput,
  стандартные select/button/details и общие tokens.
- MOBILE BEHAVIOR: постоянные пять пунктов навигации, подписи 12 px, контролы от 44 px,
  выбор даты в сетке 2×2, история сна после действий, фильтры без скрытых горизонтальным скроллом кнопок.
- APPROVED REFERENCE: существующий визуальный язык и согласованная в аудите доработка текущего
  дизайна; отдельный новый макет для стандартных компонентов не требуется. Pixel-perfect не заявляется.
- STATES: существующие loading/error/retry/disabled/success сохраняются; вместо пустого прогресса
  «0 из 0» показывается подсказка. Пустое колесо становится компактнее.
- TEST SCOPE: адресные render/navigation/date tests; scoped E2E общих форм, каталога,
  сценариев, оставшихся действий и мобильной навигации; verify и desktop/mobile browser QA.

## Принятые решения

1. Рабочий список дня расположен выше направления и быстрого создания. Создание доступно также
   в шапке. Сценарий остаётся перед списком как управляющий его содержимым выбор, но компактнее.
2. История и расширенный статус будильника на mobile идут после списка подготовки и завершения.
3. «Ещё» обозначает вложенный раздел; сон больше не заменяет цель в нижней навигации.
4. Форма следующего действия различает запуск из списка целей и из карточки; сохраняется совместимость
   старых ссылок. При отмене фокус возвращается в основную область. Локальные панели восстанавливают
   живой инициатор, начальный фокус получает доступное поле вместо разделителя ширины.
5. Основные цвета, кнопки создания, даты, заголовки форм и карточки унифицированы.
6. Добавлены отсутствовавшие в общей теме control-sm/md/lg, предусмотренные Design Rules.

## Критерии приёмки

- На mobile виден список подготовки до истории; основной текст читается в обычном масштабе.
- Список дня расположен выше вспомогательных настроек, быстрое создание остаётся доступным.
- Во вложенных разделах выделено «Ещё», состав основной навигации постоянен.
- Все четыре варианта даты помещаются по ширине панели.
- Отмена из списка целей возвращает в список; отмена из карточки — в карточку.
- Изменения проверены на наполненных и пустых состояниях без изменения пользовательских данных QA.

## Ограничения

Нативный Android, экранная клавиатура и аппаратный будильник требуют проверки на устройстве.
Этот этап не является релизом и не включает публикацию. Декоративное обновление по новому макету
может выполняться отдельно после визуального выбора.
