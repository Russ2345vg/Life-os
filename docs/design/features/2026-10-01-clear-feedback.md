## Как понят запрос

Фраза «без учёта этих правок» принята буквально: ранее обсуждённые исправления вычисления статусов,
commit/refresh и текстов дневника исключены. Вопрос об этом задан отдельно; до уточнения план
описывает новый UX поверх существующих возможностей.

Цель: из рабочего раздела быстро найти сведения об обмене данными, понять доступное действие
и вернуться в исходный раздел. Уведомления, автосохранение, retry и sync engine уже существуют.
Это ограниченное улучшение доступа и объяснения состояния, а не новая система хранения.

## Что уже есть и что добавится

| Уже есть                                                                   | Изменение этого плана                                       |
| -------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Уведомления и счётчики дня                                                 | Сохраняются без нового controller                           |
| Автосохранение дневника, retry, постоянный статус на mobile                | Сохраняются; не объявляются новой функцией                  |
| Account page, вход, recovery, ручная синхронизация, pending и время обмена | Более заметный вход и ясные подписи существующего состояния |
| Ссылка аккаунта в конце «Ещё»                                              | Прямой доступ desktop, первый пункт меню mobile             |
| Возврат из Account всегда в Today                                          | Возврат в исходный раздел с параметрами route               |

В desktop 1440×900 ссылка аккаунта после открытия «Ещё» начинается на `y=961.8`, ниже viewport.
На mobile она видна последним пунктом меню. В browser build Account недоступен; форму истёкшего
входа проверили отдельно на существующем fixture. Новый UX audit содержит восемь шагов,
16 просмотренных снимков, DOM и метрики.

## Границы

Входят: доступ из shell; подписи и пояснения существующей account-page; возврат к исходному route;
keyboard/focus, mobile и UX-приёмка. Действия аккаунта выполняет существующий service.

Исключены:

- Общий `OperationFeedback` и массовый перевод действий, дневника и памяти на него.
- Изменение action runners, completion receipt, retry после commit и очереди дневника.
- Исправление ложного «сохранено» у пустого дневника и текстов о сохранности draft.
- `PilotSyncStatus.attentionReason`, приоритеты sync mapper, freshness/read-generation,
  новый `refreshStatus` и замена транспортного источника состояния.
- Зелёный глобальный индикатор «всё синхронизировано», журнал событий, dashboard и новая страница.
- Изменение auth, recovery, sign-out, хранения, миграций, файлов и резервных копий.

Исключённые дефекты остаются открытыми. UX-приёмка этого scope не доказывает корректность старых
статусов или доставку записи на другое устройство. Поэтому новый вход называется нейтрально
**«Состояние данных»** и не показывает новую гарантию сохранения/синхронизации.

## Дизайн-контракт

```text
FEATURE → быстрый доступ к состоянию данных и возврат к работе
USER GOAL → найти состояние обмена, понять следующий шаг, вернуться в свой раздел
EXISTING LOGIC → AccountSync / AccountOverview, AccountSyncPage, текущая guard-aware навигация
PAGE/COMPONENT ARCHETYPE → существующая navigation link и стандартная страница настроек
SECTION COLOR → общий graphite/jade; gold для приоритета; текущие semantic states
ATMOSPHERIC MOTIF → спокойная рабочая поверхность
MAIN VISUAL CENTER → текущая задача; на Account — доступное действие по состоянию аккаунта
COMPONENTS TO REUSE → NavLink, AppIcon, AccountHeader, ReadyAccountPanel, account-panel/metrics
MOBILE BEHAVIOR → первый пункт «Ещё», без новой верхней строки и новой кнопки bottom nav
APPROVED REFERENCE → отдельный большой макет не требуется для существующих archetypes;
  baseline не является approval нового результата
TEST SCOPE → discoverability, source-route return, guards, copy, keyboard, desktop/mobile
```

Классификация: новая функция существующей оболочки/страницы. Актуальные компоненты и CSS изучены;
направление — действующий graphite/jade. Отдельная уникальная панель потребует изменения scope
и визуального макета; здесь она не предусмотрена.

## Вход и возврат

Desktop: в sidebar после «Поиск и добавление», перед основным nav — компактная ссылка
**«Состояние данных»** с существующим `AppIcon` account, областью нажатия не меньше 44 px.
Без счётчиков, цвета успеха и «сохранено» внутри ссылки. Она видна на 1440×900 и 1280×720
без открытия «Ещё». Основной контент Today не сдвигается вниз.

Mobile: **«Состояние данных»** — первый пункт «Ещё». Последний дублирующий пункт аккаунта убрать
из меню. Заголовок целевой страницы остаётся «Аккаунт и синхронизация». Bottom nav и верхняя
строка Today сохраняются. Доступ занимает два нажатия.

Обычный клик проходит через текущий `navigate` и guards; modified click сохраняет
`href="#/v2/account"`. Вход сам не выполняет sync/регистрацию. За native dialog ссылка
не становится доступной в обход модальности.

При разрешённом входе запомнить только исходный `PlannerRoute` в памяти оболочки.
На Account кнопка получает имя **«Вернуться в предыдущий раздел»** и ведёт к этому route,
включая дату/вид, уже закодированные в нём. При прямом URL/перезагрузке Account fallback — Today
с именем **«К плану дня»**. Возврат также проходит guards. Отказ перехода не меняет return target.
После успешного ухода с Account return target очищается; browser Forward без нового обычного
входа использует fallback Today. Источник Account никогда не записывается как цель возврата.

Сохранение произвольной локальной фильтрации и scroll после размонтирования не обещается:
сохраняются параметры route. Draft не копируется в URL, history или отдельное хранилище.

## Существующая страница аккаунта

AccountSync/AccountOverview, шаги формы и редактируемые поля сохраняются. Второго provider,
нового `SyncStatusDetails` или универсального recovery handler нет.

| Состояние                   | Отображение и действие                                            |
| --------------------------- | ----------------------------------------------------------------- |
| Загрузка                    | Текущий текст и существующий `service.load()`                     |
| Ошибка загрузки             | Текущая ошибка и «Повторить загрузку»                             |
| Unavailable                 | Причина недоступности, без новых неработающих sync controls       |
| Локальный аккаунт           | Существующее подключение/создание аккаунта, без auto-registration |
| Вход/recovery/подтверждение | Причина и соответствующая существующая форма                      |
| Ready                       | Существующий блок состояния и ручная синхронизация по нажатию     |
| Busy                        | Текущий busy/disabled блокирует повтор                            |

В `ReadyAccountPanel` изменить только представление существующих величин:

- заголовок **«Состояние данных»** вместо повторения email; email остаётся в hero;
- «Соединение» оставить;
- «Изменения» → **«Ожидают отправки»**, пояснить «Количество изменений, а не задач»;
- «Конфликты» → **«Сохранённые конфликтные версии»**, без новой классификации ошибки;
- оставить **«Последний успешный обмен в этом сеансе»** и существующее время/неизвестное значение;
- сохранить единственную **«Синхронизировать сейчас»** с текущими ограничениями;
- пояснение: «Сохранение на устройстве и обмен между устройствами — разные этапы.
  Сохранение текущего текста проверяйте в его редакторе».

Пояснения не выдают прошлый обмен за получение записи другим устройством. Формы и секреты
не переносятся в новый блок, транспортные счётчики не дублируются.
Формулировка «в этом сеансе» уже есть в AccountSyncPage: AccountSyncService берёт время из
pilot status, а PilotSyncCoordinator начинает с `lastSuccessfulSyncAt: null`. Здесь она сохраняется,
новый источник или обещание текущей доставки не вводится.

## UX и доступность

- Целевой путь: один клик desktop / два нажатия mobile до Account без прокрутки меню.
- Устойчивое имя ссылки, видимый focus, обычная семантика; цвет не является единственным сигналом.
- Tab следует DOM, скрытая responsive-копия не фокусируется. Escape штатно закрывает меню.
- После перехода focus следует существующей стратегии main; active form не закрывается в обход guard.
- На 390×844 и 320 px подписи переносятся без horizontal scroll и перекрытия controls.
- Heading/dl текущего блока сохраняют семантику; дополнительных live regions, toast и анимаций нет.

Обязательная экспертная проверка проводится на первой реализации и после её стабилизации.
Дополнительно рекомендуется короткий проход с пользователем: найти состояние, объяснить
сохранение/обмен, выбрать действие при истёкшем входе, вернуться к дневнику. Время, ошибки
и подсказки фиксируются. Этот проход не блокирует технический handoff, но без него понятность
интерфейса для пользователя остаётся гипотезой. Экспертный audit не называется тестированием
с реальными участниками.

## Критерии завершения

1. Новый вход виден в заданных местах, путь ≤1/2 нажатий; дубликат в меню отсутствует.
2. Вход/возврат соблюдают guards и сами не отправляют данные.
3. Return сохраняет исходный route и дату/вид; direct-entry fallback предсказуем.
4. Account выводит те же service values и существующие действия с ясными подписями.
5. Новый control не обещает полное сохранение/доставку. Исключённые дефекты остаются вне приёмки.
6. Targeted tests, scoped E2E, один `verify`, desktop/mobile review и Правило №38 выполнены.
7. Отчёт содержит маршруты, снимки, число действий и ограничения. Недоступный native/cloud
   сценарий и отсутствие пользовательского прогона не объявляются проверенными.

## Общие ограничения

- Новых зависимостей, миграций, application-команд и status engine нет.
- Предсуществующие незакоммиченные изменения сохраняются.
- Главный агент меняет файлы; независимые агенты исследуют и проверяют read-only.
- UI не изменяет предметное состояние напрямую; существующие service/guard контракты сохраняются.
- Commit, push, установщик и публикация в этот план не входят.
