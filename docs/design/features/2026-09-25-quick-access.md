# Единый быстрый доступ

Статус: IMPLEMENTATION AUTHORIZED (25.09.2026). Пользователь поручил внедрить предложенный
«Быстрый доступ» в выбранном размещении справа. Макету не присвоен статус APPROVED/LOCKED.
Объём: поиск, добавление действия и смена его даты.
[Интерактивный макет](../references/2026-09-25-quick-access/preview.html) содержит вымышленные
данные. После замечания к центральной панели пользователь выбрал вариант 2 — панель справа
с видимым текущим экраном — и последующим «Ну давай делай» поручил внедрение.

## Цель и границы

Из любого рабочего экрана найти нужную запись, быстро сохранить задачу или изменить её дату,
не теряя текущий контекст. Одна панель открывается видимой кнопкой «Поиск и добавление» либо
Ctrl/Cmd+K. На телефоне используется та же кнопка. Горячая клавиша не является единственным входом.

Первая поставка включает все три согласованные возможности. Массовые операции, удаление,
изменение целой повторяющейся серии, поиск по архиву, распознавание команд из свободного текста
и новый сервер поиска не входят в этот сценарий.

## Дизайн-контракт

- FEATURE: новый общий пользовательский сценарий и панель быстрого доступа.
- USER GOAL: меньше переходов при поиске, создании и планировании задачи.
- EXISTING LOGIC: PlannerCatalog.actions, GetGoals, GetDirections, GetSpheres, CreateLifeActionDraft, SetLifeActionPlan; текущая маршрутизация и формы деталей.
- PAGE/COMPONENT ARCHETYPE: правая боковая панель шириной до 560 px, на всю высоту окна; текущий экран виден слева под лёгким затемнением. Поиск — главный визуальный центр.
- SECTION COLOR: текущий нефритовый акцент; отдельная палитра не вводится.
- ATMOSPHERE: плотные графитовые поверхности Premium, системный sans-serif.
- MAIN VISUAL CENTER: строка поиска и найденные записи; во вкладке добавления — название задачи.
- COMPONENTS TO REUSE: native dialog/фокусное поведение PlannerSheet, VoiceTextInput, AppIcon, существующие кнопки, date helpers и submission helpers. Новый search icon добавляется в AppIcon, не отдельной системой.
- MOBILE BEHAVIOR: полноэкранная панель, прокрутка содержимого, доступная кнопка закрытия, зоны нажатия не менее 44 px; нижняя навигация остаётся под модальным слоем.
- APPROVED REFERENCE: общая тема Premium утверждена; размещение справа выбрано пользователем,
  реализация разрешена. Отдельного статуса APPROVED/LOCKED у макета нет.
- TEST SCOPE: агрегирующая query/selector, command regressions, render, scoped E2E desktop/mobile, verify.

Baseline: реальный маршрут `#/v2/today` на локальном Vite 5186 в активном worktree.
Сохранены baseline-desktop.png и baseline-mobile.png. Проверены текущий компонент,
каскад planner-v2 → planner-master → planner-premium и вычисленные font/акцент `#81cfab`.

## Поиск

Источники — существующие application readers. Панель загружается независимо от
PlannerWorkspace.data, чтобы работать также в аккаунте и подготовке ко сну. Отдельная база,
история запросов и синхронизируемый поисковый индекс не создаются.

Результат содержит kind, id, title, контекст сферы/направления/цели и доступные действия.
Ищем по названию и видимому контексту: trim, регистр, ё/е, все слова запроса. Точное совпадение
и начало названия идут первыми, затем совпадение внутри названия и контекста; внутри — название
и стабильный id. Максимум 30 результатов за раз, с явным предложением уточнить запрос при превышении.

Архивные записи исключаются. Для действий по умолчанию исключаются completed/cancelled;
для целей сохраняются неархивные состояния с явной подписью статуса. Список повторений
использует selectRecurringActionRepresentatives, не series id из selectActionOptions.
Строка содержит фактическую дату и признак повтора. Пустой запрос даёт ограниченную выборку
с подписью «Записи», а не выдуманные «Недавние».

Открытие результата использует существующий маршрут/редактор. Tab перемещает фокус,
ArrowDown из поиска переводит на первый результат; Enter в строке поиска открывает только
первый видимый результат, если он есть. Escape закрывает панель, возвращая фокус на источник.
При вводе через IME горячие клавиши не должны прерывать композицию.

После команды и события sync по lifeActions/goals/directions/spheres/recurrenceRules данные
перечитываются. Устаревшие async-ответы игнорируются. Ошибку одного источника нельзя выдавать
за полный пустой результат — ошибка с повтором загрузки всей выборки.

## Быстрое добавление

Обязательное название и явный выбор Сегодня / Завтра / Без даты. По умолчанию «Без даты»:
глобальное создание не заимствует незаметно дату фонового экрана. Даты вычисляются по currentDate
и addDays. Сохранение проходит через submitPlannerAction и CreateLifeActionDraft.

Кнопка блокируется на время запроса; повторное нажатие не создаёт дубликат. Успех показывается
только после подтверждённой команды. Панель остаётся открытой и показывает созданную запись;
черновик текущего экрана сохраняется. При ошибке ввод и выбор даты остаются, доступен повтор.
Название нового действия использует общую систему голосового ввода. Макет не запрашивает микрофон.

## Действия над результатом

Открытие доступно любой показанной записи. Смена даты — только поддерживаемым задачам:

- draft/ready: Сегодня или Завтра через planPlannerAction → SetLifeActionPlan;
- «Без даты»: только draft без expectedResult, readyAt и startedAt;
- in_progress и completed/cancelled: только открытие карточки, без переноса из панели;
- перенос повторения меняет конкретный action id, не всю серию; рядом подпись «Это повторение».

Недоступные действия не предлагаются. Окончательную валидацию выполняет существующая команда:
после sync состояние могло измениться. Ошибка не скрывается, дата не меняется оптимистически.
Отмена выбора даты ничего не записывает. Макет демонстрирует обычные draft-задачи.

## Сохранение текущей формы

Панель монтируется sibling к текущему контенту без смены route и без размонтирования формы.
Открытие, закрытие, добавление и изменение даты сохраняют незавершённый ввод фонового экрана.
Нельзя проверять только route new-action: редакторы сфер/направлений имеют внутреннее состояние.

Переход к найденной записи при незавершённой форме требует явного выбора «Остаться» либо
«Перейти без сохранения». Для реализации нужен локальный presentation-контракт регистрации
несохранённой формы (action/goal, balance editors, sleep/account forms по наличию ввода),
не копирование пользовательского текста и секретов в глобальный store. Проверить открытие
поверх существующего PlannerSheet и возврат фокуса. Простой key={route} не решает потерю ввода.

## Состояния и приёмка

Отдельно проверяются loading, пустая коллекция, отсутствие совпадений, error/retry,
saving/disabled, success и конфликт после изменения на другом устройстве. Текст не зависит
от цвета. При смене вкладки черновик создания не теряется до подтверждённой записи/явного сброса.

Targeted: новые query/render tests, PlannerForms, PlannerLibrary, PlannerUiFlows.integration,
actionSelection, SetLifeActionPlan. Scoped E2E: Ctrl/Cmd+K, Escape/focus, создание из account/sleep,
пустой запрос, ошибка+повтор, смена даты обычной задачи и повторения, запрет снятия даты ready,
сохранение черновика и подтверждение ухода. Размеры 1440/390/320 и keyboard/reduced-motion.

После реализации — verify. Полный E2E не требуется автоматически: routes сохраняются;
если защита форм затронет общий navigation-контракт, расширить выбранные сценарии согласно TEST_MATRIX.
