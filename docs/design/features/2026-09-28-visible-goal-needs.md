# Видимая потребность цели — 28 сентября 2026

Пользователь просит легко замечать потребность при создании и на плашке цели.
Это изменение существующих формы, списка и подробностей; новых разделов нет.

## Контракт

- Раздел: Цели. Текущая graphite/jade-тема и единая рабочая поверхность.
- Архетип: существующие форма и карточка. Название остаётся главным;
  ниже показывается подписанная потребность с более контрастным текстом.
- Переиспользование: `EntityNeedText`, `VoiceField`, `VoiceTextInput`,
  `resolveGoalNeed`, текущие токены. Сохранение через прежние application-команды.
- В форме потребность расположена сразу после названия, перед желаемым результатом.
  Она необязательна; пустое собственное поле сохраняет наследование направления.
- В списке текст виден без раскрытия, максимум две строки; источник наследования
  расположен отдельно и не обрезается. В открытой цели полный текст находится
  перед результатом и действиями.
- Empty: «Потребность пока не указана.»; данные не заполняются автоматически.
  Loading/error/success и блокировка при сохранении принадлежат существующим владельцам.
- Mobile: вертикальный поток, перенос длинного текста, отсутствие overflow на 390/320 px.
  Голосовой ввод, клавиатура и reduced motion сохраняются.
- Reference: существующий Premium; отдельный approved-макет не требуется.
  Новое визуальное утверждение от имени пользователя не заявляется.
- Scope: только цели; наследование действий и повторений остаётся прежним.
- Tests: render карточки с собственной/наследуемой/пустой потребностью,
  открытые подробности; scoped needs E2E создания, редактирования, повторного открытия
  и очистки уточнения на desktop/mobile; `npm run verify`.

## Проверка интерфейса

После реализации проверены форма на 1440×900, 390×844 и 320×844,
карточка и подробности на desktop/mobile в изолированных E2E-сценариях.
Потребность не требует раскрытия «Дополнительно» или «Детали»;
длинный текст не создаёт горизонтальную прокрутку, источник направления не скрыт.
Tab переводит фокус на поле; jade-outline заметен, подсказка связана через
`aria-describedby`. Ошибок в консоли открытой формы нет.
Общая оболочка, состояния сохранения, голосовой ввод и motion-владельцы сохранены.
Визуальная проверка по Правилу №38 выполнена для затронутых элементов:
иерархия, токены, контраст, отступы, перенос, keyboard/focus, desktop/mobile.
Новых анимаций или обхода reduced-motion не добавлено.

Снимки `after-form-*.png`, `after-card-*.png`, `after-detail-*.png` и
`after-inherited-*.png` находятся рядом с baseline. Форма во встроенном браузере
использует текущую пользовательскую ширину панели; карточки и подробности
сняты на тестовых данных без изменения пользовательского хранилища.

## Результаты проверок

- Targeted render/form: 22 passed; scoped `current.needs.spec.ts`: 6 passed,
  desktop и mobile, 48.95 s, exit 0.
- Часть `npm run verify` внутри `verify:full`: PASS — typecheck, lint,
  1637 unit/integration (1 штатный skip), 55 infra, 1 alpha, build, формат
  и Git hygiene. После этого код интерфейса не менялся.
- Полный E2E был начат из-за преждевременного перехода к выпуску 1.0.23.
  После вопроса пользователя о лишнем объёме проверок прогон остановлен;
  успешным полным gate он не считается. Owned-порт 4173 освобождён.
- Подготовка установщиков и публикация не выполнялись. Номер версии возвращён
  к 1.0.22; правка остаётся в рабочем дереве для общего следующего выпуска.
  На установленном приложении эта правка пока недоступна.

## Baseline

Активный worktree `D:/LifeOS-App`, маршруты `#/v2/goals`, `#/v2/goals/new`.
Браузер подтвердил, что поле потребности невидимо при закрытом «Дополнительно».
Desktop 1440×900 и mobile 390×844 зафиксированы до изменения.
Computed tokens: primary `#eef3f2`, secondary `#b2bfbe`, accent `#81cfab`.
Каскад: tokens/global → planner-v2 → planner-master → planner-premium;
последующие date-undo/wake overrides не относятся к потребности цели.

Снимки находятся в `docs/design/references/2026-09-28-goal-needs/`:
`before-form-desktop.png`, `before-form-mobile.png`.
Baseline карточек переиспользует screenshots актуального успешного E2E 1.0.22
на неизменённом коде: `before-card-desktop.png`, `before-card-mobile.png`.

Этот контракт уточняет отображение целей из
[модели потребностей](2026-09-27-needs-and-recurrence.md):
потребность цели больше не скрывается в дополнительной группе или деталях.
