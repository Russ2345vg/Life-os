# Единый альбом целей

Пользовательское решение: отдельные проекты заменяются целями существующего альбома.
Канонический источник — Goal в goals. ProjectRepository и projectId остаются совместимыми
портами/именами ссылок, читающими и изменяющими те же цели. Сфера, главное положение,
пауза, описание и ожидаемый результат сохраняются вместе с полями альбома.

## Дизайн-контракт

- FEATURE: изменение существующего сценария управления целями.
- USER GOAL: создавать цели и связывать направления, решения и действия с конкретной целью.
- EXISTING LOGIC: Goal album + прежние команды управления проектом через совместимый порт.
- PAGE/COMPONENT ARCHETYPE: существующие GoalAlbumPage, GoalDetailPage, GoalForm.
- SECTION COLOR: зелёный роста; primary остаётся золотым.
- MAIN VISUAL CENTER: сетка альбома / открытая карточка цели, прежний мотив роста и дали.
- COMPONENTS TO REUSE: карточки, формы, вкладки, фильтры, voice inputs, списки действий.
- MOBILE BEHAVIOR: существующая адаптивная сетка и вертикальная форма.
- APPROVED REFERENCE: новый не требуется, пользователь просит сохранить текущий интерфейс.
- STATES: loading/retry, пустой альбом, ошибки сохранения, успех, архив сохраняются.
- TEST SCOPE: domain, persistence upgrade/replay/rollback, links, sync/recovery, browser/mobile.

## Совместимость и восстановление

Каждому старому проекту соответствует ID `goal-from-project:<старый ID>`. Это необходимо,
поскольку sync metadata использует ID без типа; одинаковый ID проекта и цели нельзя смешивать.
Одинаковые названия не объединяются. Старые записи и резервная копия сохраняются локально.
Миграция и исправление ссылок атомарны. Повторный импорт использует тот же ID.
Старые события не перезаписывают цель, изменённую после переноса: исходная запись сохраняется
для восстановления. Новые изменения работают только с goals и синхронизируются как goal.
Удалённая схема не должна разрушительно меняться; старые wire types принимаются для совместимости.

## Приёмка

Один пункт «Альбом целей»; создание/редактирование, пауза, восстановление, главное положение;
сохранение существующих целей и полей проекта; направление → цель → решение → действие;
старый URL открывает соответствующую цель; reload, повторный перенос и импорт не создают дубли.

## Локальная миграция v22

Перед переносом исходные записи projects, goals, decisions, journal, walks,
preparationPlans и eveningCycles сохраняются в IndexedDB store `goal_migration_backup`.
Перенос выполняется одной versionchange-транзакцией: при ошибке сохраняется версия v21
и исходные записи. Таблица `goal_migration_bindings` хранит соответствие ID и защиту
от повторного импорта. Legacy projects остаются техническим архивом; удаление такой
исходной записи не удаляет самостоятельную каноническую цель. Коллизии ID прерывают
перенос вместо перезаписи данных. Цель со связанными записями можно архивировать;
её локальное удаление запрещено.

Удалённая среда Supabase и обмен между реальными устройствами в этой задаче не проверены.
Разрушительных DDL и удалений на сервере не выполнялось.
