# Настраиваемый фокус и история

Пользователь подтвердил макет мини-таймера 09.10.2026. Изменение существующего сценария фокуса: настройки, история в «Аналитика → Время», компактный режим главного окна Windows. Утверждённый reference: `docs/design/references/focus-mini-timer.png`.

Цель — видеть и сохранять фактическое время сосредоточенной работы и продолжать фокус после сворачивания или закрытия главного окна.

Используются существующие ActionPomodoro, WorkSessions, ActionSession и аналитика рабочего времени. Один владелец таймера и записи сессии. Фокус 1–180 минут, короткий/длинный перерыв 1–60 минут, defaults 25/5/15. Длинный перерыв после четырёх фокусов. Настройки сохраняются локально для следующих запусков; активный цикл сохраняет собственные настройки. Старые snapshots получают defaults.

Каждый новый фокус — отдельная ActionSession с additive `kind: focus`. Старые сессии остаются `work`; ретроспективная классификация не выдумывается. Паузы исключаются, перерыв не создаёт рабочую сессию. Автоматическое завершение сохраняет точный deadline; раннее завершение — фактическое время. История — подмножество существующего рабочего времени, не второй вклад. Фильтры недели/месяца/дня и локальные границы дат сохраняются. Поле совместимо с schemaVersion 1 и mixed-version sync; миграция не требуется.

Windows использует тот же WebviewWindow и React-владелец. X/minimize во время фокуса или паузы переключает его в 340×230 всегда поверх окон. Исходные bounds/mode сохраняются; «Открыть LifeOS» и окончание фокуса восстанавливают главное окно. Это видимый компактный режим, а не скрытый второй timer. Ошибки native перехода показываются. Вне активного фокуса X закрывает приложение обычным способом.

Компоненты: существующий PlannerSheet, primary controls, analytics detail rows; graphite/jade effective tokens. Главный центр — отсчёт. Mobile: адаптивная форма и история, существующий внутриприкладной индикатор. По запросу пользователя все последние изменения (прогулки, история успехов, настройки и история фокуса) выпускаются также в подписанном Android APK через существующий LifeOS-Releases. Native overlay Android не входит в согласованный сценарий; компактное окно предназначено для Windows. Empty/error/loading состояния используют существующие паттерны.

План: domain/settings и совместимость → application history/deadline → UI/settings/history → Windows controller → targeted/shared gate → scoped desktop/mobile и isolated native QA → подписанные Windows/Android сборки, проверка прежней подписи Android и update feeds.

Проверки: custom cycle/pause/reload, invalid/legacy settings, mapper и mixed-version preservation, deadline cap, история через полночь без пауз/двойного учёта, scoped UI, реальный X/minimize/restore Windows. Один `test:fast` и `verify` для общего контракта, без полного E2E. Native QA: отдельный профиль, пустые Supabase URL/key, accountSync/AI disabled при сборке; production release повторно собирается с действующей account sync конфигурацией.
