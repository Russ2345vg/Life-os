# Сон и подъём — этап 1: данные ночного цикла и расчёт времени

## Граница этапа

Этап создаёт отдельный от Evening Cycle доменный источник состояния для расписания сна. Он не
добавляет экран, уведомления, нативный Android-будильник, утренний сценарий или статистику.

## Авторитетное состояние

`SleepScheduleState` хранится как один атомарный агрегат с постоянным идентификатором
`sleep-schedule`. В агрегат входят настройки, исторические ночные циклы, конкретные будущие
срабатывания подъёма и одноразовые исключения. Каждая команда выполняет read-modify-write в одной
транзакции IndexedDB, поэтому параллельные команды не теряют изменения друг друга.

Настройки содержат локальное время сна, локальное время подъёма, IANA time zone, флаг `enabled`,
версию и время изменения. `enabled=false` — обратимый способ выключить новую функцию: будущие
активные срабатывания отменяются, история остаётся.

## Календарная семантика

`cycleDate` — локальная дата вечера, к которому относится ночь.

- Если время сна позже либо равно времени подъёма, сон приходится на `cycleDate`, а подъём — на
  следующий локальный день.
- Если время сна раньше времени подъёма, сон после полуночи и подъём приходятся на следующий
  локальный день.
- Переход через системную полночь не создаёт новый цикл и не изменяет уже созданный цикл.
- Для отсутствующего локального времени в DST gap выбирается первый существующий момент после
  него. Для повторяющегося времени выбирается первый из двух моментов; один цикл создаёт одно
  срабатывание.

## Перестроение и исключения

Перестроение принимает явный набор `cycleDate`, поэтому результат воспроизводим для фиксированных
дат. Оно сохраняет доставленные и пропущенные факты, не планирует повторный сигнал для уже
завершённой `cycleDate`, отменяет устаревшие будущие записи, не создаёт прошедшие сигналы и
повторно использует уже совпадающее активное срабатывание. Для одной пары
`cycleDate + plannedWakeAt` существует не более одного активного срабатывания.

Команда пропуска ближайшего сигнала выбирает только ближайшее активное будущее срабатывание,
переводит его в `SKIPPED` и добавляет `AlarmException`. Исключение не считается результатом
пробуждения.

## История подготовки

При первом создании `NightCycle` активные пункты подготовки копируются в снимок: идентификатор,
группа, заголовок, порядок и статус. Повторное открытие той же `cycleDate` возвращает сохранённый
цикл. Последующее переименование или удаление исходного пункта не меняет историю.

## Persistence и совместимость

IndexedDB v26 добавляет только object store `sleepSchedules` с `keyPath: id`. Миграция не
переписывает существующие stores и records. Агрегат регистрируется как sync-ready сущность
`sleep_schedule`; нативное подтверждение установки будильника остаётся за следующим этапом.
