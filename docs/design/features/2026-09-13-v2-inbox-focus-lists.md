# V2: Входящие, Фокус и общие списки

Baseline: `24560fd`, ветка `v2-current-baseline`. Предсуществующие dirty документы и настройки
не входят в блок. Требования: явный запрос пользователя, функциональная спецификация v1.1,
схема v0.2 и PDF каталога (страницы 2, 3, 7). Документы не расширяют разрешённый scope.

## Дизайн-контракт

FEATURE → новые рабочие страницы Входящие, Цели (Список/Фокус), Действия.
USER GOAL → захват без классификации, сознательный выбор фокуса, доступ ко всем записям.
EXISTING LOGIC → Goal, LifeAction, команды завершения/планирования/привязки, Journal.
ARCHETYPE → быстрый ввод и список; каталог с раскрываемыми фильтрами; глубокий фокус.
SECTION COLOR → существующие чёрно-бело-зелёные V2 tokens по явному запросу пользователя.
ATMOSPHERE → чистый чёрный фон без дополнительного декоративного мотива.
MAIN VISUAL CENTER → поле захвата / результаты списка / одна выбранная цель.
COMPONENTS TO REUSE → VoiceField, VoiceTextInput, VoiceTextArea, AppIcon, V2 формы и checkbox.
MOBILE → четыре нижних входа, одна колонка, фильтры под кнопкой, горизонтальная лента Фокуса.
APPROVED REFERENCE → PDF для списка/фильтров и визуального языка; Фокус по утверждённой
структуре запроса, Входящие из существующего архетипа быстрого ввода и списка.
TEST SCOPE → целевые domain/application/persistence/render/route/sync проверки; browser QA;
один npm run verify; полный Playwright/E2E запрещён пользователем.

Loading, empty, no-results/reset, error/retry, pending, success обязательны.

## Владение данными

- InboxIdea — отдельная входящая запись (не Goal stage=idea). Только title обязателен.
  Преобразование сохраняет исходный текст, target type/id; исходник не удаляется.
  Архивирование вместо отсутствующей политики hard-delete. Создание результата и изменение
  входящей записи происходят атомарно; повтор возвращает сохранённую ссылку.
- FocusPeriod — компактный агрегат периода с уникальными ссылками на Goal и ролями
  primary/supporting. Одна primary, максимум пять целей в интерфейсе. Goal не изменяется.
  Период по умолчанию — текущая неделя, без отдельного процесса планирования; прошлый выбор
  сохраняется, в новую неделю автоматически не копируется. Выбранная для просмотра цель — UI state.
- Списки читают существующие репозитории. Goal.status/stage не используются как признак inbox.
  Важность опирается на существующий intentionLevel, горизонт — horizon. Точного срока у Goal
  в baseline нет: не выдумывать дату из горизонта. Прогресс только из реального Goal.progress.
- Поздняя классификация и перенос используют SetLifeActionGoal и SetLifeActionPlan.
  Completion — CompleteLifeAction и существующий Journal; нет нового журнала событий.
- Две новые IndexedDB collections подключаются к существующему Sync Registry и recovery.
  Supabase migrations, transport encryption, secure storage не меняются. Обновление клиентов
  требуется до обмена новыми типами записей; старые типы и legacy UI сохраняются.
