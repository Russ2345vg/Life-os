# Вопросы для заметки на прогулке

Статус: реализация для проверки. Локальное дополнение существующей страницы.

## Контракт

FEATURE → вопросы для заметки → USER GOAL → легче начать размышление и сохранить мысль
→ EXISTING LOGIC → обычный WalkCapture через WalkServices.captures.capture
→ ARCHETYPE → раскрываемая подсказка в WalkCaptureComposer
→ SECTION COLOR → существующая graphite/jade тема
→ MAIN VISUAL CENTER → текущий вопрос внутри вторичного блока; таймер остаётся главным на странице
→ REUSE → native details/select/buttons, VoiceTextArea, текущие tokens
→ MOBILE → одна колонка, controls от 44 px, перенос длинного текста
→ APPROVED REFERENCE → отдельного нового нет; текущая страница /#/v2/walks и направление 25.09.2026
→ TEST SCOPE → помощник вставки, сохранение обычной мысли, scoped walkthrough desktop/mobile.

## Поведение и границы

- В активной или приостановленной прогулке доступен необязательный блок «Вопросы для заметки».
- Шесть тем по шесть вопросов: день, чувства, приоритеты, отношения, идеи, выбор.
  Вопросы движутся от наблюдения к значению, возможностям и небольшому действию.
- Одновременно виден один вопрос, его номер и кнопки назад/вперёд.
  Смена темы возвращает к первому вопросу, не меняя черновик.
- «Добавить вопрос в заметку» дописывает вопрос, сохраняет весь существующий текст
  и фокусирует привычное поле с голосовым вводом. Нет автоматического сохранения.
- Повторное добавление того же вопроса в этот черновик запрещено.
  При превышении существующего лимита 500 символов текст не обрезается;
  показывается совет сохранить текущую мысль и начать следующую.
- Пользователь может пропускать вопросы, закрывать блок и писать свободно.
  Никакого обязательного опроса, оценки ответов или запросов к AI.
- Вопрос и ответ сохраняются простым текстом в существующем capture с promptStage=null.
  Схема, формат sync, guided reflection stages, аккаунт и сервер не меняются.
  Совместимость самой прогулки продолжает определяться существующей политикой sync.
- Каталог и правило вставки принадлежат application; выбор темы/номера — локальный UI state.

## Состояния и проверка

Начальное состояние — блок закрыт. Empty/error/saving/success заметки остаются существующими.
Крайние вопросы имеют disabled-навигацию; duplicate/limit объясняются текстом.
Native controls сохраняют keyboard/focus; нет новых анимаций.
До правки снят текущий экран desktop 1440×900 / mobile 390×844;
evidence вне Git: artifacts/visual-qa/walk-note-questions/before.
После: screenshots открытого блока, focus, отсутствие overflow и browser errors,
сохранение/перезагрузка, смена темы без потери текста, граничный размер.

Targeted unit и scoped E2E → typecheck/lint/build/format → release checks и подпись.
Полный suite не требуется: нет общего контракта, схемы хранения или startup/routing изменений.
