# Утренняя зарядка перед главным фокусом

## Цель

Каждое утро пользователь проходит готовый комплекс зарядки примерно за 30 минут, отмечает фактические повторы или длительность каждого подхода и только после этого переходит к часу фокуса по главной задаче дня. Зарядка входит в утренний ритуал и располагается на странице «Сегодня» перед блоком «Главная задача дня».

## Дизайн-контракт

`FEATURE → USER GOAL → EXISTING LOGIC → PAGE/COMPONENT ARCHETYPE → SECTION COLOR → MAIN VISUAL CENTER → COMPONENTS TO REUSE → MOBILE BEHAVIOR → APPROVED REFERENCE → TEST SCOPE`

`Зарядка → привести тело в рабочее состояние → MorningCycle, MorningPhysicalPlan и MorningPhysicalExecution → ритуальная карточка на «Сегодня» → общий jade для текущего действия, зелёный только для завершения → список сегодняшних подходов → текущие panel/button/input и PlannerToday → один столбец, controls не меньше 44 px → YES, «Единая рабочая поверхность» → domain, migration, persistence, component, scoped E2E desktop/mobile, release regression`

## Готовый комплекс

Комплекс рассчитан на турник и коврик, не использует таймер и запускается каждый день в одном порядке:

1. Разминка — 2 подхода по 150 секунд.
2. Подтягивания — 3 подхода по 4 повторения.
3. Отжимания — 3 подхода по 10 повторений.
4. Приседания — 3 подхода по 15 повторений.
5. Планка — 2 подхода по 30 секунд.
6. Растяжка — 2 подхода по 150 секунд.

В карточке показывается весь список, текущий подход и поля факта. Пользователь вводит фактические повторения или секунды и нажимает «Готово»; отдельного обратного отсчёта нет. Подход можно пропустить. Зарядку целиком можно явно пропустить на это утро, после чего фокус разблокируется.

## Прогрессия нагрузки

После завершения комплекс оценивается по каждому силовому упражнению. Если все подходы выполнены не ниже цели, LifeOS предлагает увеличить цель на 1 повторение или 5 секунд. Если подход пропущен либо результат ниже 80% цели, LifeOS предлагает снизить цель на 1 повторение или 5 секунд. Разминка и растяжка не прогрессируют автоматически.

Предложение сохраняется в утреннем цикле. Пользователь принимает или отклоняет его. Принятый вариант становится основой следующего утра; при отклонении повторяется текущий план. До решения карточка остаётся завершённой и не блокирует фокус.

## Состояния и устойчивость

- Loading сохраняет место карточки, error даёт повторить загрузку, empty создаёт готовый комплекс.
- В процессе активен только текущий подход; завершённые и пропущенные подходы остаются видимыми.
- Перезагрузка восстанавливает текущий подход и введённые факты из IndexedDB.
- Старые базы получают определения «Разминка» и «Растяжка» миграцией без изменения пользовательских записей.
- `morning_cycle` остаётся единственным источником состояния зарядки и продолжает синхронизироваться между устройствами.
- Утренний фокус активен только после `DONE` или явного `SKIPPED` физического этапа.

## Проверка

Доменные тесты закрепляют готовый комплекс, последовательность подходов, расчёт предложений, принятие/отклонение и повторное открытие. Persistence-тесты покрывают миграцию и обратную совместимость записей. Компонентные и scoped E2E-проверки покрывают старт, ввод факта, пропуск, завершение, блокировку фокуса, desktop/mobile, keyboard focus и browser console. Поскольку результат выпускается как установочная версия, обязательны `test:release`, `verify:full`, сборка подписанных пакетов и проверка опубликованных manifest/installer URL.
