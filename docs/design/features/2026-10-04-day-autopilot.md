# Автопилот дня

## Контракт

```text
FEATURE → функция страницы «Сегодня»: автоплан остатка дня
USER GOAL → за один шаг получить реалистичное расписание и применить его после проверки
EXISTING LOGIC → LifeAction.plannedDate/isNext/estimateMinutes/scheduled*;
  TimeCapacityService; ActionSession; подтверждённые SleepObservation
PAGE/COMPONENT ARCHETYPE → inline workflow внутри существующего «Плана на сегодня»
SECTION COLOR → общий jade; gold только для главного действия
MAIN VISUAL CENTER → preview временной шкалы с резервом и отложенными задачами
COMPONENTS TO REUSE → planner-day-workspace, action rows, primary/secondary controls,
  time presentation и существующий refresh страницы
MOBILE BEHAVIOR → одна колонка; время, причина и длительность остаются читаемыми;
  подтверждение занимает полную ширину
APPROVED REFERENCE → YES: текущая «Единая рабочая поверхность» и принятый пользователем
  краткий дизайн функции от 2026-10-04
TEST SCOPE → pure planner + application/IndexedDB atomicity + component tests + scoped E2E,
  desktop/mobile/keyboard/console QA + verify
```

## Задача и границы

Автопилот собирает расписание для уже запланированных на выбранную дату открытых действий.
Главное действие получает первый доступный длинный блок. Остальные действия упорядочиваются по
приоритету, наличию оценки и времени создания. Пользователь видит preview, допущения, резерв и
список того, что не помещается. Запись выполняется только отдельной командой «Применить план».

Первый выпуск не создаёт второй объект «план дня», не переносит задачи на другую дату и не
подключает неиспользуемые runtime-слои старых RoutineBlock. Источником истины остаются временные
поля `LifeAction`. Просроченные задачи показываются как кандидаты за пределами текущего автоплана;
их дата не меняется автоматически.

## Правила построения

- Диапазон начинается с выбранного пользователем времени. Для сегодняшнего дня default — ближайшие
  пять минут после текущего момента; для будущей даты — 09:00. При пересборке сегодняшнего остатка
  выбранное начало автоматически поднимается до текущего времени, поэтому прошедшие блоки не
  перемещаются.
- Длина диапазона равна доступному времени дня. Если оно не задано, preview использует явное
  допущение 8 часов и сообщает об этом.
- Автопилот оставляет резерв 15%, минимум 30 минут. После подтверждённой короткой ночи менее
  7 часов резерв увеличивается до 25%; это мягкий сигнал планирования, а не оценка здоровья.
- Режим «Заполнить свободное» сохраняет заданные пользователем окна. Режим «Пересобрать остаток»
  может сдвинуть только будущие окна после явно показанного preview.
- Завершённые, прошедшие и связанные с running/paused session действия заблокированы. Между рабочими
  блоками вставляется пятиминутный буфер. Неизвестная оценка считается 25 минутами и помечается.
- Одно действие остаётся одним `LifeAction`. Ритм 25/5 показывается как способ выполнения внутри
  блока; отдельные сущности на каждый Pomodoro не создаются.
- Непоместившиеся действия получают причину. Автопилот не скрывает их и не меняет дату. Если режим
  пересборки вынес за пределы плана будущее действие с прежним окном, подтверждение атомарно убирает
  это окно из временной сетки и оставляет действие в плане выбранной даты.

## Preview и применение

Preview содержит момент построения, исходную версию каждого изменяемого действия, предложенные
окна, заблокированные окна, резерв, суммарную нагрузку и отложенные действия. Применение выполняется
одной `JournalUnitOfWork` транзакцией с optimistic version checks и проверкой незавершённых рабочих
сессий внутри этой же транзакции. Изменение задачи или запуск сессии в другой вкладке делает preview
устаревшим; UI перезагружает данные и предлагает собрать план снова.
Если до подтверждения наступило время любого перестраиваемого или удаляемого из сетки окна,
применение также отклоняется: пользователь собирает свежий план остатка дня.

Повторный запуск после применения открывается как «Пересобрать остаток дня»: прошедшая часть и
текущая рабочая сессия сохраняются, будущие окна можно перестроить только после нового preview и
подтверждения.

## Состояния интерфейса

- **Ready:** короткое объяснение, время старта и действие «Собрать мой день».
- **Loading:** занята только карточка автопилота; остальная страница остаётся доступной.
- **Preview:** временная шкала, причины порядка, резерв, допущения и отложенные задачи.
- **Empty:** сегодня нет открытых действий для планирования.
- **Error/stale:** понятное сообщение и действие повторного построения.
- **Success:** подтверждение, обновлённый план страницы и возможность пересобрать остаток.

Управление доступно клавиатурой, динамические результаты объявляются через live-region. На mobile
контролы и строки не требуют горизонтальной прокрутки.
