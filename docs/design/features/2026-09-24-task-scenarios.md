# Сценарии задач на странице «Сегодня»

Согласовано в диалоге: пользователь заранее собирает набор из существующих задач,
добавляя их по одной до трёх. Набор можно создавать на день или сохранять для повторного
использования. Переключение набора не сбрасывает выполнение и не создаёт новые задачи.

## Дизайн-контракт

- FEATURE: новая функция существующей страницы «Сегодня».
- USER GOAL: выбрать заранее подготовленную тройку под обстановку.
- EXISTING LOGIC: LifeAction и существующая команда CompleteLifeAction остаются источником
  состояния задач; сценарий содержит только их идентификаторы.
- PAGE/COMPONENT ARCHETYPE: существующий центр управления 8+4, inline-форма и список.
- SECTION COLOR: общий тёплый акцент; зелёный только для выполненного.
- ATMOSPHERE: общий лесной фон и дымчатые поверхности оболочки.
- MAIN VISUAL CENTER: список выбранного сценария; «Все задачи» возвращает обычный план.
- COMPONENTS TO REUSE: VoiceTextInput, строки действий, planner-segments, кнопки и tokens.
- MOBILE BEHAVIOR: одна колонка, перенос названий, touch targets не менее 44px.
- APPROVED REFERENCE: существующий общий эталон «Новое направление»; отдельный макет
  для стандартной inline-формы не требуется. Новому блоку визуальный статус не присваивается.
- TEST SCOPE: domain/application, IndexedDB upgrade/reopen, sync/snapshot compatibility,
  render tests, desktop/mobile browser flows, verify и полный E2E из-за persistence.

## Поведение

Сценарий хранит id, title, actionIds (0..3 уникальных ссылок в порядке добавления),
date (конкретный день или null для повторного использования), archived, updatedAt,
version и schemaVersion. Пустой набор разрешён для постепенного заполнения.
Сохранение происходит после каждой команды. Форма создания и редактирования содержит
название и «Сохранять на следующие дни» (по умолчанию включено).

Выбор показывает сохранённые наборы и наборы выбранного дня. Можно переименовать набор,
изменить его срок использования, убрать отдельную ссылку, добавить другую задачу или
удалить набор без удаления задач. Добавляются существующие незавершённые задачи из
каталога, с поиском; задачи выбранного дня показываются первыми. Даты задач не меняются.
Выполненные остаются в наборе с общей отметкой; автоматического повтора нет. Удалённая,
архивированная или отменённая задача отображается как недоступная ссылка, которую можно
убрать; набор не блокирует обычное удаление задач.

Выбор активного сценария — временное состояние интерфейса. После открытия страницы
по умолчанию показаны «Все задачи». Смена дня сбрасывает выбор, сохраняя сами наборы.
Загрузка и ошибки набора не блокируют общий план. Ошибка имеет действие повтора,
изменения не скрываются до подтверждения записи; успех сообщается через role=status.

## Хранение и совместимость

Отдельный taskScenarios store, IndexedDB v27; upgrade добавляет только пустое хранилище.
Application-команды работают через TaskScenarioRepository; React не пишет предметное
состояние. Sync registry использует task_scenario с необязательными ссылками life_action.
Старые snapshots v26 и ниже не обязаны содержать новый store. Наборы входят в новые
snapshots и зашифрованную синхронизацию. Для синхронизации нового типа нужны обновлённые
клиенты на обоих устройствах; смешанные версии не гарантируются существующим протоколом.

## Проверка пограничных случаев

Лимит и уникальность проверяются внутри транзакции, включая параллельное добавление.
Ошибка сохранения не меняет список. Повторная команда добавления одной ссылки идемпотентна.
Удаление набора не затрагивает задачи. Завершение общей задачи видно в нескольких наборах.
Повреждённые sync payload отклоняются; отсутствующая задача не блокирует приём набора.

## Соседний browser-контракт

Новый блок увеличивает высоту Today. Полный E2E обнаружил, что отложенное событие
прокрутки после автоматического подвода к кнопке закрывает только что открытое меню задачи.
EntityContextMenu теперь запоминает положение кнопки при открытии и игнорирует scroll
без нового перемещения; реальная прокрутка и resize закрывают меню. Игнорируемое событие
не сбрасывает подавление клика после долгого касания. Поведение закреплено browser-тестом.
