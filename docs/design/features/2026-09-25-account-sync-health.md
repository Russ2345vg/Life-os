# Достоверное состояние синхронизации

## Контракт

- FEATURE: уточнение существующего сценария аккаунта и подключения второго ПК.
- USER GOAL: понимать, отправлены ли изменения перед переходом на другое устройство.
- EXISTING LOGIC: AccountSyncService, PilotSyncCoordinator, AccountOverview. Источник состояния — существующий координатор и его отчёт; хранилище, ключи и протокол не меняются.
- PAGE/COMPONENT ARCHETYPE: существующий экран аккаунта и панели состояния/устройств.
- SECTION COLOR: текущий нефритовый акцент, успех только при подтверждённом обмене; внимание — существующее pending-состояние.
- ATMOSPHERE: плотные графитовые поверхности текущей темы.
- MAIN VISUAL CENTER: достоверный статус обмена.
- COMPONENTS TO REUSE: AccountSyncPage, account-feedback, account-metrics, существующие кнопки.
- MOBILE BEHAVIOR: существующая одна колонка, перенос текста, зоны нажатия от 44 px.
- APPROVED REFERENCE: текущая общая тема Premium; новый уникальный макет не требуется.
- TEST SCOPE: service/render regression, соседние recovery/coordinator tests, verify, scoped account E2E desktop/mobile.

## Поведение

Доступность сервера не означает успешную синхронизацию. Ready/online показывает успех только
при idle, наличии подтверждённого обмена, отсутствии очереди и конфликтов. Ошибка, offline,
syncing и attention имеют отдельные тексты. Незавершённый отчёт без sequence не подтверждает
успех; новая очередь после завершённого прохода не затирается более старым отчётом.

Время обозначено «Последний успешный обмен в этом сеансе»: координатор не сохраняет его между
запусками, и оно не гарантирует отсутствия конфликтов. Null не превращается в сегодняшнюю дату.
Статус — снимок после загрузки или команды; live-подписка в этот патч не входит.

Инструкция второго ПК находится рядом с устройствами. Ключ раскрывается только существующей
явной кнопкой. Loading/error/retry, local-only и восстановление остаются существующими сценариями.
Неудачная ручная синхронизация не показывает уведомление об успехе; повтор доступен той же кнопкой.

Полный E2E не требуется: протокол, схема хранения и общий routing не меняются. Реальная установка
и облачное восстановление на двух физических ПК остаются отдельной ручной проверкой.
