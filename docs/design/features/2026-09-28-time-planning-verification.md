# Проверка планирования времени — 28.09.2026

Поставка этого этапа: календарь дня/недели, необязательная оценка и временной блок действия,
доступное время по дням недели, отражение в Today и карточке действия. Этот документ
фиксирует календарный этап. Затем пользователь утвердил макет рабочих сессий и отчёта;
их внедрение и проверки описаны в [отдельном отчёте](2026-09-28-work-time-verification.md).

Предсуществующие evening / weekly / goals / completion summary / trash / saved views
сохранены в dirty worktree. Проверки всего репозитория не означают отдельного review
этих прежних изменений. Git commit и push не выполнялись.

## Поведение и совместимость

- Время хранится у существующего LifeAction; отдельной копии плана нет.
- Соседние окна разрешены. Ручное пересечение отклоняется в той же write-транзакции,
  включая возврат завершённого действия, дату/undo и восстановление из корзины.
- Отказ при reopen сохраняет результат, вклады цели и журнал; это проверено на реальной
  fake-indexeddb транзакции с непустыми вкладами.
- Успешный возврат подготовленного действия сохраняет его подготовку и возвращает
  ready; обычное действие возвращается в draft. Исправлена неполная запись, возникавшая
  при прежнем очищении readyAt. Domain rehydrate invariants не ослаблены.
- Уже импортированные пересечения и автоматическое возвращение существующего повторения
  сохраняют окна и показывают конфликт. Materialize не перекрывает чтение приложения
  после resume или истечения pauseUntil. Ручной перенос остаётся строгим.
- Форма времени сохраняет исходную версию и черновик при обновлении данных. Удаление
  блока сохраняет оценку, снятие даты убирает блок, undo восстанавливает прежние поля.
- Неизвестная оценка и неизвестные доступные часы обозначаются явно.
- Рабочая сессия не завершает действие. Паузы исключены из факта; одна незавершённая
  локальная сессия и версии защищены внутри UoW.
- Факт делится по местной полуночи, хранит цель на момент начала и сохраняется при
  архиве/отсутствии действия. Старые сессии остаются без выдуманной атрибуции.
- Проверены upgrade v27 → v28, манифесты снимков v23–27, exact restore старых полей,
  захват нового capacity/session в outbox, отсутствие полей старого клиента и explicit null.

## Browser review и правило №38

Проверены desktop 1440 и mobile 390 в изолированных Playwright контекстах. Снимки
календаря и Today просмотрены во время проверки; временные артефакты `test-results`
перезаписаны последующим scoped запуском и не являются постоянным приложением к отчёту.
Данные этих сценариев синтетические; профиль пользователя не заполнялся тестовыми записями.
Актуальный маршрут `/#/v2/actions?view=calendar` также проверен в in-app browser.

- Центр экрана — расписание; вторичная информация находится в контексте выбранного дня.
- Используются актуальные графитовые поверхности и jade выбранного состояния;
  золото — приоритет, красный — конфликт. Смысл дополнен текстом.
- Общие Sheet, controls, focus и типографика сохранены; новой оболочки и анимации нет.
- Короткие блоки имеют честную геометрию. Их доступные кнопки редактирования вынесены
  в список и имеют высоту не меньше 44 px.
- Mobile показывает выбранный день, доступное время и списки; горизонтального overflow нет.
- Empty, неизвестная capacity, конфликт, сохранение и disabled проверены в сценариях;
  loading/error/retry использует существующее состояние workspace.
- Escape возвращает фокус кнопке открытия. Ручная in-app проверка формы capacity
  также подтвердила возврат фокуса и отсутствие overflow.
- Вручную проверено переключение week/day/month в текущем in-app приложении.
- Scoped сценарий реального приложения завершился без pageerror.

## Ограничения

Live cloud transport не проверялся; локальные sync/recovery-контракты проверены.
Timer/report UI поставлен следующим этапом после явного утверждения макета.
Его актуальное доказательство вынесено в отдельный отчёт выше.

Полный E2E обнаружил прежние сценарии completion filters / daily workflow / motion,
которые продолжают кликать за открытой панелью «Итог задачи», и direction actions,
который ищет прежний текст «Добавить результат». Это несовместимость старых тестов
с предсуществующим completion summary; она не исправляется в time scope.
На desktop/mobile падают 2 filters, 2 daily workflow, 2 direction actions и 4 motion.
Сам актуальный `current.completion-summary.spec.ts` прошёл на обоих проектах.
Повтор полного набора после локальной коррекции prepared reopen не выполняется:
этот путь покрыт собственной регрессией и scoped E2E, общий storage-контракт не менялся.
