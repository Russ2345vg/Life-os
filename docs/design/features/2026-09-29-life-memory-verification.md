# «Память жизни»: реализация и проверки

Дата: 29.09.2026. Реализация разрешена сообщением «реализовывай»;
макет явно утверждён сообщением «да утверждаю».

## Результат

Реализованы задачи 1–8: лента по месяцам, выбор года, поиск и фильтры, редактор и просмотр,
одна фотография, отметка главного, мягкое удаление/восстановление, ручной перенос ответа
дневника за день/неделю/месяц и обзор «Мой год». На desktop раздел рядом с дневником;
на mobile он открывается через «Ещё», пять основных пунктов сохранены.

Состояние принадлежит MemoryRepository, изменения проходят через application-команды.
Схема IndexedDB v31 добавляет memoryEvents. Фото подключены к существующим encrypted
attachments, bootstrap, snapshot/recovery; remove/restore используют upsert с deletedAt.
Нет второй сохранённой копии событий для годового обзора.

Чтение, sync и recovery всегда зарегистрированы. Запись отключена по умолчанию через
VITE_LIFEOS_MEMORY_ENABLED; для browser QA флаг включался только в окружении тестового процесса.
Настройки выпуска и пользовательские данные не изменялись. Предсуществующий dirty worktree
Today/monthly direction/cold shower/action details/voice input сохранён. Commit/push/публикации нет.

Browser-сценарии: double-submit → одна запись; фото create/reload/edit/highlight/year/delete/restore;
ошибка декодирования и quota сохраняют текст; конфликт не перезаписывает чужие изменения;
Back/Escape защищают dirty draft; пагинация 30→32 и сброс фильтра; direct URL с pending photo,
правка текста сохраняет reference, явное удаление очищает его. При выключенном флаге существующие
события и год читаются, элементы записи disabled.

Дневник: перенос ждёт autosave, при сбое не открывает форму со старым текстом; отмена не создаёт
событие; снимок остаётся независимым после изменения источника; ссылки ведут в точный период.
Неделя/месяц предлагают min(periodEnd,today), а не дату переноса. После смены периода чистый подготовленный черновик закрывается и не открывается повторно при возвращении; дополнительный scoped Diary-набор — 8 PASS, exit 0.

Независимый final review нашёл два P2, оба воспроизведены RED→GREEN:

- Открытый дневник мог переносить свежую repository-версию вместо видимого ответа. Теперь
  expectedVersion берётся из autosave-контроллера после flush; чужая правка даёт конфликт.
- HTML max даты блокировал правку только текста события из другого часового пояса. Неизменённая
  дата существующей записи допускается; новые будущие даты по-прежнему отклоняет application.

Также исправлен возврат фокуса после отмены импорта: кнопка временно disabled, поэтому её
сохраняют до начала операции. Backend review ранее исправил потерю materialized photo и дату
старого периода. Null-фото сохраняет bytes/reference, удаление требует removePhoto:true.

Полный E2E не запускался: текущий этап — реализация одного раздела. Риски UI, Diary и account
покрыты выбранными сценариями; sync/migration/attachment/recovery — integration-тестами.
Managed E2E runner каждый раз подтвердил освобождение 4173. На Windows tree cleanup выдавал
Access denied, затем точный owned-root fallback завершался RECOVERED; чужие процессы не закрывались.

## Visual QA и Правило №38

Проверены реальное приложение, текущий каскад и computed tokens: accent #81cfab, priority #e4bc7b,
graphite surfaces. Новый memory.css загружается после planner-premium и diary.css.
Неопределённые priority/space-5 заменены существующими warning/space-6 локально.

- Desktop 1440×1000: лента/empty/year, редактор и focus. Populated E2E screenshots — 1440×900.
- Mobile 390×844 и 360×800: одна колонка, перестройка фильтров и формы, доступные нижние действия;
  overflow не обнаружен. В populated E2E проверены 390×844 и сохранность фото.
- Keyboard: начальный focus, Escape, блокировка Back при dirty, возврат в инициатор.
- Свежая загрузка в отдельной QA-вкладке: warn/error logs пусты. Ранние ошибки HMR при создании
  модулей устранены; проверка выполнялась после reload.
- Loading/empty/error/retry/success/disabled/pending/removed предусмотрены; категории и главность
  обозначены текстом/aria, не только цветом. Высота controls ≥44 px. Новых анимаций нет; общие
  reduced-motion правила переиспользованы.
- Чек-лист №38: визуальный центр — содержимое события; controls вторичны; единые поверхности,
  spacing/tokens/иконки, focus и контраст текущей темы. Структура не зависит от glow или цвета.

## Решения и граница выпуска

- Продолжена активная feature-ветка с существующими изменениями: спецификация зависит от них.
  Цена ошибки — необходимость внимательно отделить общие hunks перед будущим commit.
- Выбраны targeted/scoped проверки и один финальный verify вместо повторных полных suites.
  Цена ошибки — соседние сценарии опираются на выбранные integration/E2E и unit gate.
- Год выбирается числовым control вместо списка макета: доступны все календарные годы.
  Цена ошибки — возможная небольшая полировка control.

Native Windows/Android, реальный микрофон, фото между устройствами, offline/restart/reconnect
на установленных клиентах **не проверены**. Browser emulation не заменяет эти проверки.
Поставка A должна обновить чтение/sync/recovery всех устройств при выключенном создании.
Поставка B включает запись после подтверждения обновления устройств. Старый клиент отклоняет
memory_event и останавливает pull; неизвестные события не пропускаются молча.
Ни одна поставка не опубликована. Перед разрешённым релизом необходим R12 и native QA.
