# Динамика цели за 30 дней

Пользователь утвердил реализацию внутри существующей карточки цели сообщением «Давай сделаем».

## Дизайн-контракт

- FEATURE: новая функция существующей карточки цели, без нового раздела или маршрута.
- USER GOAL: увидеть сохранённые изменения результата и открыть записи/исходные выполнения.
- EXISTING LOGIC: PlanningContext и contributionIsEffective; канонический progress reader.
  Amount — дельта, initial — база, null неизвестен, 0 является настоящим результатом.
- PAGE/COMPONENT ARCHETYPE: существующая рабочая карточка цели; вторичный компактный график
  записанных изменений и раскрываемая хронология. Заголовок цели/её результат остаются главным
  визуальным центром. Исторические значения/проценты и причинные выводы не вычисляются.
- SECTION COLOR: текущие graphite/jade токены. Столбцы нейтральные; знак не означает оценку
  результата (отрицательное изменение может приближать цель).
- ATMOSPHERE: текущая premium-оболочка без новых фонов и эффектов.
- COMPONENTS TO REUSE: planning-workspace, planner-details, details/summary, ссылки и типографика;
  готового shared time-series chart нет, добавляется небольшой доступный SVG без зависимостей.
- MOBILE BEHAVIOR: один поток, масштабируемый график, полные даты и значения доступны в списке,
  controls ≥44 px, без горизонтального скролла.
- STATES: существующие loading/error карточки; empty «Нет записей за этот период»; неуказанные
  значения и недоставленные вклады отмечены текстом. Все изменения read-only, success state
  означает отображение сохранённых данных, новых команд записи нет.
- APPROVED REFERENCE: отдельное утверждение не требуется для компактного расширения текущего
  архетипа. Baseline реальной карточки снят desktop 1440 и mobile 390 в изолированном E2E.
  Текущий пользовательский профиль пуст, тестовые данные в него не записывались.
- TEST SCOPE: query/render и scoped current.goal-dynamics.spec.ts desktop/mobile → verify.
  Общие storage/routing контракты не меняются, полного E2E не требуется.

## Семантика

Окно включает сегодня и предыдущие 29 календарных дней. Дата результата — effectiveDate;
дата исправления — updatedAt. Initial, future, voided, stale completionKey и reopened вклады
не входят в записанные изменения. Архивация/удаление исходного действия сами по себе не
изменяют каноническую эффективность вклада; недоступный источник не превращается в ссылку.

Для каждой даты суммируются известные изменения. Если хотя бы одно значение не указано,
полный столбец дня не рисуется; известные записи доступны в подробностях. Пустые даты не
добавляются как нули. Нулевой результат рисуется точкой на нулевой линии. Переход цикла recurring
не становится отрицательной дельтой. Единица подписана как текущая: история её изменений не
хранится. Исправления пересчитывают график по актуальным фактам.

Для цели без измерения график и процент отсутствуют; показываются выполненные связанные
действия по completedOn (fallback localDate(completedAt)), без архивных/удалённых. Выполнения
рядом с записями не означают, что обычная связь действия с целью меняет числовой прогресс.
