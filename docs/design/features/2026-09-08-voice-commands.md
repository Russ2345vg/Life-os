# Голосовые команды — этап 2

Статус: этап 2 реализован и проверен из пользовательского интерфейса. Commit/push не выполнялись.

## Цель и граница

Речь или введённая команда превращается в структурированное намерение. Интерпретатор не получает
хранилище, application services или возможность выполнять код. Локальный русский разборщик
реализует заменяемый интерфейс. Подключение внешней модели не входит в эту реализацию.

Поток: Voice Input → CommandInterpreter → CommandValidator → CommandRegistry → preview →
confirmation → существующая application-команда → результат. Только navigate/search могут
исполняться без подтверждения. Удаление, редактирование, составные команды исключены.

## Найденные предметные контракты

| Намерение            | Текущий контракт                                  | Ограничение                                         |
| -------------------- | ------------------------------------------------- | --------------------------------------------------- |
| create_task          | CreateDecisionForDate                             | В LifeOS это решение, необходимы kind и plannedDate |
| create_goal          | CreateGoal                                        | Точного deadline нет; horizon не является датой     |
| create_note          | CreateWalkCapture только внутри прогулки          | Универсальной заметки нет                           |
| create_journal_entry | Нет команды свободной записи                      | Journal хранит историю событий и коррекций          |
| search               | GetGoals фильтрует status/directionId             | Поиска по тексту нет; команда неподключена          |
| navigate             | ApplicationShell, AppSection, GoalAlbumNavigation | Переход через существующие callbacks                |

Пользователь определил scope: задачи, цели и навигация через существующие операции.
Заметки и свободный дневник отложены до появления application-команд. Точный срок цели
не подменяется horizon: такая команда отклоняется до preview с объяснением.
Задача создаётся как дополнительное решение обычного приоритета на указанную дату;
цель — будущая, стадия «Идея», без направления. Эти defaults видны в preview.

## Контракт безопасности

- Вход интерпретатора и выход внешнего/заменяемого адаптера проходят runtime validation.
- Разрешены ровно шесть известных типов; дополнительные поля и неизвестные операции отклоняются.
- Все даты в намерении — календарные ISO dates, рассчитанные от текущей даты приложения.
- Неясная дата или неподдерживаемая команда требует исправления, а не угадывания.
- Предпросмотр неизменяем; подтверждение связано с его revision. Редактирование и отмена
  инвалидируют revision и поздние async ответы. Двойной клик исполняет команду один раз.
- После начала записи отмена не обещает откат. На время выполнения новая команда не принимается.
- При исключении записи автоматического retry нет: результат мог сохраниться до сбоя ответа.
- Интерпретатор не определяет, является ли операция изменяющей: политика задана в коде.
- Реестр проверяет доступность операции и предметные ограничения до preview и повторно при
  выполнении: существующий CreateGoal не принимает deadline, поэтому такой срок отклоняется,
  а не отбрасывается.
- CreateDecisionForDate умеет переносить создание с завершённого сегодня на завтра. Voice binding
  передаёт requireExactDate: завершённый день отклоняется без переноса, в том числе если состояние
  дня изменилось между preview и confirm. Прежние вызовы без флага сохраняют своё поведение.
- LifeOS не сохраняет аудио, историю распознанных команд или неподтверждённые preview.
- Диктовка в обычное поле остаётся диктовкой и никогда не вызывает командный интерпретатор.

## Дизайн-контракт

- FEATURE: новый пользовательский сценарий, глобальная палитра команд.
- USER GOAL: произнести действие, проверить содержание, явно подтвердить изменение.
- EXISTING LOGIC: текущие application-команды и navigation callbacks.
- PAGE/COMPONENT ARCHETYPE: палитра по правилу №36, стандартная форма подтверждения №18.
- SECTION COLOR: нейтральный графит, gold для primary; success green, error red.
- ATMOSPHERE: тёмное стекло временного слоя, без самостоятельного фонового изображения.
- MAIN VISUAL CENTER: распознанное действие и редактируемый preview.
- COMPONENTS TO REUSE: Voice Input, AppIcon, VoiceField, общие стили полей и кнопок.
- MOBILE BEHAVIOR: один вертикальный поток, широкая форма, touch zones минимум 44 px.
- APPROVED REFERENCE: отдельного визуального approval нет; используется существующий архетип
  палитры и предоставленная пользователем схема подтверждения, без нового крупного экрана.
- STATES: пустой ввод с примерами, распознавание/разбор, preview, выполнение, ошибка, success.
- TEST SCOPE: parser/schema/controller, интеграция реальных команд, UI lifecycle,
  desktop/mobile E2E, keyboard/focus и console. Полный E2E нужен при подключении к shell/navigation.

## Модули

`src/application/voice-commands/`: схема, validator, interpreter, registry, controller.
`src/app/composition/createVoiceCommandController.ts` связывает executor с существующими операциями;
`src/app/VoiceCommands.tsx` и `src/presentation/voice-commands/VoiceCommandPalette.tsx` подключают
палитру к shell. Presentation отображает controller и использует текущий `useVoiceInput` /
`VoiceInputCoordinator`. Никакого второго SpeechRecognition provider нет.
Прямой доступ executor к IndexedDB/Supabase запрещён.

Глобальная кнопка «Голосовые команды» находится в боковой навигации на desktop; на mobile
это золотой микрофон справа в существующей шапке. Точка входа не меняет рабочую высоту экранов.
Палитра отображается через portal в нативном modal dialog и сохраняет доступность при изменении
ширины экрана. Открытие окна не включает микрофон. Кнопка микрофона явно запускает
общий Voice Input, повторное нажатие завершает запись. Итоговая фраза автоматически разбирается.
Ручное исправление текста отменяет предыдущий preview; «Разобрать команду» получает новый.
Нативный modal dialog удерживает фокус, Escape/«Отмена» отменяет запись и поздние ответы;
во время выполнения закрытие заблокировано. Результат содержит «Открыть задачу/цель».
Обновление существующих date/route queries сохраняет смонтированные формы и их черновики.

Навигация: Сегодня, цели, дневник (существующая «История»), проекты, распорядок, прогулки,
управление, сферы, аналитика, настройки («Ещё»), задачи («Решения»).

## Пользовательский сценарий

Любой основной экран → «Голосовые команды» в левой панели (на телефоне — микрофон справа в шапке) → микрофон в палитре →
«Добавь задачу купить продукты завтра» → дождаться завершения распознавания или нажать микрофон
повторно → увидеть текст, «Создать задачу?», название и точную дату → «Создать» →
«Задача создана» → «Открыть задачу» или «Закрыть».

Для цели: «Создай цель выучить английский» → будущая цель, идея, без направления → подтвердить.
Для навигации: «Открой дневник» / «Перейди к целям» → переход сразу, компактный результат.
Заметки, свободная запись дневника, текстовый поиск и точный срок цели — будущие возможности.

## Проверка

Targeted tests → test:fast для общего application-контракта → npm run verify.
После UI/navigation интеграции: npm run test:e2e и desktop/mobile visual QA по правилу №38.
Предсуществующий dirty worktree не является частью этого патча.

Первоначальный внутренний срез проверял 41 случай parser/schema/controller. Сам по себе он
не подтверждал фактическую запись данных или работу команд в приложении.
Русский разборщик поддерживает перечисленные формы команд, сегодня/завтра/послезавтра, ISO date,
DD.MM.YYYY, число или порядковое числительное с русским месяцем. При отсутствии года используется
текущий год; перенос на следующий год не угадывается. Дни недели, время и неясные комбинации
дат требуют уточнения. Суммы остаются в названии цели без догадки о валюте и текущем прогрессе.
