# Визуальная ясность LifeOS

Дата: 30.09.2026. Статус: переработанный пилот утверждён пользователем; реализация проверена,
итоговый экран ожидает визуальной оценки пользователя. [Результаты проверки](../../architecture/2026-09-30-visual-clarity-verification.md).
[План реализации](../../superpowers/plans/2026-09-30-visual-clarity.md).
[Пары «до/после» и browser baseline](../references/2026-09-30-visual-clarity/README.md).

## Одно обновление

«Кузов, салон и отделка» — единая визуальная иерархия LifeOS. На каждом экране сразу виден
главный объект, рабочие списки остаются компактными, вторичные сведения не спорят с содержимым,
а поля, панели и состояния выглядят частью одного приложения.

Пользователь запросил предложение одного мощного визуального обновления и план. Рабочее
предположение: развиваем утверждённое направление «Единая рабочая поверхность» от 25.09.2026.
Графитовая база, jade для основного действия/выбора, золото для приоритета и отдельные success/error
уже существуют. Их повторное внедрение и новая система анимаций не являются результатом этой задачи.

## Выбор подхода

| Подход                                        | Эффект и цена                                                                                                                   |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Визуальная ясность — выбран для плана**     | Заметнее главное, спокойнее вторичное, последовательнее детали; сохраняет архетипы и выборочно меняет порядок двух блоков Today |
| Усилить фактуры, тени и декоративный свет     | Больше декоративной выразительности, но слабее влияние на читаемость и выше риск перегруза                                      |
| Полностью перестроить композиции всех страниц | Большой визуальный эффект, но смешивает оформление с новым UX и требует отдельного проектирования сценариев                     |

## Источник и наблюдения

Авторитетен активный `D:/LifeOS-App` вместе с предсуществующими изменениями надёжного выполнения
и панели действия. Прочитаны `LifeOS_DESIGN_RULES_v1.md`, `docs/codex/UI_RULES.md` и действующий
[Premium-контракт](2026-09-24-premium-all-screens.md). Просмотрен
[утверждённый визуальный язык](../references/2026-09-25-premium/approved-direction.png);
это reference направления, а не снимок текущего приложения.

Свежий browser baseline и пилот получены после планирования через локальный Chrome/Playwright на
1440×900 и 390×844. Встроенный browser tool завершился ошибкой `failed to write kernel assets …
os error 3`. На снимках и в computed styles подтверждены различия типографики/поверхностей; в
мобильном дневнике видна тесная вертикальная композиция. На просмотренных маршрутах нет
page/console errors и горизонтального переполнения. Подробности — в reference выше. До пилота
ниже были подтверждены только наблюдения по коду.

- Общий H1 в `planner-premium.css` — 28–38 px, Today — 32–44 px, Diary/Memory — 32–48 px,
  панель действия — 27.2–36.8 px. Разница должна определяться ролью заголовка.
- `diary/diary.css` использует отсутствующий в `tokens.css` `--space-5`;
  `planner-action-panel.css` — отсутствующий `--radius-lg`. Canonical names уже есть:
  `--space-6` (24 px), `--radius-large` (16 px).
- Общие карточки, каталоги и Diary/Memory имеют разные радиусы и тени;
  часть empty/error цветов задана напрямую при наличии семантических токенов.
- Общие правила распределены между `tokens.css`, `planner-v2.css`, `planner-master.css`,
  `planner-premium.css` и feature CSS. Diary/Memory и дочерние CSS могут влиять на результат
  после Premium: фактический каскад требуется проверить в браузере.
- Motion, reduced motion, `PlannerSheet`, `PlannerDisclosureCard`, `AppIcon`, Voice Input,
  primary/segments/form styles уже реализованы. Большая новая библиотека компонентов не нужна.

## Дизайн-контракт

```text
FEATURE → визуальное обновление существующих страниц и shared UI
USER GOAL → быстро отличать главное, вторичное, доступное действие и состояние
EXISTING LOGIC → нынешние application-команды, read models, формы и навигация
PAGE/COMPONENT ARCHETYPE → Today: центр управления; каталог; detail/sheet; запись; настройки
SECTION COLOR → действующий graphite/jade; gold priority; отдельные success/error
ATMOSPHERIC MOTIF → спокойная матовая рабочая поверхность текущего приложения
MAIN VISUAL CENTER → текущий план и действия; фокус месяца и сценарий вторичны
COMPONENTS TO REUSE → PlannerSheet, PlannerDisclosureCard, AppIcon, VoiceTextControl,
  существующие .planner-page-heading / .planner-primary / .planner-segments / .planner-form
MOBILE BEHAVIOR → план и первое действие перед обзором месяца; текущая навигация;
  controls ≥44 px; читаемые подписи; внутренний scroll sheet; safe-area;
  без незапланированного horizontal overflow
APPROVED REFERENCE → общая тема YES; переработанный пилот YES для реализации
TEST SCOPE → computed styles и визуальное сравнение, shared render при JSX-правках,
  scoped desktop/mobile flows и один актуальный verify
```

Классификация: значимое визуальное изменение существующих страниц и UI-компонентов, без новой
бизнес-функции. Пилотное утверждение требуется для предлагаемой новой общей визуальной иерархии;
старое утверждение палитры не считается утверждением ещё не показанного результата.

## Что пользователь увидит

1. **Ясный центр экрана.** На Today план и первое действие видны сразу. Фокус месяца находится в
   обзорной колонке desktop и после плана mobile; сценарий идёт после действий. В панели центр —
   действие и операция над ним, в дневнике — запись.
2. **Предсказуемый ритм.** Заголовок, toolbar, содержимое и раскрытые подробности разделены
   одинаковыми интервалами по роли. Длинные списки не превращаются в стопку тяжёлых карточек.
3. **Понятная глубина.** Фон, рабочая поверхность и overlay различимы. Вложенные блоки не получают
   автоматически ещё одну рамку и тень. Граница/акцент показывают состояние или группировку.
4. **Согласованная отделка.** Размеры текста, радиусы, иконки, поля, кнопки и status feedback
   используют один набор ролей. Выбор и выполнение различимы также по подписи/форме/иконке.
5. **Та же ясность на телефоне.** Первое действие попадает в экран 390×844 без прокрутки в
   контрольном состоянии. При переносе строк и открытии клавиатуры действия, подписи и сообщения
   сохраняют читаемость. Существующие способы управления остаются доступны.

## Предлагаемая шкала для пилота

Это значения утверждённого пилота после сравнения с browser baseline. Новые значения нельзя
выбирать независимо в каждом разделе.

| Роль                         | Предложение                                                            | Владелец                                                                                      |
| ---------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Page title                   | `clamp(1.75rem, 3vw, 2.375rem)`, line-height 1.2, weight 650           | Новый `--planner-type-title` в `tokens.css`                                                   |
| Today focus title            | `clamp(1.875rem, 2.8vw, 2.25rem)`, line-height 1.2                     | `--planner-type-focus-title`; заголовок Today                                                 |
| Detail/panel title           | `clamp(1.75rem, 2.4vw, 2.125rem)`, line-height 1.2, weight 650         | `--planner-type-detail-title`; ограниченная ширина панели                                     |
| Today plan title             | 28 px desktop / 24 px mobile                                           | главный заголовок рабочей поверхности                                                         |
| Section / item / body / meta | 20 / 16 / 15 / 13 px; body line-height 1.55                            | `--planner-type-section`, `--planner-type-item`, `--planner-type-body`, `--planner-type-meta` |
| Длинная запись               | 16 px, line-height 1.65                                                | `--planner-type-reading`, только редактор/текст записи                                        |
| Интервалы                    | 8 / 12 / 16 / 24 / 32 / 48 px по смысловой вложенности                 | Существующие `--space-2/3/4/6/8/12`                                                           |
| Радиусы                      | 8 px controls, 14 px обычная рабочая группа, 16 px крупная поверхность | Существующие `--radius-small/medium/large`; геометрия full-height sheet сохраняется           |
| Поверхности                  | canvas → surface-1 → surface-2; selected из текущего surface-selected  | Существующие palette tokens; цветовые значения сохраняются                                    |
| Тени                         | рабочие группы без тени либо shadow-glass; overlay — shadow-deep       | Существующие shadow tokens, без добавления постоянного glow                                   |
| Touch / motion               | 44/48 px; существующие duration/easing и reduced motion                | Текущие control/motion tokens                                                                 |

Использования несуществующего `--space-5` в Diary переводятся на `--space-6` (24 px),
`--radius-lg` в подтверждении панели — на `--radius-large` (16 px). Новых неоднозначных aliases
с этими именами не добавлять. Общая типографика использует новые role tokens; существующие
`--planner-font-body/meta` остаются совместимыми aliases там, где они нужны другим consumers.

## Охват одного выпуска

- Пилот: Today/завтра с планом первым, фокусом месяца в aside, сценарием после действий и новой
  панелью действия. Два переноса требуют JSX/DOM-правки, чтобы порядок Tab совпадал с изображением.
- Общие рабочие экраны: Actions, Goals, их detail/forms и overlays, Quick Access.
- Текстовые экраны: Diary и Memory; сохраняются собственные композиции и поведение редакторов.
- Проверка наследования общего стиля: сферы/направления, календарь/канбан/дерево, Sleep, Account.
  Локальные feature CSS меняются только для расхождений с утверждёнными ролями.

Native Android alarm, новая палитра/тема, новые шрифтовые зависимости, массовое перемещение controls,
новые навигация/параметры плотности/анимационная система и переработка бизнес-логики в этот выпуск
не входят. Данные, даты, статусы, цветовые значения предметных сущностей и фото не перекрашиваются
по декоративным правилам. В пилоте порядок DOM меняется только для двух блоков, чьё прежнее место
скрывает действие с первого экрана; CSS `order` не использовать, чтобы не расходились visual/Tab.

## Состояния и приёмка

- Loading сохраняет геометрию, только там, где loading уже существует. Fake progress не добавляется.
- Empty/no results/completed используют существующий смысл и доступные действия.
- Error/retry и success видны в активной поверхности; aria/live regions и тексты сохраняются.
- Focus имеет отдельный видимый контур, disabled читается, hover не является единственным способом
  найти управление, selected/success/priority отличаются без цвета.
- Длинные названия, отсутствие данных, много строк, expanded disclosures и вложенные dialogs
  сохраняют читаемость и доступность команд.
- В контрольном состоянии одно длинное действие начинается на 474 px desktop / 611 px mobile;
  текущий baseline — 778 / 977 px. В дополнительных состояниях не требовать универсальной
  видимости без прокрутки, но проверять приоритет плана и доступность фокуса/сценария.
- Сравнение before/after в одинаковых viewport и состоянии: 1440×900, 390×844; дополнительно
  1600×900, 1280×720, 360×800, 320 px и переход 730–760 px по responsive-риску.
- Contrast: обычный текст ≥4.5:1, крупный текст и значимые границы/focus ≥3:1; проверять
  реальные пары computed colors. Disabled оценивается отдельно по читаемости.
- Пройти применимые пункты Правила №38 с актуальным jade-исключением. Скриншот сам по себе не
  доказывает соответствие: нужен просмотр рядом с baseline/approved pilot.

Утверждение пилота разрешает реализацию; визуальная готовность продукта требует проверки
фактических экранов на desktop/mobile и итогового review.
