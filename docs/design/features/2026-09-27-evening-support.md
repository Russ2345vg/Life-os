# Вечер: подготовка и завершение дня

Статус: дизайн согласован пользователем после удаления режимов «Минимум / Полный»;
реализация в активном worktree, итоговые проверки фиксируются ниже.

## Цель и границы

Обновление включает анализ истории и спокойное завершение дня. По уточнению пользователя
переключатели короткого/полного режима исключены: остаётся один существующий чек-лист.
Обновляем существующий `#/v2/sleep`, сохраняя планировщик и sleep schedule источниками
состояния. Не подключаем старый evening-cycle runtime.

## Что найдено

- `SleepPreparationPage.tsx` уже поддерживает группы, каталог, отметки, завершение с пропусками,
  будильник и историю. История показывает три ночи и преимущественно результаты подъёма.
- `NightCycle` хранит снимок списка, статусы пунктов, плановое время сна и время завершения
  подготовки. Фактическое засыпание, причина пропуска и длительность каждого пункта неизвестны.
- Browser baseline: `http://127.0.0.1:5181/#/v2/sleep`, экран первоначальной настройки,
  desktop/mobile снимки в текущей сессии. В этом browser origin личная история отсутствует.
  Настройки и пользовательские данные для макета не изменялись.
- Каскад: global/tokens → planner-v2 → planner-master → planner-premium. Вычисленный шрифт
  Inter/system sans-serif; графитовая база, jade основного действия.

Атмосферный мотив: спокойная текущая рабочая поверхность без новой декоративной сцены.

## 1. Последние вечера

Период — последние 14 календарных вечеров до текущего cycleDate, исключая текущую ночь.
Показываем отдельно количество сохранённых ночей и количество завершённых подготовок.
Отсутствующая запись не означает пропуск.

Для каждого пункта считаем `DONE / число завершённых ночей, где пункт присутствовал` по
стабильному ID. `SKIPPED_TODAY` исключается из рекомендации о конкретном пункте: отказ от
всего вечера не доказывает, что мешает именно он. Незавершённые ночи показываются отдельно,
а не превращаются в явные пропуски. Переименования не переписывают исторические снимки.

После минимум пяти подходящих наблюдений показываем до трёх пунктов, которые чаще оставались
невыполненными, с числителем/знаменателем. При равенстве используем порядок текущего каталога.
Предложение — «Пересмотреть список», без автоматического отключения пунктов и без утверждения
причинной связи. Для меньшей выборки — «Пока мало данных для устойчивого вывода».

Время завершения сравниваем с `plannedSleepAt` только для ALL_DONE/WITH_SKIPS. Подпись:
«Подготовка завершена до времени сна». Не называем это фактическим отходом ко сну.

## 2. «Закрыть день»

Необязательный inline блок под чек-листом, свёрнутый по умолчанию.

- Незавершённые действия сегодняшнего плана из `GetPlannerToday`: перенести конкретное
  действие на завтра через `planPlannerAction`, либо оставить без изменений. Просроченные
  действия и in-progress не переносятся автоматически. Обрабатываем stale status и ошибки.
- «Что осталось в голове?» — `VoiceTextArea`; сохранить через `plannerInbox.capture`.
  Ошибка сохраняет введённый текст, повторное нажатие блокируется на время записи.
- Главное на завтра выбирается из существующих действий через `SetLifeActionPlan` с
  `isNext=true`; существующее главное заменяется по действующему application-контракту.
  Показываем текущее главное до замены. Новый параллельный список приоритетов не создаём.

Это независимые действия с явным подтверждением каждой записи. Нет общей транзакции между
inbox, planner и sleep; успешные операции не откатываются из-за ошибки следующей. Закрыть
блок можно без выполнения всех действий. Несохранённый текст защищает quick-access guard.

Дата закрываемого дня — `cycleDate` текущей ночи; после полуночи это всё ещё предыдущий
вечер до установленного времени подъёма. В заголовках показываем обе конкретные даты.
Завтра вычисляется календарным `addDays(cycleDate, 1)`, а не прибавлением 24 часов.

## Состояния и проверка

Loading: существующая загрузка; empty: нет истории/действий — отдельные объяснения;
error: inline retry без потери ввода; success: подтверждение результата и обновление источника;
busy: предотвращение дубликатов. Клавиатура, focus, reduced motion, 390px и desktop обязательны.

Используем существующие ночные снимки и команды планировщика. Новые режимы, поля настроек
и расширение формата хранения для этого обновления не требуются.

Targeted tests: расчёт выборки и знаменателей, UI ошибки, inbox и перенос/главное завтра. Затем один
`npm run verify` и scoped `current.sleep-preparation.spec.ts` на desktop/mobile. Полный E2E
не нужен при локальном обновлении sleep UI и переиспользовании planner-команд.

Макет: [preview.html](../references/2026-09-27-evening-support/preview.html). Все числа и дела в
нём демонстрационные; он не читает и не записывает IndexedDB.

## Реализация и проверка

- История рассчитывается `eveningHistoryModel.ts` из существующих ночных снимков, без записи
  статистики и изменения формата хранения. Активный вечер исключён; для вывода о пункте нужно
  минимум пять завершённых наблюдений именно этого пункта.
- `EveningDayClosure.tsx` использует существующие planner-команды, inbox и VoiceTextArea.
  Обновляет дела после Quick Access и изменения sync status. Дата плана учитывает переход
  через полночь; краткий заголовок входящей мысли ограничен 200 символами, полный длинный
  текст сохраняется в note.
- Targeted модель и существующий render: 8 тестов прошли.
- Scoped browser: 6 тестов прошли на desktop/mobile — inbox с ошибкой и retry, перенос и
  замена главного с reload, переход к плану после полуночи. Существующие четыре проверки
  каталога сна также прошли. Снимки результата визуально изучены.
- Общий `npm run verify` прошёл полностью: typecheck, lint, 1538 unit/integration, 55 infra,
  alpha, build, format и Git hygiene. По разрешению пользователя устранено форматирование
  `CompletionResult.tsx` и `current.completion-summary.spec.ts`; поведение этих файлов не менялось.
  Полный E2E не требуется для scope, предыдущие scoped browser-проверки остаются актуальны.
- Визуальный review desktop 1440px / mobile 390px: один главный checklist, свёрнутый по
  умолчанию closure, одна mobile колонка, существующие graphite/jade controls, voice input,
  empty/error/retry/success состояния. Review кода после исправлений не имеет блокирующих
  замечаний. Реальная пользовательская история в доступном browser origin отсутствует;
  статистика проверена на тестовых ночных снимках.
