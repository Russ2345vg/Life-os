# Обновления Windows без флешки

Цель: после выпуска версии на ноутбуке установленный LifeOS на ПК сам находит обновление
через интернет и устанавливает его по кнопке. Пользователь согласовал этот сценарий.

## Дизайн-контракт

- Классификация: новый пользовательский сценарий в общей оболочке.
- Раздел: общая оболочка; текущая страница остаётся доступной.
- Акцент: общий theme accent существующих кнопок; без отдельной палитры обновлений.
- Атмосфера: существующая оболочка, дополнительный фон не создаётся.
- Архетип: компактный inline banner по правилу №30, над содержимым страницы.
- Визуальный центр блока: новая версия и единственная основная кнопка «Обновить».
- Повторное использование: planner-primary, стандартная secondary button, общие tokens.
- Узкое окно: текст и кнопки переносятся, touch targets не меньше 44 px.
- Отдельный approved reference не требуется для стандартного уведомления; существующая
  оболочка сохраняется. Статус APPROVED новому компоненту не присваивается.
- Состояния: проверка и отсутствие версии скрыты; available предлагает установку/отложить;
  installing сообщает прогресс и блокирует повтор; error предлагает повтор/отложить;
  installed сообщает о передаче управления установщику.

## Контракт поведения

ApplicationUpdateService — единственный источник состояния обновления в текущем запуске.
Presentation вызывает application-команды; Tauri находится только в infrastructure.
App собирает service и gateway, запускает проверку один раз, включая React StrictMode.
Браузер и Android не вызывают Windows updater. Существующий Android updater не меняется.

Проверяется опубликованный latest.json. Подпись пакета проверяет Tauri по существующему ключу.
Смена ключа, app identifier, IndexedDB и пользовательских данных не входит в задачу.
Установка начинается только по нажатию; перед нажатием пользователь видит предупреждение
о сохранении открытых форм и перезапуске приложения. «Позже» скрывает баннер до следующего
запуска. Неудачная проверка не блокирует локальную работу; повтор доступен в баннере.

## Выпуск

Новая версия выпускается явно после проверки изменений. Сохранение файла на ноутбуке
не публикует незавершённый код. Windows готовится отдельно от Android; публикуется уже
подготовленный набор, сверенный по SHA-256. Предыдущий Android manifest переносится в новый
latest release со старым неизменяемым APK URL, если он присутствует в текущем канале.

## План и проверки

1. Application state machine и Windows adapter: startup, отсутствие версии, offline,
   повтор установки, защита от двойного запуска, освобождение native resource.
2. Баннер и подключение к shell; render checks и browser desktop/mobile сценарии.
3. Постоянный endpoint, точный выбор версии installer, Windows prepare/publish workflow.
4. Targeted tests, release script tests, verify и полный E2E: затронут startup/browser flow.
5. Подписанная bootstrap-сборка; публикация и установка на другом ПК проверяются отдельно.

Ручное подтверждение обновления между двумя установленными Windows-версиями на ПК остаётся
необходимым: browser tests используют имитацию native gateway и не запускают NSIS.
