# Отмена переноса даты

Новая функция существующих страниц планирования. После успешного переноса
даты доступна отмена последнего переноса. Уведомление содержит название действия,
кнопки «Отменить» и «Закрыть»; сохраняется при переходах между страницами, до
закрытия, нового переноса или перезагрузки. Автоматическое исчезновение не мешает
пользователю клавиатуры. Новых режимов и настроек нет.

- Цель: быстро исправить случайный перенос.
- Источник состояния: LifeActionRepository и JournalUnitOfWork, без новой схемы.
- Архетип: компактное уведомление в существующей рабочей поверхности.
- Акцент: общий jade, графитовая поверхность; атмосферный мотив текущей оболочки.
- Визуальный центр: кнопка отмены рядом с названием изменённого действия.
- Компоненты: существующие кнопки, status/alert, shared tokens.
- Mobile: перенос строк, кнопки минимум 44px, без горизонтального скролла.
- Loading: кнопки блокируются на время отмены; empty: уведомление отсутствует.
- Error: возврат отклоняется при новой версии или занятом главном деле прежней даты.
- Success: прежняя дата восстановлена, списки обновляются.
- Approved reference: не требуется для стандартного уведомления.

Перенос даты делает действие обычным, сохраняя главное дело целевой даты.
Отмена возвращает прежнюю дату, флаг главного дела и исходные метаданные
повторения. Снимок формируется внутри команды из свежей сущности. Проверка версии
и конфликта главного дела выполняется атомарно; чужие действия не изменяются.
Выбор главного дела и создание действий остаются отдельными командами.

Проверки: targeted команды, IndexedDB конфликты и повторения, scoped browser
сценарии на desktop/mobile, verify. Полный E2E не нужен: общая схема хранения,
startup, routing и shell не меняются.
