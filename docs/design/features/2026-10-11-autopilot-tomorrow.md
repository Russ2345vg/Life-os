# Завтрашний день в автопилоте

Исправление ранее запрошенного пользователем сценария: опубликованная 1.0.45 передаёт отдельной странице автопилота только текущую дату. Application-сервис уже принимает будущую дату и сохраняет отдельные дневные черновики/расписания. Новый планировщик не нужен.

FEATURE → выбор дня существующей страницы «Распорядок → Автопилот дня».
USER GOAL → заранее собрать и проверить завтрашнее расписание с прежними предпочтениями, ритуалами и отдыхом.
EXISTING LOGIC → DayAutopilotService, dated draft, preview/apply guard, DayDate/addDays.
ARCHETYPE → текущая форма и timeline; общий переключатель planner-day-switch из Today.
SECTION COLOR → текущие graphite/jade tokens.
MAIN VISUAL CENTER → расписание выбранного дня; его дата видна над формой.
REUSE → native buttons с aria-pressed, shared heading/segments, текущие поля, loading/error/success.
MOBILE → переключатель и дата располагаются вертикально при узкой ширине; touch targets не меньше 44px.
REFERENCE → текущая страница 1.0.45 и существующий Today-переключатель; baseline desktop/mobile сохранён в ../artifacts/autopilot-tomorrow-qa/baseline/ относительно корня проекта. Стандартные controls по ясному запросу не требуют отдельного visual approval согласно AGENTS.md.
TEST SCOPE → route roundtrip и соседние component tests; scoped desktop/mobile E2E сохранения, reload, сброса preview и разделения черновиков; один verify из-за общего route type. Без полного browser suite.

## Поведение и минимальный план

1. В маршрут автопилота добавить тот же optional day=tomorrow, что в Today; неизвестный параметр остаётся сегодняшним днём. Reload сохраняет выбор, сегодняшний URL совместим.
2. Workspace вычисляет завтра календарным addDays от currentDate; не по текущему часу компьютера и не добавлением 24 часов.
3. Над формой видны «Сегодня / Завтра» и явная дата. Для завтра кнопка называется «Собрать план на завтра», для сегодня сохраняется прежнее имя.
4. Смена даты перемонтирует карточку: прежний preview не может примениться как план нового дня. Дневные пожелания/закрепления/время читаются из собственного черновика; общие предпочтения остаются общими. Future default — 09:00, редактируется пользователем.
5. Preview и apply продолжают использовать существующую дату/атомарность. Задачи других направлений не перемещаются просто от смены вкладки. Contextual assistant получает признак tomorrow, как на странице Today.

Без миграций, новых зависимостей, изменения алгоритма подбора или native-кода. Исправление готовится как устранение пропуска в ранее разрешённом общем выпуске для Windows и Android, версия 1.0.46.
