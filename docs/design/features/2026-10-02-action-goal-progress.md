# Прогресс количественной цели в строке действия

## Контракт

- **Разделы:** «Сегодня» и «Действия»; существующие архетипы центра дня и каталога.
- **Цель пользователя:** видеть сферу и направление действия, а также текущее значение связанной количественной цели без открытия карточки.
- **Источник данных:** `PlanningContext.progress` и связи `PlanningState.links`; для старых целей с `Goal.progress.type = metric` используется их сохранённое значение. Обычная связь действия с целью даёт контекст, явная связь вклада также делает цель видимой. Новое предметное состояние не создаётся.
- **Акцент и мотив:** текущая графитовая рабочая поверхность, jade для управления; числовая метрика вторична и нейтральна. Главный визуальный центр — название действия.
- **Компоненты:** существующие строки `PlannerToday` и `PlannerActionRow`, `ActionGoalProgress` как общий компактный read-only фрагмент.
- **Mobile:** метаданные переносятся под название и могут переносить длинные единицы и названия; горизонтальная прокрутка не появляется.
- **Состояния:** до загрузки контекста метрика отсутствует; при неполном синхронизированном расчёте вместо числа показана синхронизация; при ожидающем фактическом значении сохраняется известное число с пометкой; после обновления показывается новый результат.
- **Макет:** отдельный approved reference не требуется: строка полностью собирается из существующего паттерна.
- **Проверка:** targeted render test, scoped browser flow на desktop и mobile, визуальная проверка и правило №38.
