## Цель и границы

Утром быстро сохранить субъективную оценку ночи и самочувствия. Вечером видеть время начала подготовки по одному общему бюджету времени. Сохранённая длительность таймера относится только к растяжке; поминутной настройки остальных действий нет.

Функции существующей страницы `/#/v2/sleep`. Сохранить накопленные пункты 1–3, 6 и 8, историю ночей, пользовательские пункты, ручные времена и реальное подтверждение Android. Выпуск, установка, push и изменение версии не входят в этот этап; текущая версия 1.0.44.

## 1. Утренняя самооценка

В утреннем виде рядом с записью ночи блок «Как прошла ночь?» с двумя независимыми выборами:

- Качество сна: «Хорошо», «Средне», «Плохо».
- Самочувствие утром: «Бодр», «Нормально», «Устал».

Один tap сохраняет выбранную оценку для показанной даты подъёма. Вторую оценку можно оставить пустой. Выбор можно изменить; вторичное действие «Сбросить оценку» убирает обе оценки. Показаны сохранение, подтверждение сохранения и ошибка с повтором.

Оценка доступна и до ввода времени сна. Она не подставляет время подъёма, не подтверждает ночь, не создаёт фактическую длительность и не меняет статистику времени в постели. В истории у соответствующей даты видны текстовые оценки; если времён ещё нет, это явно указано. Это самооценка пользователя, без медицинских выводов и автоматического вывода из продолжительности ночи.

Дата следует существующему выбору записи, а не текущему календарному дню устройства. Будущую дату оценивать нельзя. Во время несохранённого редактирования времён оценки временно недоступны с пояснением: сначала сохранить времена или сбросить изменения. Это защищает ввод от перемонтирования формы. При смене режима и приходе sync черновик сохраняется.

## 2. Таймер только для растяжки

В настройках времени пользователь выбирает существующий пункт растяжки из своего списка и задаёт длительность, исходно 10 минут, диапазон 1–120 целых минут. Связь хранится по ID пункта: переименование не превращает растяжку в другое действие и не сбрасывает настройку.

В пошаговом режиме таймер показывается только у выбранной растяжки. Остальные шаги показывают действие, прогресс и переход дальше. Таймер подставляет сохранённые минуты, поддерживает старт, паузу, продолжение и сброс. Истечение не отмечает растяжку выполненной. Уход из режима сбрасывает текущий отсчёт; выбранная длительность сохраняется после перезапуска и синхронизируется.

Автоматически добавлять новый пункт растяжки или назначать любой похожий по названию пункт нельзя. Если связь не настроена, пользователь может выбрать пункт в настройках; если пункт удалён или отключён, нужно выбрать доступный пункт. Старые снимки ночей не переписываются.

## 3. Когда начинать подготовку

Одно поле «Общее время подготовки, включая растяжку», исходно 30 минут, диапазон 1–180 целых минут. Это плановая оценка пользователя, а не измеренная длительность. Отдельные времена для проветривания, воды, кровати и других действий не нужны.

Формула: `начало подготовки = плановый отбой − общее время подготовки`.

Пример: отбой 23:00, общая подготовка 30 минут → «Начать подготовку в 22:30». Таймер растяжки 10 минут входит в эти 30 минут и второй раз к ним не прибавляется. Настройка общей длительности должна быть не меньше настроенной растяжки, если пункт растяжки выбран.

В вечернем виде рядом со списком: время начала, плановый отбой и общая длительность; рядом «Настроить время». После времени начала незавершённый вечер предлагает начать подготовку. После завершения повторного призыва нет. При отбое после полуночи и переходе даты показывается правильная дата начала в часовом поясе расписания.

Источник отбоя — существующий `NightCycle.plannedSleepAt` вечернего сценария / `calculateNightWindow`, без нового независимого календаря. Арифметика выполняется с полными датами, а не вычитанием строк HH:MM. Утренний режим сохраняет приоритет записи ночи и самооценки.

Новые системные напоминания, изменение native AlarmManager и автоматическое изменение плана дня не входят в scope. Выбран пункт 5 с расчётом и отображением начала; интеграция самочувствия в автопилот из пункта 9 не выбрана.

## Владельцы данных и совместимость

- Необязательное `SleepObservation.morningFeedback`: `sleepQuality: GOOD | OK | POOR | null`, `energy: ENERGETIC | OK | TIRED | null`, `recordedAt: Date`. Хотя бы один выбор заполнен; сброс убирает поле. Application-команда сохраняет feedback в существующей очереди мутаций наблюдений. При отсутствии записи создаётся неподтверждённый draft с пустыми временами, исходным timezone и стабильным ID существующего observation-контракта. Confirm/revise, ручные отметки и alarm prefill сохраняют оценку.
- Необязательное `SleepScheduleState.preparationTiming`: `totalPreparationMinutes`, `stretchingItemId: string | null`, `stretchingMinutes`. Отдельные preferences в state, а не новые настройки native-будильника. Application-команда валидирует диапазоны, связь с каталогом и общий бюджет. Изменение preferences не меняет `SleepSettings.version/updatedAt` и не делает актуальный Android report устаревшим.
- Domain владеет проверками, преобразованием самооценки и расчётом начала. Application выполняет команды, читает расписание и сохраняет через существующие repository-порты. UI передаёт команды, не обращается к IndexedDB.
- Storage сохраняет optional fields с ISO датами. Старые записи читаются без новых полей. Повреждённые optional данные не блокируют основные записи и не превращаются в положительную оценку. Сохраняются record schema v1, database version и существующие sync payload types `sleep_observation` / `sleep_schedule`; новых stores, server endpoints и зависимостей нет.
- Не выводить самооценку в фактическую кривую сна. Confirmed night по-прежнему требует записанных и подтверждённых времён. История и редактирование старых дат остаются доступны.

## Проверки и метод

Одним исполнителем, затем один итоговый независимый read-only review, как выбран ранее. Сначала written-spec review пользователя, затем план реализации; код — после согласования плана. Сохранить существующую dirty ветку и все предыдущие изменения.

TDD: независимые и частичные оценки, будущая дата, сброс, сохранение оценки через все команды времени, отсутствие влияния на confirmed sleep и статистику; валидность и диапазоны timing, стабильная связь растяжки, общий бюджет без двойного сложения, midnight/timezone, native ack не меняется от timing; old record/malformed optional, put failure/retry, production capture/apply/reopen sync.

UI/scoped sleep E2E: оценка без времён, обновление и история/reload, защита dirty-ввода, таймер только выбранной растяжки и сохранённые минуты, изменение общего бюджета и начало после полуночи, отсутствие преждевременного DONE; desktop/mobile, keyboard/focus, reduced motion, console/overflow, final screenshots и сравнение с baseline.

Проверки дельты → `npm run test:fast` → один итоговый `npm run verify`. Полный E2E без селекторов не нужен: scope ограничен sleep flow. Повтор gate только после влияющей правки или диагностированного failure. Native сборка и физический телефон относятся к будущему общему выпуску.
