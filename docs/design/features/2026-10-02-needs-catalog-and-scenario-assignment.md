# Каталог потребностей и сценарий при создании действия

## Цель

При создании направления, цели или действия пользователь выбирает потребность из готового набора либо добавляет свою. Открыв потребность, он видит связанные направления, цели и действия, включая завершённые. При создании действия из цели можно сразу выбрать существующий сценарий задач.

## Контракт данных

- Поля `need` в направлении, цели, действии и правиле повторения остаются источником истины. Их формат и синхронизация не меняются.
- Каталог — проекция из стартового набора и сохранённых собственных формулировок. Своя потребность добавляется при назначении объекту и после сохранения появляется в каталоге. Неиспользованный черновик не создаёт отдельную запись.
- Сопоставление игнорирует регистр и крайние пробелы; текст в существующих объектах не переписывается. Связи с целями и действиями учитывают действующее наследование потребности от родителя.
- Сценарии загружаются через `PlannerScenarios.list` для выбранной даты; заполненные сценарии недоступны. Сохранение действия выполняется существующей командой, затем `addAction`. Если второй шаг не удался, интерфейс сообщает, что действие уже сохранено, и предлагает добавить его в сценарий из карточки, исключая повторное создание.

## Интерфейс

Каталог размещается рядом с направлениями и целями, использует текущую графитовую оболочку и общий акцент. Центр страницы — выбранная потребность; ниже компактные группы направлений, целей и действий со статусами и ссылками. На мобильном группы идут одной колонкой. Формы используют стандартный `select`; пункт «Добавить свою…» раскрывает текстовое поле. Пустой выбор сохраняет действующее наследование.

Состояния: стартовый набор виден без пользовательских данных; во время загрузки связей показывается сообщение; при ошибке — повторная загрузка; после сохранения — существующее уведомление; если у потребности нет связей, показано объяснение. Для сценария предусмотрены загрузка, отсутствие доступных сценариев, сохранение и частичный успех.

## Проверка

Модульные тесты проекции потребностей, наследования, дедупликации и частичного успеха привязки сценария. Адресные browser-сценарии для выбора готовой/своей потребности, просмотра связей, выбора сценария при создании действия, а также desktop/mobile визуальная и keyboard-проверка. Затем `npm run verify`; полный E2E не требуется, поскольку общая схема хранения и маршрутизация других разделов не меняются.
