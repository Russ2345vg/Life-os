# LifeOS V2 — Канбан, Календарь, Древо

## Контракт

Новые представления существующих разделов «Цели» и «Действия». Goal и LifeAction
остаются единственными предметными записями; представления не имеют persistence.
Источник требований — прямой запрос пользователя, функциональная спецификация v1.1,
каталог макетов V2 (страницы 4–6). Технический план первого цикла — исторический
контекст; его запрет начинать последующие представления заменён текущим запросом.

Визуальный источник: `05LifeOS_V2_Каталог_макетов.pdf`, предоставленный пользователем.
Используется утверждённое направление V2: почти чёрный фон, белый/серый текст,
текущий зелёный theme accent, без атмосферного изображения, стекла и золота V1.
Главный центр — содержимое выбранного представления. Результат реализации ещё не
имеет отдельного пользовательского visual approval.

## Представления

- Канбан целей группирует Goal по существующему status: future, active, paused,
  achieved, archived. Фокус — отметка, не дополнительная копия и не новый статус.
  Смена состояния через UpdateGoal с expectedVersion; achieved согласуется со stage.
  Архив доступен для чтения; управление архивом остаётся в полной карточке.
- Канбан действий: открытые без даты, открытые с датой, выполненные, отменённые.
  Дата и completion управляются существующими SetLifeActionPlan/CompleteLifeAction.
  Меню/формы вместо DnD, без Start/Session/Timer и без операции reopen.
- Календарь: месяц и выбранный день, LifeAction.plannedDate. У Goal нет точной даты;
  все Goal доступны в «Без даты». Horizon не преобразуется в дедлайн.
  Перенос completed меняет только план, не факт результата или Journal completion.
- Древо: Sphere → Direction → Goal → LifeAction, включая пустых родителей и группы
  «Без сферы», «Без направления», «Без цели». Существующие прямые sphereId у Goal
  сохраняются. Раскрытие не вызывает запись. Связи через UpdateGoal/SetLifeActionGoal.

## Архитектура и повторное использование

PlannerLibraryWorkspace загружает наборы через текущие query/services, подписывается
на sync invalidation и выполняет команды. Чистые presentation-проекции индексируют
наборы за линейный проход; запросов на карточку нет. Переиспользуются PlannerActionRow,
PlannerGoalProgress, тексты статусов/важности, поля дат/связей, V2 tokens и shell.
Ошибки не применяют оптимистических предметных изменений. expectedVersion защищает Goal.
Изменения LifeAction сохраняются через JournalUnitOfWork с проверкой версии.

## Responsive и состояния

Desktop: полноценные колонки; календарь с панелью дня; вложенные списки дерева.
Mobile: горизонтальная лента колонок с snap; компактные дни с количеством элементов,
детали ниже; ограниченный отступ дерева и ленивое раскрытие потомков.
Переключатель представления компактный, нижняя навигация сохраняет четыре пункта.
Loading, empty с понятным действием, error/retry, busy, completion, длинные названия,
незаданные дата/связи обязательны. Большие группы показываются порциями.

## Проверка и границы

Целевые domain/application, projection, render и IndexedDB integration tests;
browser QA desktop/mobile, keyboard/focus и console; один итоговый `npm run verify`.
Полный E2E запрещён прямым запросом. Не меняются sync protocol, crypto, schema,
legacy V1, зависимости. Не входят новые сроки Goal, календарные сущности, DnD,
неделя, ритуалы, планы периодов, аналитика. Commit включает только этот блок, без push.
