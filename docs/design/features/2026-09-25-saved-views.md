# Сохранённые представления

**Дата:** 2026-09-25

**Статус:** дизайн-контракт определён; письменная спецификация ожидает review

**Поведенческая спецификация:** [LifeOS saved views](../../superpowers/specs/2026-09-25-saved-views-design.md)

## Дизайн-контракт

```text
FEATURE → сохранённые и закреплённые представления списков целей и действий
USER GOAL → возвращаться к полезным наборам фильтров без повторной настройки
EXISTING LOGIC → фильтры PlannerGoalList/PlannerActionList, semantic periods, Quick Access
PAGE/COMPONENT ARCHETYPE → текущий catalog list с selector, меню и стандартным диалогом
SECTION COLOR → jade для выбора/сохранения; red только для удаления и ошибки
ATMOSPHERIC MOTIF → компактные персональные настройки внутри графитовой поверхности
MAIN VISUAL CENTER → существующий список результатов; имя представления даёт контекст
COMPONENTS TO REUSE → filter panels, PlannerWorkspace, EntityContextMenu, dialog, status notice, Quick Access
MOBILE BEHAVIOR → компактный selector; управление в меню; summary переносится ниже
APPROVED REFERENCE → YES; «Единая рабочая поверхность» и текущие списки
TEST SCOPE → domain/application, persistence/sync, route/history, UI, Quick Access, desktop/mobile E2E
```

## Изменение существующих страниц

В заголовке списков целей и действий появляется selector представлений. Первый пункт —
`Без сохранённого представления`, затем закреплённые и остальные представления. Текущий список
результатов сохраняет композицию и остаётся главным визуальным центром.

Панель фильтров получает действие `Сохранить представление`. Диалог использует существующие поля,
checkbox, кнопки и validation message. После изменения открытого представления заголовок показывает
`Есть несохранённые изменения` и действия `Сохранить изменения`, `Сохранить как новое`, `Сбросить`.

Меню представления содержит переименование, копирование, pin/unpin, выбор default и удаление.
Удаление использует компактный confirmation dialog и прямо сообщает, что цели и действия останутся.

## Quick Access

Закреплённые представления образуют группу `Представления` перед обычными результатами и видны при
пустом запросе. Строка содержит имя и нейтральный контекст `Цели` или `Действия`. Открытие только
переходит на маршрут с `savedViewId`; мутаций предметных данных нет.

## Состояния

- loading — сохранённое определение загружается до показа результатов;
- empty — в selector нет пользовательских представлений;
- saving — dialog блокирует повторный submit;
- validation error — конфликт имени или неверное определение остаётся в dialog;
- unavailable — удалённый, неизвестный или несовместимый view предлагает обычный список;
- unresolved reference — отсутствующий фильтр назван и доступен для редактирования;
- success — save/update/rename/pin подтверждаются через `role=status`.

## Responsive и доступность

На мобильной ширине selector занимает одну компактную строку, длинное имя визуально сокращается,
но остаётся полным в accessible name. Управление находится в меню, summary переносится ниже.
Selector, pin/default и management actions имеют точные accessible names; диалоги удерживают и
возвращают фокус. Unsaved state и ошибки выражены текстом, а не только цветом.

Отдельный уникальный макет не требуется: функция расширяет утверждённые catalog/list и Quick Access
паттерны. Перед handoff обязательны desktop/mobile browser QA и сравнение с текущей оболочкой.
