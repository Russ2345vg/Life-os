# Полный минималистичный редизайн LifeOS

Дата: 9 сентября 2026 года. Статус: **DRAFT — выбор композиции**.

## Результат и границы

Цель пользователя — получить минималистичный, аккуратный и красивый LifeOS без перегруженности.
Текущий заказ включает план внедрения и макеты всех существующих страниц, форм и вариантов
заполнения. Изменение приложения, перенос дизайна в runtime и публикация в этот этап не входят.

В этой редакции готовы реестр покрытия, порядок проектирования и три стартовых концепта
«Сегодня». Это ещё не полный комплект макетов. Остальные экраны получают выбранную композицию
после визуального выбора пользователя; существующие функции не исчезают ради упрощения.

## Дизайн-контракт

```text
FEATURE: полный редизайн существующих страниц и пользовательских сценариев
→ USER GOAL: быстро понимать главное и заполнять формы без перегрузки
→ EXISTING LOGIC: текущие domain-модели, application-команды, queries и контроллеры
→ PAGE/COMPONENT ARCHETYPE: центр управления; список и детали; глубокий фокус; аналитика
→ SECTION COLOR: выбранная палитра темы, без новой радуги разделов
→ MAIN VISUAL CENTER: текущее действие, выбранная сущность или текущий шаг формы
→ COMPONENTS TO REUSE: ApplicationShellView, AppIcon, SectionPageHeader,
  SectionDateNavigator, SphereReference, SubjectiveRatingScale,
  VoiceTextInput / VoiceTextArea / VoiceField, действующие формы и контроллеры
→ MOBILE BEHAVIOR: один поток; список → отдельные детали; длинная форма на весь экран;
  touch-зоны от 44px; существующая нижняя навигация и возврат сохраняются
→ APPROVED REFERENCE: YES для прежних палитр; NO для новых композиций
→ TEST SCOPE: сейчас реестр, ссылки, формат и макеты;
  при внедрении targeted tests, verify и browser/mobile gate по матрице
```

Классификация — переработка UI существующих страниц и сценариев. Новые разделы, функции и
изменения бизнес-логики не подразумеваются. Новая композиция всего приложения требует
визуального утверждения до переноса в продукт.

## Принципы минимализма

1. Один главный объект и одна сильная кнопка на текущий смысловой экран.
2. Группировка через типографику, отступы и разделители; карточка нужна отдельному объекту,
   но не каждому абзацу или строке списка.
3. В первом слое — название, состояние и следующее действие. История, связи и редкие параметры
   доступны через понятное раскрытие. Ошибки и обязательные поля никогда не скрываются.
4. Обычный текст 14–16px, подписи над полями, согласованная шкала отступов 4/8/12/16/24/32/48/64.
   Контраст измеряется при детализации, а не считается подтверждённым картинкой.
5. Спокойный матовый фон; атмосферный мотив почти незаметен. Уменьшение декора — предложение
   нового редизайна, а не незаметное изменение ранее утверждённой системы.
6. Сохраняются видимые входы в существующие разделы, голос, синхронизацию и восстановление.
   Сокращение бокового меню не должно делать функции недоступными.
7. Компактная форма использует один экран. Большая — смысловые группы с дополнительными
   параметрами. Новый обязательный wizard ради оформления не вводится.

## Матрица форм и заполнений

Для каждой формы из реестра создаются кадры:

- `empty` — первая открытая форма с реальными defaults;
- `filled` — реалистично заполненный пример;
- `validation` — обязательное поле/ошибочное значение, текст остаётся в форме;
- `submitting` — сохранение, защита от повторного submit;
- `save-error` — ошибка сохранения с возможностью повтора без потери текста;
- `success` — результат, возврат к сущности или подтверждение;
- `edit` — существующие значения, включая длинные тексты и отсутствующие связи;
- отдельные кадры каждой условной ветки, меняющей доступные поля или решение пользователя.

Общие варианты могут ссылаться на единый лист компонентов. Уникальные ошибки, поля и переходы
показываются отдельно. Отсутствие применимого состояния явно объясняется в карточке кадра.

| Форма           | Поля, которые нужно сохранить                                                                                                                    | Обязательные условные варианты                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| Направление     | Название, описание, сфера, стратегический замысел, желаемое состояние, входит/не входит в направление                                            | Без главной цели; пересмотр стратегии с изменением существующих связей             |

| Решение         | Вид, дата, формулировка, причина, ожидаемый результат, сфера, цель, приоритет, цена, жертвы, связь с целью                                       | Главное/обычное решение: фактическая разная обязательность; уточнение начатого     |

Демонстрационные данные синтетические. Пример единой цепочки: «Развитие» → «Читать регулярно» →
«Прочитать 12 книг» → «Читать каждый вечер» → «Прочитать главу книги». Заполненные макеты должны
сохранять правдоподобные связи и даты относительно 9 сентября 2026 года.

## Размеры и общие состояния

Основной desktop: 1440×1024; tablet: 768×1024; mobile: 390×844; узкий: 360×800.
Для каждого уникального экрана обязательны desktop и mobile. Tablet и 360px проверяют каждый
тип композиции и все исключения с длинными формами, таблицами, клавиатурой и закреплёнными CTA.
Кнопки не перекрывают поля при открытой мобильной клавиатуре; длинная форма сохраняет доступ к
ошибкам и действиям. Возврат из деталей восстанавливает фильтр и позицию списка.

Общий лист компонентов покрывает default, hover, pressed, selected, focus, disabled, loading,
empty, no-results, error/retry, success, readonly, offline. Критические состояния из SY/SR/MO/EV
не заменяются абстрактной карточкой ошибки. Skeleton соответствует геометрии целевого экрана.

## Формат полного комплекта и приёмка

Для каждого кадра фиксируются: ID, вход/выход, viewport, тема, тестовые данные, поля, обязательность,
контроллер/команда, главный CTA, поведение отмены и ошибки, связь с предыдущим и следующим кадром.
Имена: `GL-create-metric-filled-mobile-graphite`, `EV-sleep-blocked-desktop-graphite`.
Статусы: `planned → draft → reviewed → approved`; только явное утверждение пользователя даёт approved.

- [x] Текущие разделы, сценарии и критические ветки проверены по коду.
- [x] Подготовлены три концепта одного экрана для выбора композиции.
- [ ] Пользователь выбрал направление или сформулировал правки.
- [ ] Создан полный комплект кадров для всех ID и применимых состояний.
- [ ] Есть библиотека форм, полей, диалогов и интерактивных состояний.
- [ ] Уникальные композиции показаны на desktop и mobile; обе темы покрыты.
- [ ] Ни одна функция или обязательное поле не потеряны при сверке с реализацией.
- [ ] Выполнены визуальный review и чек-лист №38 на уровне макетов.
- [ ] Пользователь утвердил комплект; составлен окончательный план патчей по каждому разделу.

В этой фазе проверяются статические артефакты. Работающая клавиатурная навигация, browser console,
реальный responsive и сохранение данных проверяются только при последующем внедрении.
