# От фокуса к действию

Дата: 01.10.2026. Статус: реализовано; визуальный результат ещё не утверждён пользователем.

[Исходный интерфейс](../references/2026-10-01-goal-guidance/README.md) ·
[Проверка реализации](../../architecture/2026-10-01-goal-guidance-verification.md).

## Цель и выбранное направление

Пользователь выбрал результат: «Помочь выбрать конкретный шаг на сегодня из моих целей».
Обновление помогает открыть цель из «Сегодня», понять основание предложенного шага
и явно добавить существующее действие в план дня. Успешный результат — конкретное действие
в сегодняшнем плане с сохранённой связью с целью, которое видно после перезагрузки.

Предлагаемое название входа: **«Выбрать шаг к цели»**. Название панели: **«Шаг к цели»**.
Слово «главное» в этой панели относится к недельной цели только при наличии такого выбора
в данных. Добавление шага не означает назначение главным делом дня.

интерфейсу коучем: активный composition API описан в `docs/codex/PROJECT_MAP.md`.

## Выбор решения

Рассмотрены три варианта:

1. Ссылка из Today на «Фокус». Малый объём, но человек продолжает самостоятельно соединять
   цель и дату действия.
2. **Контекстный выбор шага внутри Today — выбранный вариант.** Показать основание выбора,
   дать выбрать другую цель/действие и применить одну существующую операцию даты.
3. Свободный коуч-чат. Потребует отдельного решения по модели, доступу к данным и качеству
   рекомендаций; выбранный пользователем результат можно получить без этого расширения.

## Основной сценарий

1. В Today пользователь нажимает «Выбрать шаг к цели». Открывается стандартная `PlannerSheet`.
   Панель не назначает фокус, следующий шаг или даты существующих действий при открытии.
   Штатное обновление PlanningContext сохраняет существующую materialization повторений
   и совместимое чтение/импорт старого фокуса; это не новая функция помощника.
2. Если есть валидная главная цель текущей недели, она выбрана. Подпись:
   «Главная цель этой недели». Иначе виден выбор активной цели без автоматического назначения.
   Список сначала показывает цели в фокусе, затем остальные; порядок внутри групп стабилен.
3. Для выбранной цели показываются её название, существующее «Почему важно» при наличии
   и связанные открытые действия. Валидный `Goal.nextActionId` предвыбран с пояснением
   «Вы выбрали это действие следующим шагом цели».
4. Если такого шага нет, пользователь выбирает действие сам. Первое в сортировке,
   `LifeAction.isNext` или произвольная старая запись не выдаются за рекомендацию.
   Выбор другого действия помечается «Ваш выбор на сегодня» и остаётся локальным для панели.
5. Панель показывает существующую дату и доступную оценку длительности, если она задана.
   Она не обещает, что действие оптимально или обязательно поместится в день.
6. Для действия без даты primary — «Добавить на сегодня». Для другой даты —
   «Перенести на сегодня» с явным «Сейчас запланировано: …».
   Для действия на сегодня — «Открыть действие», без повторной записи.
7. После успешного commit receipt сохраняется, панель закрывается, начинается обновление плана.
   Подтверждение с названием действия, отмена даты и состояние чтения принадлежат Workspace
   и доступны после закрытия панели. После успешного чтения фокус возвращается на добавленную
   строку или её кнопку открытия. Если commit прошёл, а обновление списка нет, UI сообщает
   «Дата сохранена. Не удалось обновить план» и предлагает только повторить чтение.

Изменение цели/действия в панели не меняет недельный фокус и `Goal.nextActionId`.
Доступ «Открыть цель» ведёт к существующей карточке, где можно изменить долгосрочные решения.
Источник локального выбора хранится отдельно для цели и действия: начальный default либо
явное действие пользователя. Фиксация default в памяти панели не превращает его в «Ваш выбор».
Если при обновлении данных прежнее основание исчезло, показать «Фокус/следующий шаг цели
изменился. Проверьте выбранное действие», сохранить видимые поля и запросить новое нажатие.

## Пустые и особые состояния

| Ситуация                                                                            | Поведение                                                                                                                                                             |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Нет активных целей                                                                  | «Создайте цель, чтобы выбрать шаг на сегодня» и существующая «Создать цель».                                                                                          |
| Есть цели, нет главной цели недели                                                  | Показать selector цели. При единственной цели всё равно не назначать ей недельную главность.                                                                          |
| У цели нет открытых действий                                                        | «Создать действие для цели»: закрыть помощник и открыть текущую форму с `goalId`, `date=today`, `title=goal.nextProgress` при наличии. Ничего не создаётся до submit. |
| Пользователь отменил создание                                                       | Готовая форма сохраняет обычные guards; возврат в Today, без созданного действия и без обещания восстановления выбора помощника.                                      |
| Выбранный шаг завершён, удалён, отменён, архивирован или больше не относится к цели | Объяснить, что шаг недоступен; показать выбор из актуальных действий, не подставлять другое молча.                                                                    |
| Действие выполняется (`inProgress`)                                                 | Доступно «Открыть действие»; помощник не переносит его дату.                                                                                                          |
| Недельный фокус и направление месяца различаются                                    | Это допустимо. Использовать явную недельную цель как default, позволить выбрать другую; не объявлять конфликт ошибкой.                                                |
| Смена недели/дня, sync или изменение из другого экрана                              | Обновить чтение. Сохранить валидный явный выбор пользователя; инвалидный объяснить. Не переключать незаметно цель под открытой панелью.                               |
| Ошибка начальной загрузки                                                           | Inline error и «Повторить загрузку»; без активной команды добавления.                                                                                                 |
| Ошибка обновления при старом снимке                                                 | Пометить данные устаревшими, блокировать назначение до успешного чтения. Старые сведения не объявлять актуальным советом.                                             |
| Изменилось действие после показа                                                    | Команда отвергает несовпавшую версию. Обновить данные и потребовать нового явного нажатия.                                                                            |
| Ошибка записи                                                                       | Панель и выбор остаются, ошибка рядом с действием; повтор только по нажатию.                                                                                          |
| Двойное нажатие                                                                     | Один запрос; busy блокирует повтор. Отмена даты не затирает более позднее изменение.                                                                                  |
| Раздел «Завтра»                                                                     | Новый вход скрыт: текущая версия помощника работает только с сегодняшним днём.                                                                                        |

## Дизайн-контракт

```text
FEATURE → выбрать шаг к цели из Сегодня
USER GOAL → понять, какое конкретное действие выбранной цели добавить на сегодня
EXISTING LOGIC → PlanningState, Goal.nextActionId, SetLifeActionPlan, текущие формы/панель действия
PAGE/COMPONENT ARCHETYPE → Today + стандартная PlannerSheet с выбором из существующих сущностей
SECTION COLOR → текущие graphite/jade tokens; gold только у действующего приоритета
ATMOSPHERIC MOTIF → спокойная рабочая поверхность без новой иллюстрации
MAIN VISUAL CENTER → выбранное действие и один CTA внутри панели; план дня остаётся главным вне неё
COMPONENTS TO REUSE → PlannerSheet, PlannerActionForm, PlannerActionPanel, AppIcon, form styles,
  текущая отмена даты, guards и focus-return
MOBILE BEHAVIOR → тот же вход в шапке Today, одна колонка панели, controls ≥44 px, scroll/safe area
APPROVED REFERENCE → текущий UI и общие компоненты; нового утверждённого макета нет
TEST SCOPE → выбор/основание, запись/отмена, версии/свежесть, desktop/mobile, keyboard, UX-задания
```

Классификация: новая функция существующей страницы со стандартной формой. Новый раздел,
отдельный route помощника и уникальная композиция страницы не нужны; по правилам AGENTS
отдельный большой approved-макет не обязателен. Если реализация потребует уникального wizard
или перестройки Today, это изменение scope: сначала подготовить конкретный макет для утверждения.
Новый результат не маркировать APPROVED/LOCKED без соответствующего решения пользователя.

Вход размещается в группе служебных действий шапки Today рядом с «Рабочее время». Desktop
оставляет основные колонки на месте; mobile переносит эту группу строкой при недостатке ширины.
Постоянной раскрытой карточки над главным делом нет. В панели один primary, остальные действия
спокойные. Открытие фокусирует поле цели, Escape закрывает с возвратом на вход.
`PlannerSheet` не владеет busy: Workspace блокирует повторный submit и обрабатывает закрытие
во время запроса. Закрытие не отменяет уже отправленную команду; её результат остаётся доступен
в Today, если пользователь ещё на этом экране. Browser Back/уход закрывает помощник без позднего
открытия панели или прыжка фокуса на другой маршрут.

## Архитектура и минимальные изменения

Новый чистый application query `buildTodayGoalGuidance` строит представление из `PlanningState`
и локальной даты. Канонические периоды/memberships и `Goal.nextActionId` читаются напрямую;
второй store рекомендаций, отдельный provider, миграция и сетевой сервис не требуются.
Presentation хранит открытость панели, выбранные ID и происхождение локального выбора.
Это временное UI-состояние; React не изменяет предметные данные.
Существующий `usePlanningState` сообщает `refreshing` для блокировки submit во время чтения;
результат старого запроса не должен снимать pending более нового запроса или другого дня.

Для защиты от незаметного переноса изменившегося действия расширить `changeDate` необязательным
`expectedVersion`. Проверка выполняется по свежезагруженному действию **внутри команды**,
до применения изменений; существующий optimistic commit защищает дальнейшую гонку. Старые
callers без параметра сохраняют поведение. Новый помощник всегда передаёт показанную версию.
Проверка только отдельным чтением в React не заменяет этот контракт.

Операция помощника возвращает отдельный результат: запись не состоялась либо запись состоялась
и чтение после неё успешно/неуспешно. Сразу после commit сохраняется undo receipt, затем ожидаются
оба чтения: Today и PlanningContext. Текущий `Workspace.run` с общим catch и проглатыванием ошибки
не даёт такого результата и не используется здесь как подтверждение успеха.

Создание остаётся в существующей форме. Новая операция не объединяет создание, смену
следующего шага, недельного фокуса и главности дня в один submit.

## Приёмка и UX

- Для уже выбранных главной цели недели и следующего шага без даты: два нажатия от Today
  до добавления (вход → «Добавить на сегодня»). Reload сохраняет дату и связь с целью.
- Пользователь видит причину предложения и может выбрать другую цель/действие.
- Отмена, просмотр и изменение локального выбора не вызывают новых команд назначения
  фокуса, следующего шага и дат существующих действий.
- Главное действие сегодняшнего дня, недельный фокус и `Goal.nextActionId` остаются прежними
  после добавления. Если шаг был главным на прежней дате, перенос снимает ту главность
  по существующим правилам; это обозначается перед переносом и восстанавливается штатной отменой.
- Старый снимок/несовпавшая версия не приводят к переносу и ложному success.
- Уже запланированный шаг открывается; двойное нажатие не создаёт дубликатов/лишних изменений.
- Desktop 1440×900 и 1280×720; mobile 390×844 и 320 px; keyboard/focus, Escape, safe area,
  длинные названия, reduced motion и browser console. Применяется Правило №38.
- Экспертный проход проверяет задачи: добавить готовый шаг, выбрать при пустом фокусе,
  понять перенос будущего действия, отказаться без изменений, восстановиться после ошибки.
- Дополнительный проход с пользователем: найти вход без подсказки за ≤10 секунд;
  объяснить основание выбора и разницу между шагом цели и главным делом дня;
  добавить шаг с первой попытки. Это целевые критерии, пока не измеренные результаты.

## Границы

В обновление не входят AI API/чат, анализ текста дневника, психологические выводы, новая оценка
важности, автономное планирование, уведомления и новая еженедельная рефлексия. Не входят
устранение ранее известных sync/completion/Diary дефектов и подготовка релиза.
Данные пользователя не нужны для baseline: сценарии можно проверить на синтетических записях.
