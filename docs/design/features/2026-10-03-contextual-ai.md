# Контекстный помощник LifeOS

## Цель

Помощник доступен из каждого рабочего раздела и отвечает на вопрос с учётом только
текущего раздела, выбранной записи и периода. Он помогает понять данные и предлагает
варианты дальнейших действий, но не назначает жизненные приоритеты и не меняет записи.
Существующий свободный вопрос в аккаунте сохраняется.

## Дизайн-контракт

- FEATURE: общий сценарий помощника для существующих разделов.
- USER GOAL: получить ответ по данным текущей страницы без ручного копирования в чат.
- EXISTING LOGIC: application-запросы и локальные данные LifeOS; серверный OpenAI gateway.
- PAGE/COMPONENT ARCHETYPE: существующий `PlannerSheet` поверх текущей страницы.
- SECTION COLOR: общий jade-акцент темы, без новой палитры.
- MAIN VISUAL CENTER: основной объект текущей страницы остаётся главным; помощник открывается по запросу.
- COMPONENTS TO REUSE: `PlannerSheet`, `VoiceTextArea`, кнопки и состояния формы.
- MOBILE BEHAVIOR: существующая полноширинная нижняя панель, touch-зоны от 44 px.
- APPROVED REFERENCE: отдельный не требуется; используется текущий архетип панели.
- TEST SCOPE: application-контекст, transport/handler, UI, scoped browser на desktop/mobile.

## Данные и границы

Контекст строится в Application из авторитетных read-моделей, по allowlist полей и с
лимитом записей/размера. Страница показывает раздел, период и список отправляемых
источников до отправки. Передача происходит только по нажатию «Спросить».
Фотографии, удалённые записи, ключи, пароли, sync payload и полные domain-объекты
не передаются. Контекст и ответ живут только до закрытия панели.

Сервер повторно проверяет схему, аутентификацию и allowlist, сохраняет `store:false`
и отправляет модели только вопрос и предоставленный снимок. Модель получает инструкцию
считать пользовательские записи данными, отмечать неполноту, не выводить причинность
из совпадений и не утверждать, что выполнила изменение. Ответ — обычный текст.

Разделы: сегодня/завтра, сферы, направления, потребности, цели и планирование,
действия и время, входящие, прогулки, дневник, память жизни, подготовка ко сну,
аналитика, аккаунт. Детальные маршруты используют выбранную запись.

## Проверка

Должны работать: пустые и заполненные разделы, выбранная запись/период,
отмена запроса, запрет отправки до явного действия, ограничение объёма,
отсутствие секретов и удалённых записей, отклонение произвольного контекста
сервером, смена маршрута, keyboard/focus и mobile. Реальное подключение
по-прежнему зависит от развёрнутой Edge Function и серверных secrets.
