# Ядро LifeOS V2

Изменение только бизнес-логики от baseline `4a98318`. Требования согласованы в задаче:
создание самостоятельного действия по title, завершение любого открытого действия без сессии
и обязательной заметки, поздняя обратимая связь с Goal, активная Goal без Direction.

Источники состояния — существующие LifeAction и Goal. Единственный факт выполнения —
`actionCompleted` в существующем Journal, атомарный с сохранением действия. Повторное
завершение не меняет дату, заметку, версию или историю. Завершённое действие без подготовки
должно восстанавливаться из существующего формата хранения. Дата Journal — дата выполнения.

`SetLifeActionGoal.execute({ lifeActionId, goalId })` назначает существующую Goal либо снимает
связь через null. Меняется та же запись и её версия; completion не воспроизводится.
Архивированное действие сохраняет существующий запрет изменений. Decision, Project,
ActionSession и их legacy-команды сохраняются.

UI, V2 Today, редизайн, Supabase migrations, PROTOCOL_VERSION, Tauri crypto и secure storage
не входят в блок. Визуальные компоненты, акценты и mobile-поведение не меняются.

Проверки: целевые domain/application/IndexedDB-тесты через `test:target`, один `npm run verify`
после стабилизации. Полный E2E и Playwright запрещены. Предсуществующие изменения документации
и настроек остаются вне патча. После отчёта работа останавливается.

## Границы совместимости

Прямое завершение не закрывает running/paused legacy-сессию. Её можно завершить отдельно
через CompleteActionSession; это не создаёт повторного actionCompleted. Старый UI продолжает
использовать VerifyLifeActionResult и собственные ограничения сессий до отдельного этапа UI.

Production composition всегда передаёт JournalUnitOfWork в CompleteLifeAction. Старый
конструктор без UoW оставлен для совместимости: при таком самостоятельном создании команды
Journal и проверка версии не обеспечиваются. Новая SetLifeActionGoal требует UoW.
