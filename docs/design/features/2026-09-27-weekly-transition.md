## Объём первой поставки

- Представление «Обзор недели» внутри «Целей», без новой глобальной навигации.
- Последняя завершённая календарная неделя по локальной дате, понедельник–воскресенье.
  Можно смотреть текущую и прошлые недели. Будущие исключены.
- Число завершённых неархивных действий по сохранённому локальному completedOn (fallback completedAt), не количество целей.
  Reopen исключает действие; это текущие записи, не неизменяемая история.
- Текущие активные цели с явной подписью. Записи результата недели считаются отдельно
  от завершённых действий, через effectiveDate и contributionIsEffective, без initial.
  Нулевой вклад — запись. Pending и неполные данные не выдаются за отсутствие результата.
- Для измеряемых целей текущий итог показывает канонический progress reader. Цикл recurring
  и изменение недели подписываются отдельно. Legacy без истории не получает выдуманной суммы.
- «Без записей результата» — нейтральный факт, не утверждение о застое.
- Незавершённые дела выбранной недели доступны для явного выбора даты в обзоре и открытия карточки
  и существующую application-команду. In-progress не перепланируется; READY остаётся с датой.
- Следующий шаг относится к конкретной дате. Новое предметное поле «главное недели»
  не создаётся: пользователь выбирает главное для дня существующим механизмом.
- Loading/empty/error/retry наследуют workspace/provider. Ошибка команды сохраняет ввод.
  Успешная запись обновляет тот же источник, сохраняет выбранную неделю и возвращает фокус.
- Не входят: массовые автоматические переносы, изменение сроков целей, пауза целей,
  новая схема хранения, выдуманный процент готовности, новые режимы и настройки.

## Реализация после утверждения

Маршрут `#/v2/goals?view=review&week=YYYY-MM-DD`, entry в переключателе целей.
Week хранится в URL; браузерный Back из карточки возвращает выбранную неделю.
Невалидная дата возвращает последнюю завершённую неделю, будущая ограничивается текущей.
Application buildWeeklyGoalReview читает загруженный PlanningState через PlanningProvider.
Используются createGoalProgressReader и contributionIsEffective. Recurring показывает цикл
сейчас с точными границами, отдельно от вклада выбранной недели. Initial/voided/stale-key
не входят в недельные записи; pending/incomplete явно помечены и исключены из «без записей».
Текущие active цели и незавершённые неархивные/неудалённые действия; выполненные по completedOn.

Перенос использует SetLifeActionPlan с draft/ready policy и isNext=false на новой дате.
Повторное сохранение той же даты только обновляет представление, не меняя main или счётчик.
In-progress остаётся доступным для открытия; его дата не меняется из обзора.
Ошибки PlanningProvider отображаются даже со старым state: видна пометка и retry.
Storage/schema/общая навигация не изменены; общий E2E не требуется.

Targeted projection/render/navigation: 14 тестов прошли. Соседний goal-actions E2E: 2 сценария desktop/mobile прошли. Weekly E2E: desktop и mobile прошли после добавления same-date/main и simulated provider failure/retry; mobile overflow проверяется после готовности обзора, а не во время перезагрузки.

Visual QA: реальные desktop 1440px и mobile 390px снимки, сравнение с approved reference. Иерархия сводки, graphite/jade, shared controls, мобильная сетка, empty state, keyboard/date focus и >=44px controls проверены; browser errors отсутствуют. Rule38 применён: без новых декоративных цветов, отдельной карточки на каждую строку или второй системы навигации. В текущем browser profile нет целей, поэтому там виден empty; тестовые данные создавались только в изолированном E2E профиле.
