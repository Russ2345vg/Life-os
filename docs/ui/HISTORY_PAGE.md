# Раздел «История»

## Назначение

Раздел показывает неизменяемую хронологию значимых событий. Для ограниченного набора ошибочных
значений из него можно запустить отдельное аудируемое исправление. Он объединяет в одну хронологию:

- подтверждённые и отменённые решения;
- завершённые и отменённые действия;
- завершённые и прерванные рабочие сессии.

## Диапазон

Выбранная в верхней панели дата является концом периода. Доступны три диапазона:

- один день;
- последние 7 дней;
- последние 30 дней.

При изменении даты или диапазона открытая карточка закрывается, а устаревший ответ запроса не
заменяет данные нового периода.

## Итоги

Над хронологией отображаются:

- количество подтверждённых решений;
- количество завершённых действий;
- количество рабочих сессий;
- суммарное чистое рабочее время без пауз.

## Фильтры

Над журналом доступен регистронезависимый поиск по названию решения или действия, сохранённому в
момент события. Записи также можно одновременно отфильтровать:

- по дате внутри загруженного диапазона;
- по сфере, включая записи без сферы и записи с недоступной сферой;
- по типу: день, решение, действие, рабочая сессия или исправление данных;
- по состоянию: создано, начато, на паузе, продолжено, завершено, прервано, перенесено, отменено
  или исправлено.

Показывается количество найденных событий, все условия применяются одновременно. Сброс возвращает
полную хронологию выбранного диапазона. Поиск и фильтры работают только с уже загруженным
представлением и сами по себе не изменяют записи журнала или другие данные в IndexedDB.

Исправления также находятся по прежнему и новому значению и по указанной пользователем причине.

## Безопасное исправление данных

Действие «Исправить данные» доступно только там, где событие однозначно связано с актуальной
сущностью и типизированным полем:

- причина отмены Решения;
- фактический результат завершённого Действия;
- причина отмены Действия.

Даты, состояния, сферы, служебные поля и произвольные пути данных из журнала не исправляются. Форма
показывает сущность, поле и фактическое текущее значение. Новое значение должно быть корректным и
отличаться от текущего, а причина обязательна.

Исходное событие не изменяется и не удаляется. Обновление актуальной сущности и добавление события
«Исправление данных» выполняются одной транзакцией. Повторное исправление добавляет следующую запись
с актуальным прежним значением; возврат к первоначальному значению также остаётся новой записью.
Идентификатор команды защищает форму от повторной отправки. Удаление исправлений не предусмотрено.

## Открытие карточек

Нажатие на решение открывает полную карточку решения в режиме чтения. Нажатие на действие или
сессию открывает карточку связанного действия в режиме чтения. Обычное редактирование, перенос,
отмена и запуск сессий из истории недоступны. Корректирующая запись показывает прежнее и новое
значения, причину и переход к исходному событию. Если исходное событие или связанная сущность
недоступны, история всё равно открывается с безопасной подписью.

## Хранение

Запрос `GetHistoryForDateRange` получает финальные сущности и сессии из репозиториев, фильтрует их
по фактическому времени завершения или отмены и сортирует новые события первыми. Постоянные
репозитории используют существующие object stores IndexedDB. Корректирующие данные сохраняются в
типизированном поле записи журнала; старые записи без него читаются как прежде. Версия схемы базы не
изменяется, поэтому миграция не требуется и старые события не переписываются.
