# Подтверждённые проблемы

## Dev toolchain содержит транзитивную high-уязвимость nanoid

- **Модуль:** `vite@8.2.0 → postcss@8.5.25 → nanoid@3.3.16`.
- **Воспроизведение:** `npm audit --json` сообщает `GHSA-2v37-7h3g-55p8`; проблема относится к
  custom generators с нулевым размером. `npm audit --omit=dev --json` возвращает ноль уязвимостей.
- **Статус:** открыто; исправление требует отдельного контролируемого обновления dev toolchain.
  `npm audit fix` автоматически не выполнялся.
- **Связанные проверки:** `npm ls nanoid --all`, полный `npm audit`, production-only audit.
- **Риск:** затрагивает build tooling, а не production dependency graph; остаётся причиной
  ненулевого exit code полного `npm audit`.

## Документ IndexedDB отстаёт от кода

- **Модуль:** `docs/architecture/INDEXED_DB_STORAGE.md`.
- **Воспроизведение:** документ описывает версию `2` и пять stores; константы в
  `src/infrastructure/persistence/indexed-db/LifeOsIndexedDb.ts` задают версию `8` и десять stores.
- **Статус:** открыто; исправление существующей продуктовой документации не входит в Codex upgrade.
- **Связанные тесты:** `src/infrastructure/persistence/indexed-db/LifeOsIndexedDb.test.ts`.
- **Риск:** агент может спроектировать неверную миграцию или пропустить существующее хранилище.

## PROJECT_STATUS содержит устаревший следующий этап

- **Модуль:** `PROJECT_STATUS.md`.
- **Воспроизведение:** нижний раздел называет следующим этапом 13.3, хотя текущий `main` содержит
  более поздние routine, walk, sphere, journal, analytics и shell-коммиты.
- **Статус:** открыто; файл нельзя использовать как единственный источник текущего scope.
- **Связанные тесты:** отсутствуют; состояние подтверждается кодом и Git history.
- **Риск:** новая задача может начаться с уже реализованного этапа или неверного состава сущностей.

## Playwright зависит от системного Google Chrome

- **Модуль:** `playwright.config.ts` и `tests/e2e/lifeos.smoke.spec.ts`.
- **Воспроизведение:** проект использует Playwright channel `chrome`, чтобы не устанавливать
  браузерные бинарники вне worktree.
- **Статус:** принятый инфраструктурный компромисс; на текущей машине Chrome доступен.
- **Связанные тесты:** `npm run test:e2e` — 3 passed, 1 ожидаемый mobile skip 2026-08-24.
- **Риск:** на другой машине без Google Chrome smoke не запустится до установки браузера или
  явного изменения поддерживаемого channel.

## Полный Vitest run долго не показывает прогресс

- **Модуль:** `package.json`, script `test`.
- **Воспроизведение:** `npm run test` около минуты показывает только заголовок `RUN`, затем штатно
  завершает весь suite.
- **Статус:** зависание не воспроизведено; запуск 2026-08-24 завершился с кодом `0` за 62.99 секунды
  (147 файлов, 1166 тестов).
- **Связанные проверки:** `npm run test`; для локализации использовать
  `npm run test -- --reporter=verbose` с внешним ограничением времени.
- **Риск:** отсутствие промежуточного вывода можно ошибочно принять за зависание и прервать
  корректный one-shot процесс.

## Project config не активируется без доверия к новому worktree

- **Модуль:** пользовательская конфигурация Codex.
- **Воспроизведение:** в `%USERPROFILE%\.codex\config.toml` есть trust entry для
  `C:\LifeOS-App`, но нет entry для `C:\LifeOS-Codex-Upgrade`; Codex загружает project config
  только для trusted project.
- **Статус:** требуется действие пользователя; глобальная конфигурация не изменяется автоматически.
- **Связанные тесты:** повторный запуск Codex из worktree и проверка активной конфигурации.
- **Риск:** будущий `.codex/config.toml` может быть проигнорирован до выдачи доверия.

## Основной Figma-файл LifeOS не указан

- **Модуль:** UI design source of truth.
- **Воспроизведение:** Figma plugin/MCP авторизованы, но в проекте нет `figma.com/design` URL с
  `fileKey` и `node-id`.
- **Статус:** `Требуется создать/указать основной Figma-файл LifeOS`.
- **Связанные проверки:** после получения URL вызвать read-only design context для конкретного node.
- **Риск:** до этого можно проверять согласованность с UI-токенами и приложенными изображениями, но
  нельзя заявлять соответствие основному Figma-дизайну.

## Глобальные rules содержат разрешения для старого Obsidian LifeOS

- **Модуль:** `%USERPROFILE%\.codex\rules\default.rules`.
- **Воспроизведение:** файл содержит длинные allow-rules для `Second Brain Vault`,
  `LifeOS-Test-Vault`, `LifeOS-Development` и операций установки старого Obsidian-плагина.
- **Статус:** требует отдельного разрешения пользователя на изменение глобального файла.
- **Связанные тесты:** ручная ревизия rules после будущего изменения.
- **Риск:** устаревшие широкие разрешения не относятся к текущему приложению и увеличивают область
  допустимых действий.
