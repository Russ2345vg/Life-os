# Выпуск обновлений LifeOS для Windows

LifeOS при запуске проверяет канал
`https://github.com/Russ2345vg/LifeOS-Releases/releases/latest/download/latest.json`.
Если доступна более новая версия, появляется кнопка «Обновить». Сначала сохраните открытые
формы: установщик закроет приложение и запустит его снова. «Позже» откладывает до следующего
запуска. Интернет нужен для проверки и загрузки, локальная работа доступна без него.

## Первое подключение ПК

На ПК со старой сборкой без проверки обновлений нужно один раз запустить новый подписанный
установщик поверх существующего приложения. После публикации его можно скачать из
[LifeOS Releases](https://github.com/Russ2345vg/LifeOS-Releases/releases).
Удалять приложение или очищать его данные не нужно. Последующие выпуски обнаружатся внутри LifeOS.

## Подготовка на ноутбуке

1. Завершить изменения. Поднять версию в package.json, package-lock.json, src-tauri/Cargo.toml
   и записи пакета lifeos в src-tauri/Cargo.lock. Версия должна быть выше установленной.
2. Выбрать проверки дельты по `AGENTS.md` и `TEST_MATRIX.md`. Выпуск версии не запускает
   полный E2E автоматически. Выполнить `npm run test:release` и
   `npm run release:windows -- check` до долгой сборки.
3. Подготовить подписанный Windows installer, например:

   ```powershell
   npm run release:windows -- prepare 1.0.17
   ```

Результат: `src-tauri/target/release-channel/v1.0.17/windows/` — installer, подпись,
latest.json, SHA256SUMS.txt и локальный prepared.json для проверки перед публикацией.
Android SDK/keystore и GitHub CLI для подготовки не нужны. Нужны существующие Windows/Rust
build tools и updater signing configuration в `D:/Android/LifeOS/signing`.
Ключи нельзя заменять, публиковать или коммитить. Сборка ограничена 15 минутами.

Production настройки прежнего Supabase-проекта должны быть в игнорируемом `.env.production`
или окружении сборки: `VITE_LIFEOS_SUPABASE_URL`, `VITE_LIFEOS_SUPABASE_PUBLISHABLE_KEY`,
`VITE_LIFEOS_ACCOUNT_SYNC_ENABLED=true`. Ключ подписи обновления и Supabase client key решают
разные задачи. Приватные server keys в клиенте запрещены.
`prepare` останавливается до компиляции при отсутствии настроек и после сборки сверяет
конфигурацию фактического frontend bundle; `prepared.json` содержит URL проекта и hash публичного
ключа, без значения ключа. `publish` не принимает старый пакет без этого свидетельства.
На новом компьютере сначала проверь production-конфигурацию, а затем сборку и подпись.

## Публикация проверенного пакета

Нужны установленный GitHub CLI (`gh`), вход в аккаунт с доступом к репозиторию
Russ2345vg/LifeOS-Releases и разрешение владельца на публикацию конкретного выпуска.
Скрипт не создаёт репозиторий и не публикует исходный код.

```powershell
npm run release:windows -- publish 1.0.17
```

Команда проверяет контрольные суммы подготовленных файлов, сохраняет действующий Android feed,
загружает assets в draft, проверяет их имена/размеры и только затем делает release публичным/latest.
Повторную публикацию существующего тега скрипт отклоняет. Если загрузка draft не завершилась,
нужно проверить draft вручную, не перезаписывая уже опубликованный выпуск.
Для полностью нового канала сначала создаётся репозиторий; подготовка работает и без него.

После публикации проверьте загрузку latest.json и installer по ссылкам manifest, затем
обновление на тестовом ПК с более старой подключённой версией. Убедитесь, что версия изменилась,
приложение открылось снова и прежние записи доступны. Browser E2E не заменяет эту native проверку.

Подготовка и публикация разделены: команда publish не пересобирает уже проверенный установщик.
Изменения исходников на ноутбуке сами по себе не выпускают обновление.

## Одновременный выпуск Windows и Android

После обновления версий, успешного `npm run test:release` и проверок дельты по `AGENTS.md`
подготовьте оба подписанных пакета:

```powershell
npm run release:publish -- prepare 1.0.30 --owner Russ2345vg --notes "Описание обновления"
```

Скрипт сохраняет шесть файлов канала и `prepared.json` в
`src-tauri/target/release-channel/v1.0.30/`. Проверьте пакеты и манифесты. Когда выпуск
разрешён, опубликуйте именно подготовленные файлы:

```powershell
npm run release:publish -- publish 1.0.30 --owner Russ2345vg
```

`publish` не запускает сборку. Перед загрузкой он проверяет версию, GitHub owner, исходный
commit, состав файлов и SHA-256 каждого asset. Изменение исходного commit, любого asset или
release notes требует новой подготовки. Публикация создаёт публичный release; вызывайте её
только после проверки и разрешения на выпуск. Прежний синтаксис `--prepare-only` больше не
используется.
