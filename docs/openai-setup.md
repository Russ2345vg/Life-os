# Активация OpenAI в LifeOS

В коде подготовлено подключение: «Аккаунт» → «Помощник OpenAI» → один вопрос/ответ.
По умолчанию оно выключено. Функция не читает задачи или дневник и не сохраняет
переписку в LifeOS. Только отправленный текст передаётся серверу LifeOS и OpenAI.
`store:false` отключает хранение Response для последующего получения через API;
это не обещание отсутствия всех журналов у провайдера.

## Сервер

Используется существующий Supabase-проект с аккаунтом LifeOS. Нужны:

- `OPENAI_API_KEY`: ключ вашего проекта OpenAI, только в Supabase secrets.
- `LIFEOS_OPENAI_MODEL`: точный ID доступной вашему API-проекту модели с поддержкой
  Responses API. Модель задаётся сервером, приложение не может подменить её.
- `LIFEOS_OPENAI_ALLOWED_USER_IDS`: UUID разрешённых пользователей Supabase Auth,
  через запятую. Пустой список отключает функцию. Anonymous и неподтверждённые
  аккаунты не принимаются даже при наличии UUID в списке.

Ключ не присылайте в чат, не помещайте в Git или `VITE_*`. Задайте эти значения
в Supabase Dashboard → Edge Functions → Secrets. Функция использует встроенные
`SUPABASE_URL` и `SUPABASE_ANON_KEY` для серверной проверки пользователя.

После проверки diff и разрешения на deployment из корня проекта:

```powershell
npx supabase functions deploy lifeos-openai --project-ref <ваш-project-ref>
```

JWT verification оставьте включённой. Дополнительно handler проверяет bearer
через Auth `/user` и allowlist. Сам по себе публичный ключ не даёт доступа к AI.
Новые таблицы и миграции не требуются.

Это личная интеграция для явно разрешённых аккаунтов, без тарификации и квот на
каждого пользователя. Перед доступом широкой аудитории нужны серверные общие
квоты/rate limiting. В первой версии ограничены размер запроса/ответа и время,
автоматических повторов нет; расходы контролируются в вашем OpenAI API-проекте.

## Приложение

В локальной конфигурации сборки, где уже заданы публичные Supabase URL/key:

```dotenv
VITE_LIFEOS_ACCOUNT_SYNC_ENABLED=true
VITE_LIFEOS_OPENAI_ENABLED=true
```

Пересоберите native-приложение LifeOS и войдите в разрешённый подтверждённый аккаунт.
Browser preview сохраняет текущий native-only auth контракт; там реальный AI
не включается. Кнопка отправляет только текущий вопрос (до 4000 символов).
Сервис не запоминает предыдущий вопрос, поэтому каждый запрос независим.

## Проверка после активации

Откройте «Аккаунт» и отправьте несекретный вопрос, например «Ответь одним словом:
подключено». Убедитесь, что пришёл ответ. Затем проверьте отмену и сообщение
об ошибке для аккаунта вне allowlist. Локальные тесты используют тестовые ответы
и не подтверждают доступность ключа/модели или развёртывание Edge Function.

Отключение: `VITE_LIFEOS_OPENAI_ENABLED=false` и новая сборка; серверный доступ
можно независимо прекратить очисткой allowlist/удалением ключа в secrets.

Документация: [OpenAI API](https://developers.openai.com/api/docs/guides/text),
[Supabase secrets](https://supabase.com/docs/guides/functions/secrets).
