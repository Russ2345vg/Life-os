# Альбом целей — дизайн рабочего раздела A1

## Цель и границы

Создать отдельный верхнеуровневый раздел LifeOS «Альбом целей», который открывается из существующего левого меню, восстанавливается по прямому URL и показывает реальные Goals в контексте существующих Sphere и Direction. Экран следует композиции утверждённого визуального эталона A1 и текущей дизайн-системе LifeOS.

Патч является только вертикальным срезом A1. Он не включает полноценные A2 Goal Detail и A3 Create Goal, редактирование, галерею, Музей достижений, историю пути, конфликты целей, ЧасыЖизни, финансовую модель, автоматический прогресс, связи Goal с Project/Decision/Today и AI-функции.

Незакоммиченные изменения Goal domain/application/persistence считаются техническим фундаментом этапа и сохраняются. Без доказанной необходимости эти файлы не изменяются.

## Выбранный подход

`goals` становится самостоятельным `AppSection`, а не вкладкой раздела «Управление». Это прямо выполняет требование отдельного пункта левого меню и сохраняет существующую систему верхнеуровневой навигации.

Маршруты следуют принятой в проекте hash-конвенции:

- `#/goals` — альбом;
- `#/goals/:goalId` — минимальный read-only экран перехода в цель;
- `#/goals/new` — честная заглушка следующего create-state без формы A3.

Для маршрутов создаётся отдельный чистый navigation-модуль с parse/build-функциями. `ApplicationShell` расширяет уже существующее восстановление hash-маршрутов и не создаёт второй router. Переход назад/вперёд обновляет экран, а пункт «Альбом целей» остаётся активным на album, detail и create-placeholder routes.

## Архитектура и поток данных

Поток остаётся:

```text
ApplicationShell
→ GoalAlbumPage
→ goal album presentation mapping
→ GetGoals + GetDirections + GetSpheres
→ существующие domain/repository/persistence contracts
```

`GoalAlbumPage` получает только существующие application queries и callbacks навигации. При открытии альбома он одним параллельным снимком загружает Goals, Directions и Spheres через `Promise.all`. Чтений repository из presentation нет, N+1 запросов по карточкам или направлениям нет.

Чистый presentation-модуль строит lookup-таблицы по идентификаторам и возвращает готовые view models: счётчики, подписи, карточки, фильтрованные списки и группы. React управляет только состояниями загрузки, выбранным фильтром, выбранным режимом просмотра и маршрутом; доменные сущности не изменяет.

Новый application query `GetGoalAlbum` не вводится: существующих `GetGoals`, `GetDirections` и `GetSpheres` достаточно, а дополнительный контракт без необходимости затронул бы уже изменённый Goal-фундамент.

## Навигация

В `APP_SECTION` добавляется `goals`, подпись «Альбом целей» и пункт menu options. Desktop sidebar и мобильное раскрывающееся меню используют существующий `NavigationButton`, получают новую иконку `goals`, active state через `aria-current="page"` и сохраняют collapse/tooltips/focus behavior.

Нижняя мобильная навигация не расширяется пятым постоянным разделом: альбом остаётся доступен из мобильного меню. Настройка стартового раздела получает «Альбом целей» через существующий список разрешённых разделов.

При переходе в `#/goals/:goalId` альбом находит Goal в уже загруженном снимке. Существующая цель показывает название, статус и сообщение о том, что полный экран A2 будет подключён отдельно, плюс возврат в альбом. Неизвестный идентификатор показывает понятное состояние «Цель не найдена» без технических деталей.

`#/goals/new` показывает заголовок «Добавить цель», пояснение о следующем этапе A3 и возврат в альбом. Это не форма, не вызывает `CreateGoal` и не создаёт данных.

## Композиция A1

Экран использует текущий shell и токены LifeOS; тестовые тексты, числа и изображения из A1 не копируются в реальные данные.

Порядок блоков:

1. заголовок «Альбом целей» и CTA «Добавить цель»;
2. обзор «Картина будущего»;
3. фильтры статуса и переключатель режима просмотра;
4. сетка Goals либо группы Sphere → Direction → Goals.

Кнопки анализа фокуса, импорта и прочие элементы, которые видны в A1, но не входят в текущее ТЗ, не добавляются. Главная цель периода отсутствует в domain, поэтому featured-компонент не моделируется и не получает persistence; на этом этапе обзор содержит только реальные сводные показатели.

Визуальный язык: глубокий графитовый фон, матовые поверхности, тонкие спокойные границы, золото для выбранного фильтра и основной CTA, зелёный только для активного/достигнутого состояния, минимальное свечение и компактная информационная плотность.

## «Картина будущего» и фильтры

Сводка вычисляется из реальных `Goal.status`:

- активные — `active`;
- будущие — `future`;
- достигнутые — `achieved`;
- всего целей — сумма активных, будущих и достигнутых.

Архив не входит в «всего целей», как показывает семантика A1, и доступен отдельным режимом.

Фильтры используют существующий `GoalStatus` без UI-дубликата:

- «Все» — все неархивные Goals;
- «Активные» — `active`;
- «Будущие» — `future`;
- «Достигнутые» — `achieved`;
- «Архив» — `archived`.

Второй presentation-control переключает плоскую сетку и режим «По направлениям». Выбор фильтра и режима просмотра не изменяет Goal и не сохраняется в domain.

## Группировка Sphere → Direction → Goals

Для каждого Goal с `directionId` название и Sphere берутся из реального снимка Directions/Spheres. Копии Direction или самостоятельные UI-направления не создаются.

В режиме «По направлениям» после применения status-фильтра:

1. Directions группируются по реальной Sphere;
2. внутри Sphere показываются только Directions с видимыми Goals;
3. внутри Direction отображается сетка GoalCard;
4. Direction без `sphereId` попадает в секцию «Без сферы»;
5. Goal с `directionId: null` попадает в отдельную секцию «Без направления».

Goals без направления допустимы для будущего состояния по текущему domain/application контракту. Активную цель без направления создать нельзя. Если Goal содержит идентификатор отсутствующего Direction, карточка сохраняется и получает честную подпись «Направление недоступно», а не маскируется как `directionId: null`.

Группы сортируются по названиям Sphere и Direction с русской локалью. Исходные массивы query не мутируются.

## GoalCard

Карточка является production-ready интерактивным элементом и целиком открывает detail-route. Вложенных action-кнопок внутри кликабельной области нет.

Она показывает:

- реальную `coverImage.dataUrl` с безопасным `object-fit: cover` либо системный placeholder с иконкой цели;
- полное название с переносом длинного текста;
- название Direction или честное fallback-состояние;
- stage и status отдельными подписями;
- horizon;
- domain-native progress;
- `nextProgress` или «Следующий шаг не задан».

Для metric progress показываются `current`, `target`, `unit` и ограниченная 0–100% ширина индикатора. Для milestones показываются `completed / total` и производная доля. Для qualitative progress показывается реальная стадия `start / moving / close / done` человеческой подписью без выдуманного числового процента. При `progress: null` карточка сообщает «Прогресс не задан».

Карточка не обрезает title и `nextProgress`, использует `overflow-wrap`, сохраняет читаемость длинных значений и доступный `focus-visible`.

## Состояния и ошибки

Страница имеет четыре явных состояния:

- `loading` — понятный status без зависшего пустого экрана;
- `error` — нейтральное сообщение, кнопка «Повторить», без stack trace и внутренних enum;
- `empty` — «В Альбоме пока нет целей» и CTA «Добавить цель»;
- `data` — сводка, фильтры и текущий режим отображения.

Если общий список не пуст, но выбранный фильтр ничего не нашёл, показывается отдельное presentation-empty сообщение с возможностью вернуться к «Все»; это не глобальное empty-state.

Асинхронная загрузка защищена от stale completion после unmount/повторной попытки. Повторный запрос не создаёт дублирующих listeners. Техническая ошибка всегда допускает retry.

## Responsive и accessibility

На 1600×900, 1440, 1280 и 1024 px экран остаётся плотным и не конфликтует с существующим sidebar. Сетка использует адаптивные колонки с `minmax(0, 1fr)`, карточки и группы имеют `min-width: 0`, текст переносится, горизонтальный scroll не появляется.

На 390×844 и 360×800 сохраняется базовая рабочая mobile-композиция: одна колонка, CTA не перекрывает контент, учтён нижний safe area, альбом доступен из мобильного меню. Полная отдельная mobile-концепция A1 не входит в этап.

Фильтры являются кнопками с `aria-pressed`, режим просмотра имеет доступную group-label, загрузка/ошибка используют live regions, изображения получают корректный `alt`, icon-only controls имеют `aria-label`, а reduced motion наследует существующий shell contract.

## Тестовая стратегия

Реализация идёт TDD. До production-кода добавляются падающие проверки на:

- parse/build album, detail и create-placeholder routes;
- прямой URL, back/forward и active goals section;
- пункт desktop/mobile sidebar и отсутствие регрессий существующих пунктов;
- loading, error/retry, empty и data;
- параллельную загрузку Goals/Directions/Spheres без N+1;
- реальные счётчики и фильтры по `GoalStatus`;
- использование существующего Direction и Sphere;
- группировку Sphere → Direction → Goals, «Без сферы» и «Без направления»;
- отдельное fallback-состояние для отсутствующего Direction;
- GoalCard с cover/placeholder, stage, horizon, status, всеми видами progress и длинными данными;
- переход из GoalCard в `#/goals/:goalId`;
- корректные detail-not-found и `#/goals/new` placeholders;
- responsive/CSS-контракты, focus-visible и reduced motion.

После целевых тестов выполняется полный gate:

```text
npm run typecheck
npm run lint
npm run test
npm run build
npm run format:check
git diff --check
```

## Визуальная приёмка

Локальный route открывается во встроенном браузере и сравнивается с A1 на одинаковом desktop viewport. Проверяются иерархия, плотность, обзор, фильтры, карточки, группировка, sidebar и focus states. Отдельно проверяются 1024 px, 390×844 и 360×800, длинные реальные значения, empty/error и отсутствие horizontal overflow.

Для browser QA разрешено использовать только временные тестовые записи в изолированном браузерном IndexedDB; они не входят в production-код и не остаются демонстрационными данными приложения.

После этого этап останавливается. A2 и A3 не начинаются.
