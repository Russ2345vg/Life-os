# Diary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить в LifeOS самостоятельный раздел «Дневник» для дневных оценок и текстов,
недельной рефлексии и месячных итогов с детерминированными сводками.

**Architecture:** Новый aggregate `DiaryEntry` и `DiaryRepository` сохраняют одну версионируемую
запись на календарный период. Application service владеет draft/completion, агрегацией и чтением
канонических фактов PlanningState. Infrastructure добавляет IndexedDB v29, encrypted structured
sync и recovery. React получает только application API, ставит автосохранение в последовательную
очередь и регистрирует её в общем guard переходов.

**Tech Stack:** TypeScript, React, IndexedDB, Vitest, Playwright; новых зависимостей нет.

**Spec:** `docs/design/features/2026-09-29-diary.md`

## Global Constraints

- Работать только в активном worktree `D:/LifeOS-App`; перед каждым коммитом сверять
  `git status --short` и включать только файлы текущего этапа.
- Не откатывать предсуществующие изменения сна, холодного душа, потребностей целей и других
  параллельных задач. Перед правкой `PlannerWorkspace.tsx`, composition и sync fixtures повторно
  прочитать актуальное содержимое и интегрировать изменения по месту.
- Соблюдать направление UI → Presentation → Application → Domain; Infrastructure реализует
  application-порты. React не пишет в IndexedDB и не дублирует сохранённое предметное состояние.
- Использовать локальные `DayDate` и `CurrentDateProvider`. Неделя — Пн–Вс, месяц — календарный;
  `thirtyDayPeriod` для месяца запрещён.
- Не сохранять тексты дневника в `localStorage`, analytics или PlanningState. Факты планировщика —
  текущая динамическая read model и не входят в payload `DiaryEntry`.
- Не добавлять удаление, tombstone, AI-анализ, поиск, напоминания, вложения или настройку вопросов.
- Запись открытого периода не должна самопроизвольно переключаться в локальную полночь.
- UI использует утверждённый reference
  `docs/design/references/2026-09-29-diary/preview.html`, текущие tokens/shared components и
  каскад `planner-premium.css`; новые локальные стили не создают отдельную палитру.
- Каждый этап начинается с наблюдаемого failing test, затем минимальная реализация, targeted GREEN
  и отдельный коммит. Не обходить RED изменением ожиданий под текущую реализацию.
- Перед каждым `git commit` выполнить `git diff --cached --check` и просмотреть
  `git diff --cached`. Для файлов с предсуществующими правками использовать `git add -p`; широкое
  добавление каталога запрещено.

## Review Focus

1. Единственность записи по `periodKey`, optimistic version check и атомарность не допускают тихой
   потери текста при двух окнах или sync.
2. Старые snapshots без `diaryEntries` остаются читаемыми, а v29 без обязательного store отклоняется.
3. Route-leave guard одинаково покрывает ссылки, bottom navigation, смену периода, Back/Forward и
   `beforeunload`, сохраняя локальный ввод при ошибке.
4. Сводки не считают пропуски нулями, не выводят причинность и используют только completed entries.
5. Mobile navigation остаётся ровно из пяти пунктов и сохраняет доступ к «Направлениям» через
   «Ещё»; клавиатура, focus и touch targets соответствуют дизайн-контракту.
