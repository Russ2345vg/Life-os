# LifeOS — план полного минималистичного редизайна

> Для исполнителя: текущая фаза — только проектирование. Перенос в приложение не разрешён этим
> запросом. Главный агент — единственный автор изменений; независимое исследование/review
> допускается по AGENTS.md. Прежде чем выполнять будущий runtime-план, прочитать актуальную
> specification и правила проекта.

**Цель:** подготовить согласованный комплект макетов всех существующих страниц, форм и состояний,
затем внедрять его последовательно, сохраняя функции и данные.

**Архитектура:** изменения оформления принадлежат Presentation и общей оболочке. Application и
Domain остаются источниками контрактов; существующие контроллеры и команды переиспользуются.
UI не становится вторым хранилищем предметного состояния.

**Стек:** существующий React/TypeScript/CSS; новые зависимости не запланированы.

**Specification:** [полный реестр и дизайн-контракт](../../design/features/2026-09-09-minimal-redesign.md).

Статус: **предварительный поэтапный план, визуальное направление ожидает выбора**. Это порядок
работ и критерии каждого пакета, а не готовое разрешение менять код. Подробные CSS/JS-патчи
определяются по выбранным макетам; придумывать их до визуального решения преждевременно.

## Общие ограничения

- Продукт, навигационные возможности, обязательность полей и данные сохраняются.
- Основная палитра следует ранее выбранным «Графиту» и «Бордо»; новые композиции отдельно утверждаются.
- Desktop 1440×1024, mobile 390×844; дополнительные проверки 768×1024 и 360×800.
- Отсутствие макета не означает, что соответствующую функцию разрешено удалить.
- Смена визуальной темы не сбрасывает сессию, фильтры, выбранную дату или введённый текст.
- В текущем worktree много предсуществующих изменений. Перед внедрением повторно сверить status
  и контракты, не откатывать чужую работу и не использовать старые копии проекта.

### Проверки будущего кода

```text
npm run test:target -- <точный путь к тесту затронутого поведения>
→ npm run test:fast только при изменении общего контракта
→ npm run verify после стабилизации пакета
```

Полный E2E не запускается после каждой косметической правки. Для пакетов, меняющих browser
interaction, navigation, responsive flow, startup/recovery или persistence, он обязателен по
матрице. Полные этапы R10 и финальный R12 требуют `npm run test:e2e` после verify либо
`npm run verify:full`. Перед запуском записывается конкретное основание; зелёный suite без
влияющих изменений повторно не запускается.

При внедрении сравнивать approved-reference и browser screenshot одного состояния и размера;
проверять console, keyboard/focus, touch, контраст, reduced motion и checklist №38. Скриншот
ImageGen не доказывает эти свойства. Перенос сам по себе не требует миграции IndexedDB.
