# Направления, действия и повторения — план

**Goal:** выполнить единый патч из DOCX на текущей реализации LifeOS.

**Architecture:** существующие серии RecurrenceRule и экземпляры LifeAction; общий application projection для выбора. Контекст действия через реальные идентификаторы. Результат через existing actualResult и application command.

**Spec:** [дизайн-контракт](../../design/features/2026-09-21-directions-actions-recurrence.md).

## Шаги и журнал

- [x] Проверки связей и результата: integration tests на создание из направления/цели, roundtrip, повторение и независимые результаты.
- [x] Domain/application/persistence: optional directionId, наследование контекста, защита completionKey; совместимость sync/deletion.
- [x] Общий выбор серии: стабильный ruleId, поиск, обычные действия, разрешение конкретной даты только в датированных сценариях.
- [x] UI: фильтр сфер, компактный список действий направления, существующие формы с контекстом, общая метка повторения, необязательный результат.
- [x] Targeted tests → test:fast → verify → полный E2E (затронуты persistence, routing и browser flows). Команды выполнены; общие gates имеют ограничения вне scope, описанные в QA-отчёте.
- [x] Browser desktop/mobile review, независимый review, diff/status.

## Итог

Патч реализован. Финальные targeted browser-сценарии — 6/6 desktop/mobile; полный unit/integration — 3604/3604. Общий verify блокируется форматированием пяти предсуществующих файлов, полный E2E достиг deadline на фоне legacy-ожиданий старой оболочки. Детали и ручная QA: [отчёт](../../design/features/2026-09-21-directions-actions-recurrence-qa.md).

## Review focus

Старые записи без новых полей; устаревшая форма результата после reopen; серия без открытых экземпляров; разные серии с одинаковым названием; выбранная цель из другого направления.

## Ограничения выполнения

Реализацию делает главный агент в активном worktree, субагент исследует read-only. Dirty baseline не откатывается. Новая система отчётов и полная миграция не вводятся. Подтверждение выполнения уже дано пользователем; стандартные формы не требуют отдельного visual approval.
