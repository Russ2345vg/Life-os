# ADR-0021: безопасный перенос решения

## Статус

Принято.

## Контекст

Пользователю нужно переносить ещё не начатое решение на другую календарную дату, сохраняя его
идентичность и связи. Для главного решения на целевой дате требуется заново определить позицию, а
связанные действия не должны неявно менять собственный план. Низкоуровневый предметный перенос не
координирует эти межагрегатные проверки.

## Решение

1. Пользовательский перенос разрешён только для неархивированного `planned`-решения.
2. Позиция главного решения на новой дате выбирается автоматически: первая свободная из 1–3.
3. На одной дате допускается не более трёх активных главных решений в состояниях `planned` или
   `in_progress`; окончательные и архивированные решения позицию не занимают.
4. Связанные действия автоматически не переносятся, не изменяются и не пересохраняются.
5. `ready`, `completed` и `cancelled`-действия перенос решения не блокируют.
6. `draft`- и `in_progress`-действия блокируют перенос.
7. Дата раньше текущей календарной даты из `CurrentDateProvider` запрещена.
8. Перенос на ту же дату идемпотентен: версия, события, Clock, IdGenerator и хранилище не меняются.
9. Пакетный перенос решения и действий потребует отдельного транзакционного сценария.

`RescheduleDecisionSafely` загружает решение и связанные действия через прикладные порты, для
главного решения читает решения целевой даты, вызывает предметный метод только после всех
проверок и один раз сохраняет тот же `Decision`.

## Последствия

- новая дата и автоматически выбранная позиция сохраняются в IndexedDB;
- поиск по старой дате больше не возвращает решение, а поиск по новой дате возвращает его без
  дубликатов;
- связи, даты, состояния и история всех `LifeAction` сохраняются;
- интерфейс обновляет список «Сегодня» и закрывает карточку без F5;
- перенос `in_progress`, `confirmed`, `cancelled` и архивированных решений в пользовательский
  сценарий не входит.
