# ADR-0025: Хронология результатов только для чтения

## Статус

Принято.

## Контекст

Обзору истории недостаточно показывать две отдельные колонки решений и действий. Пользователю
нужно видеть последовательность фактических результатов, длительность рабочих сессий и сводку за
период, не рискуя случайно изменить уже завершённые данные.

## Решение

1. История строится отдельным запросом `GetHistoryForDateRange`.
2. Диапазон ограничен 31 календарным днём; интерфейс предлагает 1, 7 и 30 дней.
3. Решения попадают в историю по `confirmedAt` или `cancelledAt`.
4. Действия попадают в историю по `completedAt` или `cancelledAt`.
5. Сессии попадают в историю по `completedAt`; незавершённые сессии скрыты.
6. Репозитории могут предоставить `findAll`; запрос сохраняет запасной путь через существующие
   методы поиска по дате и действию для тестовых реализаций.
7. Хронология сортируется от новых событий к старым.
8. Карточки открываются только в режиме чтения.
9. Суммарное рабочее время рассчитывается по `workedDurationAt`, поэтому паузы не входят в итог.
10. Схема IndexedDB и предметные модели не изменяются.

## Последствия

- история остаётся производной проекцией существующих данных;
- после F5 она восстанавливается из IndexedDB без отдельного хранилища истории;
- фильтры и диапазон являются временным состоянием интерфейса;
- экспорт, поиск по тексту и произвольный диапазон больше 31 дня остаются отдельными этапами.
