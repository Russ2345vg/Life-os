# ADR-0002: Автоматическое открытие текущего дня

- Статус: принято
- Дата: 2026-08-01

## Контекст

LifeOS должен отражать календарную реальность без обязательного ежедневного ритуала запуска.
Пользователь может не завершить вчерашний день, но это не отменяет наступление новой даты.

## Решение

- Обязательная команда и пользовательская функция «Начать день» исключены.
- При открытии LifeOS команда `EnsureCurrentDay` гарантирует наличие записи текущей локальной даты и
  автоматически переводит наступивший запланированный день в `open`.
- Если текущий день уже завершён, он возвращается без повторного открытия и без второй записи.
- Завершение дня остаётся отдельной явной операцией.
- Прошедший незавершённый день не блокирует создание текущего.
- Допускается несколько прошлых открытых дней; каждый вычисляемо получает признак
  `requiresAttention`.
- Текущий день определяется совпадением календарной даты с датой устройства, а не глобальным
  флагом активности.

## Последствия

`CurrentDateProvider` отделяет локальную календарную дату от предметной модели и делает сценарий
проверяемым без системного времени. Репозиторий обязан обеспечивать уникальность даты. Для
постоянного хранилища в будущем потребуется атомарная гарантия уникальности при конкурирующих
вызовах; текущий in-memory-адаптер обеспечивает её в рамках одного процесса.
