# ADR-0027: явное начало текущего дня

## Статус

Принято. Заменяет решение ADR-0002 в части автоматического открытия дня.

## Контекст

Генеральный цикл LifeOS требует отдельного перехода «план дня → начатый день». Автоматическое
открытие при загрузке не позволяло отличить подготовленный план от фактически начатого рабочего
цикла и не давало надёжно запретить запуск труда до начала дня.

## Решение

1. `EnsureCurrentDay` по-прежнему гарантирует единственную запись текущей календарной даты, но
   создаёт её в состоянии `planned` и не запускает день автоматически.
2. Уже существующие записи `open` и `completed` не понижаются и не переписываются при обновлении.
3. Пользователь запускает день отдельной командой `StartCurrentDay`.
4. Команда разрешена только для текущего `planned`-дня и требует хотя бы одно активное главное
   решение (`planned` или `in_progress`).
5. До записи команда убеждается, что в хранилище нет другого `open`-дня.
6. Успешный запуск выполняет предметный переход `Day.open`, сохраняет время начала, увеличивает
   версию и создаёт событие `day.opened`.
7. Повторный вызов для уже открытого текущего дня идемпотентен и не вызывает `Clock`,
   `IdGenerator` или `save`.
8. Команда возвращает первое текущее действие: выполняемое имеет приоритет над готовым, затем
   используется порядок создания. Действие при этом не изменяется.
9. `StartLifeActionSession` разрешает запуск рабочей сессии только для действия текущей даты и
   только когда текущий день находится в состоянии `open`.
10. Presentation получает новое состояние из результата команды и сразу обновляет оболочку,
    карточку дня и текущего действия без F5.

## Последствия

Планирование и фактическое начало дня теперь различаются. Все экраны используют один экземпляр
`Day`, а запуск сессии не может обойти начало дня. Старые открытые дни сохраняются без опасной
миграции; если хранилище содержит несколько открытых дней, команда останавливается с
`day.multiple_open_detected`, пока данные не будут восстановлены отдельным сценарием.
