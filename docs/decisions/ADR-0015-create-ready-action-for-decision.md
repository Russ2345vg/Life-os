# ADR-0015: Создание готового действия для решения

- Статус: принято
- Дата: 2026-08-02

## Контекст

Предметная модель создаёт `LifeAction` как черновик и переводит его в готовность отдельным
переходом. В карточке решения пользователь ожидает создать уже запланированный следующий шаг.
Сохранение промежуточного черновика сделало бы частичное состояние видимым после сбоя подготовки.

Связь с решением и доступность решения требуют прикладной координации двух агрегатов, но не должны
изменять исходный `Decision`.

## Решение

1. Интерфейс вызывает `CreateLifeActionForDecision` и получает сразу готовое действие.
2. Команда проверяет существование решения и разрешает создание только для неархивированных
   `draft`, `planned` и `in_progress` решений.
3. `LifeAction` связывается ровно с одним `Decision` через `decisionId`.
4. Черновик создаётся через `LifeAction.createDraft`, переводится в `ready` методом `makeReady` в
   памяти и сохраняется один раз после успешных переходов.
5. Для обоих переходов используется одно значение `Clock`; действие и события
   `action.draft_created` и `action.ready` получают три отдельных идентификатора.
6. `Decision` не изменяется и не сохраняется.
7. Presentation получает команду и запросы через `LifeOsApplication`, не обращаясь к IndexedDB
   напрямую.

## Последствия

Сбой `makeReady` не оставляет черновик в репозитории. Сохранённое действие сразу доступно в
статусе `ready`, восстанавливается из IndexedDB после нового запуска и остаётся связанным с
решением. Запуск действия и создание `ActionSession` намеренно отложены до следующего этапа.
