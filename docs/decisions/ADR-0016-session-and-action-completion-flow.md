# ADR-0016: последовательное завершение сессии и действия

## Статус

Принято.

## Контекст

Рабочая сессия и действие имеют разные жизненные циклы. Пользователь может закончить отдельный
отрезок работы и продолжить действие позже либо зафиксировать итог всего действия. Сессия и
действие сохраняются отдельными командами и отдельными операциями постоянного хранения.

## Решение

1. Пользователь всегда сначала завершает `ActionSession` через `CompleteActionSession`.
2. После завершения сессии `LifeAction` может остаться `in_progress`; тогда позже можно начать
   новую сессию.
3. Для завершения `LifeAction` обязателен `ActionActualResult`, передаваемый в
   `CompleteLifeAction`.
4. Если завершение сессии прошло успешно, а завершение действия завершилось ошибкой, завершённая
   сессия не откатывается и не считается активной.
5. После частичного сбоя интерфейс сохраняет фактический результат и позволяет отдельно повторить
   только `CompleteLifeAction`.
6. Рабочее время, время пауз и итоговые суммы не сохраняются отдельными полями. Они вычисляются по
   `ActionSession` через `workedDurationAt(...)` и `pausedDurationAt(...)`; для завершённой сессии
   расчёт ограничен `completedAt`.

## Последствия

- сохранённая сессия не теряется из-за сбоя следующей команды;
- повтор после частичного сбоя не пытается повторно завершить уже завершённую сессию;
- после перезапуска состояние однозначно восстанавливается из `LifeAction` и `ActionSession`;
- интерфейс явно различает итог отдельной сессии и фактический результат всего действия.
