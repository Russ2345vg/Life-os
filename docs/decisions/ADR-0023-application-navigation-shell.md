# ADR-0023: оболочка приложения и основные разделы

## Статус

Принято.

## Контекст

После завершения полного цикла «решение → действие → сессия → результат» приложение оставалось
одним большим экраном. Добавление следующих функций без общей оболочки привело бы к разрозненным
экранам, повторному состоянию даты и различному поведению на компьютере и телефоне.

## Решение

1. Создать единую `ApplicationShell`, которая отвечает за активный раздел и общую `selectedDate`.
2. На широком экране использовать простую боковую навигацию без сложного сворачивания.
3. На телефоне использовать нижнюю навигацию «Сегодня / Действия / Создать / История / Ещё».
4. Не подключать маршрутизатор: активный раздел является временным состоянием интерфейса.
5. После F5 открывать «Сегодня» и текущую дату.
6. Передавать все запросы через `LifeOsApplication`; presentation не обращается к IndexedDB.
7. Подключить `GetLifeActionsForDate` к composition root для обзора действий и истории.
8. Разделы «Решения», «Действия» и «История» на первом этапе являются безопасными обзорами;
   изменение предметных объектов продолжает выполняться на рабочем экране «Сегодня».
9. Будущие разделы в «Ещё» обозначать как недоступные, а не имитировать готовые кнопки.
10. Центральная мобильная кнопка создания открывает существующую форму решения и не создаёт
    отдельный дублирующий сценарий.

## Последствия

- все основные разделы доступны из одной предсказуемой структуры;
- выбранная дата не теряется при переходе между обзорами;
- мобильный интерфейс получает устойчивую нижнюю навигацию;
- предметная модель и постоянное хранение не меняются;
- глубокие ссылки и сохранение активного раздела потребуют отдельного этапа маршрутизации;
- прямое открытие карточки действия из обзора «Действия» остаётся следующим отдельным вертикальным
  срезом.
