# ADR-0029. Единая модель состояний главного экрана

## Статус

Принято для этапа 10.1.

## Контекст

После завершения Alpha 0.1 экран «Сегодня» умел начать и завершить день, но определял подписи
непосредственно внутри React-компонента. Состояние рабочей сессии восстанавливалось только после
открытия карточки действия. Из-за этого главная страница не имела отдельного, проверяемого ответа
для всех состояний, перечисленных в генеральном плане.

## Решение

Создать чистую функцию `resolveTodayScreenState`, которая получает сохранённый день, решения,
действия, незавершённую сессию и признак открытого вечернего контроля. Функция возвращает одно
взаимоисключающее состояние:

1. день не запланирован;
2. день запланирован;
3. день начат;
4. активная рабочая сессия;
5. рабочая сессия на паузе;
6. нет текущего действия;
7. вечерний контроль;
8. день завершён;
9. ошибка восстановления.

Переходная загрузка остаётся техническим состоянием интерфейса и не записывается в предметную
модель.

Текущий день считается незапланированным, если запись дня существует в состоянии `planned`, но
на дату нет активного главного решения. Таким образом, схема IndexedDB и предметные состояния дня
не расширяются ради экранной подписи.

`TodayPage` при открытии одновременно читает действия текущей даты и единственную незавершённую
сессию. Выполняемая или приостановленная сессия имеет приоритет над обычной карточкой текущего
действия. Если сессия ссылается на отсутствующее действие или чтение завершается ошибкой, экран
показывает контролируемое восстановление и не изменяет данные.

После запуска, паузы, продолжения и завершения сессии экранное состояние обновляется из результата
прикладной команды без F5. После нового открытия приложения те же данные читаются из IndexedDB.

## Последствия

- Все варианты главного экрана имеют один селектор и автоматические проверки.
- React не вычисляет состояние сессии несколькими независимыми условиями.
- Завершённый день имеет приоритет и остаётся видимым даже при сбое фонового чтения списков.
- Этап не добавляет карточку следующего действия, стрелки действий, статистику или другие части
  этапов 10.2–10.4.
