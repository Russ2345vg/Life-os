# ADR-0012: Формат persistence records

- Статус: принято
- Дата: 2026-08-02

## Контекст

Предметные сущности LifeOS содержат классы значений, `Date`, поведение и непереданные события.
Сохранение экземпляров классов напрямую связывает формат базы с внутренним устройством домена и
не даёт устойчивого сериализуемого контракта. До подключения постоянного хранилища необходимо
зафиксировать этот контракт и путь безопасного восстановления агрегатов.

## Решение

1. В базе хранятся plain records, а не экземпляры предметных классов.
2. Все значения `Date` сохраняются как канонические ISO-строки UTC.
3. `DayDate` сохраняется отдельно в календарном формате `YYYY-MM-DD` без UTC-преобразования.
4. Каждая запись содержит `schemaVersion`; предметный `version` агрегата хранится независимо.
5. Преобразование выполняют отдельные mapper-ы, а восстановление сущности — её предметный
   `rehydrate()` без создания событий.
6. IndexedDB и persistence adapters подключаются следующим отдельным этапом.

## Последствия

Формат хранения состоит только из сериализуемых примитивов, массивов и plain objects. Изменения
внутреннего устройства классов не обязаны менять сохранённые данные, пока mapper поддерживает
зафиксированную схему. Неизвестные версии схемы и повреждённые структурные значения отклоняются
явными ошибками `persistence.*`, а ошибки предметных инвариантов из `rehydrate()` передаются без
маскировки.

На этом этапе данные ещё не переживают перезапуск приложения: решение определяет формат, но не
подключает IndexedDB, `localStorage`, сервер или синхронизацию.
