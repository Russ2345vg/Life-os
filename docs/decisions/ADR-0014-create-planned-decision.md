# ADR-0014: Создание сразу запланированного решения

- Статус: принято
- Дата: 2026-08-02

## Контекст

Предметная модель создаёт решение как валидный черновик, а затем планирует его отдельным
переходом. Для рабочего дневного интерфейса сохранение промежуточного черновика нежелательно:
пользователь ожидает увидеть готовое решение на выбранной дате, а сбой планирования не должен
оставлять невидимую неполную запись.

Выбор порядка главного решения также нельзя перекладывать на пользователя. Позиция зависит от
других активных решений дня и является прикладным межагрегатным правилом.

## Решение

1. Интерфейс вызывает координирующую команду `CreateDecisionForDate` и получает сразу
   запланированное решение.
2. Команда читает решения даты, проверяет лимит и автоматически выбирает первую свободную позицию
   1–3 для главного решения.
3. Черновик создаётся через `Decision.createDraft`, затем планируется предметным методом `plan` в
   памяти и сохраняется только один раз после обоих успешных переходов.
4. Для создания и планирования используется одно значение `Clock`; решение и два события получают
   отдельные идентификаторы.
5. Если проверка или планирование завершается ошибкой, черновик не сохраняется.
6. Presentation получает команду и запрос через `LifeOsApplication` и не обращается к IndexedDB
   напрямую.

## Последствия

Пользовательский сценарий не раскрывает технический жизненный цикл черновика. Ограничение трёх
активных главных решений и автоматический порядок применяются до сохранения. Дополнительные
решения не получают главного порядка и не ограничиваются количеством. Все созданные решения
сохраняются постоянным репозиторием, подключённым в composition root.
