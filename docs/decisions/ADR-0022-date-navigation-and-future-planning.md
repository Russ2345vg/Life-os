# ADR-0022: навигация по датам и планирование будущих дней

## Статус

Принято.

## Контекст

Первый рабочий экран изначально показывал только текущую дату, хотя прикладные сценарии уже умели
создавать и читать решения для произвольного `DayDate`. Для планирования будущего дня нужен переход
между датами без отдельного календарного раздела, маршрутизации и нового постоянного состояния.

## Решение

1. `TodayPage` является экраном выбранного дня и по умолчанию открывает `currentDate` из
   `LifeOsApplication`.
2. `selectedDate` хранится только в локальном состоянии интерфейса и не сохраняется в IndexedDB,
   `localStorage`, URL или глобальном singleton.
3. Предыдущий, следующий и произвольный день открываются на том же экране; кнопка «Сегодня»
   возвращает `currentDate`.
4. Каждая дата загружается отдельным вызовом `GetDecisionsForDate`; поздние ответы устаревших
   запросов не обновляют интерфейс.
5. Прошедшие даты доступны для просмотра. Интерфейс запрещает создание и редактирование, не меняя
   предметные правила переноса и отмены.
6. `CreateDecisionForDate` создаёт решения на выбранную текущую или будущую дату. Существующий
   сценарий не дублируется.
7. «Планировать завтра» выбирает следующий день относительно `currentDate` и открывает форму, но
   не создаёт решение автоматически.
8. Отдельный календарный раздел и месячный календарь будут рассмотрены позднее.

## Последствия

- решения разных дат остаются разделены запросом и сохраняются в IndexedDB без дубликатов;
- после переноса решение исчезает со старой даты и доступно на новой;
- после F5 экран возвращается к `currentDate`, а постоянные решения выбранных дат сохраняются;
- интерфейс не требует новой зависимости, маршрутизации или изменения предметной модели.
