ЗАДАЧА: синхронизировать существующий Evening Command Center LifeOS с приложенными утверждёнными визуальными референсами.

Эти изображения являются visual source of truth. Не проектируй новый дизайн и не интерпретируй композицию свободно.

Сопоставление:

02_reflection.png → ReflectionScene
03_tomorrow.png → TomorrowScene
04_preparation.png → PreparationScene
05_shutdown.png → ShutdownScene
06_recovery.png → RecoveryScene
00_design_system.png → общий стиль компонентов
07_all_scenes_overview.jpg → обзор всей системы

ПРАВИЛА:
1. Сначала проведи сравнительный аудит текущего UI и каждого референса. Выведи кратко: сцена | расхождение | изменение.
2. Затем реализуй визуальную синхронизацию всех сцен одним согласованным UI/presentation patch.
3. Не изменяй доменную бизнес-логику E1–E8, EveningCycle, ReflectionEngine, TomorrowPlan, PreparationPlan, Shutdown, UoW и существующие команды.
4. Архитектура остаётся: existing read model → presentation mapping → UI → existing command.
5. Не копируй текстовые примеры из картинок как пользовательские данные. Реальные значения бери из текущих read models.
6. Если текущий интерфейс расходится с изображением, приоритет у изображения, пока это не противоречит бизнес-логике.
7. Сохрани единый каркас Evening Command Center: навигация LifeOS, header, journey, KPI-ряд, основная рабочая зона, контекстные блоки.
8. Визуальная система: глубокий графит; тёплое золото/янтарь для текущего этапа, главного приоритета и CTA; зелёный только для completed/ready/success; красный только для ошибки/риска/destructive; никаких постоянных фиолетовых/синих акцентов; тонкие границы; минимальное свечение; матовые карточки; высокая информационная плотность.
9. Desktop должен быть близок к референсам по расположению, относительным размерам, плотности, иерархии, отступам, карточкам и кнопкам.
10. Mobile не копирует desktop буквально: одна колонка, без горизонтального scroll, CTA не перекрывает контент, safe-area и клавиатура учтены.
11. Не создавать новые параллельные компоненты/экраны, если существующие E9-компоненты можно привести к референсам.
12. После реализации проверить NORMAL, QUICK и “Позднее завершение”, empty/loading/error/completed/recovery.
